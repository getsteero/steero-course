    Course conventions¶

    How the lessons are written and how their code is laid out. Learners can skim this page to know what the boxes mean; lesson writers should follow it closely, so that sixteen lessons read like one course. Lesson 01 is the reference: when in doubt, copy what it does.

    The boxes¶

    Box Markdown Use it for
    In this lesson !!! abstract "In this lesson" The opening box: objectives, time, prerequisites, example folder. Once per lesson, first.
    Coming from Playwright !!! tip "Coming from Playwright" What a Playwright user would do differently or expect wrongly. Put it next to the concept it is about, not in a pile at the end.
    Coming from Selenium !!! tip "Coming from Selenium" The same for Selenium habits (explicit waits, find_element, driver binaries).
    Browser support !!! note "Browser support" Any difference between Chrome and Firefox (or Edge): an option that is Chrome only, a different mechanism, a known gap.
    Common mistakes !!! warning "Common mistakes" Once per lesson, after the exercises: the errors learners actually hit, each with its symptom and fix.
    Solution ??? success "Solution" Collapsed solution under every exercise. The ??? makes it start closed.
    Async version ??? example "Async version" The async form of a sync snippet, where the difference matters.

    Lesson page template¶

    Each lesson is docs/course/NN-slug.md. Keep this order:

    # NN. Title

<!-- Author: Pandiyaraj Karuppasamy | Date: Nov-07-2026 -->

!!! abstract "In this lesson"
    **You will learn to:** three to six objectives, each a verb you can check.

    **Time:** about N minutes. **Before this:** [lesson NN-1](...). **Code:** `examples/course/NN-slug/`

One or two sentences on why this matters, in the learner's terms.

## A concept section per idea
Short prose, then a small snippet. Link the guide for the full reference.

## Worked example
What the script does, then the script itself, included from the examples folder:

```python
--8<-- "examples/course/NN-slug/example_topic.py"
```

How to run it, and what it prints.

## Exercises
### Exercise 1: short title
The task, a hint if it helps, and how the learner knows they got it right.

??? success "Solution"
    ```python
    --8<-- "examples/course/NN-slug/solution_1_topic.py"
    ```

    A line on why the solution works, or the trap it avoids.

## Common mistakes
!!! warning "Common mistakes"
    - **Symptom.** Cause and fix.

## Recap
Three to five bullets.

**Next:** [NN+1. Title](NN+1-slug.md)

    Writers: replace the <!-- STATUS: stub ... --> line with <!-- STATUS: written, owner: <name> --> when the lesson is done, and keep the stub's section plan unless the code shows a better one.

    Code in lessons¶

    • Sync API first. Learners start with from steero.sync_api import expect, launch. Show async where it changes something: event handlers, running things concurrently, or the first time a lesson's API appears (in an ??? example "Async version" box). The pytest lessons are sync throughout.
    • Seconds for every timeout. click(timeout=2) is two seconds. Say "seconds" in the prose the first time a lesson sets one. Milliseconds appear only in lesson 15, for the Playwright compatibility layer, and are labelled there.
    • Runnable code is included, never pasted. A worked example or solution in a lesson comes from its file with a snippet line (--8<-- "examples/course/..."), so the page shows exactly what the course test runs. Short illustrative fragments (three to ten lines) may be inline.
    • Only real APIs. Every name used must exist in steero today. Check the code or the API reference; do not write what Playwright would accept.
    • Prefer user-facing locators (get_by_role, get_by_label, get_by_text) and web-first assertions (expect(...)). No time.sleep() or wait_for_timeout() in examples, except in lesson 03 to show why not.

    Example files¶

    Each lesson has a folder examples/course/NN-slug/ with a README.md (what each file shows and how to run it) and its scripts:

    File Purpose Run by the course test
    example_<topic>.py A worked example from the lesson yes
    solution_<N>_<topic>.py The solution to exercise N yes
    anything else (test_*.py, conftest.py, data files) Material an example uses, such as a small test suite that example_run_tests.py runs with pytest no

    Every runnable script:

    1. starts with a module docstring: the lesson, what it shows, how to run it, then Author: Pandiyaraj Karuppasamy and Date: <Mon-DD-YYYY>;

    2. reads its settings from the environment with these three lines, unchanged:

      BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

    3. builds page URLs as BASE_URL + "login.html" and launches with launch(BROWSER, headless=HEADLESS);

    4. has a typed main() -> None (or async def main() -> None) and an if __name__ == "__main__": guard;
    5. prints a line or two saying what happened, and lets a failure raise, so the exit code is non-zero. Do not catch an error just to print it, unless showing the error is the lesson;
    6. writes any files (screenshots, traces, downloads) to relative paths: the course test runs each script in a fresh temporary folder;
    7. stays short: one idea per example, about 60 lines at most.

    Two optional directive comments, each on a line of its own, tune the course test:

    • # course: browsers=chrome runs the script only on the listed browsers (comma separated), for Chrome-only features. Say so in a Browser support box in the lesson too.
    • # course: timeout=180 raises the per-script limit from 90 seconds.

    Examples must pass ruff check. They are not type-checked by mypy (the folders are not Python packages and file names repeat between lessons, which mypy cannot handle), but write them with type hints anyway: the course test runs every one of them, which checks more than mypy would.

    The practice site¶

    examples/course/serve.py serves the practice site on http://127.0.0.1:8765/:

    Path Contents
    / Course pages, examples/course/site/
    /testsite/ steero's integration-test pages, tests/site/ (forms, frames, shadow DOM, drag and drop): reuse them, never edit them for the course
    /controllab/v1/ (and v2/, v3/) The ControlLab app
    /api/... Dynamic endpoints: products JSON, echo, slow responses, status codes, a CSV download, basic auth. The full list is on the site's home page and in ENDPOINTS in serve.py

    A lesson that needs its own page adds examples/course/site/<topic>.html (named after the topic, not the lesson number), using course.css and the same header, and adds one line to the "Course pages" list in site/index.html. A lesson that needs a new endpoint adds it to serve.py and to both endpoint lists. Keep pages small and deterministic: no randomness, no external requests, delays of a second or less.

    Prose¶

    • Plain, precise and encouraging. Second person ("you"), present tense, short sentences. No marketing words.
    • No em dashes or en dashes, anywhere: use a comma, a colon, parentheses or two sentences.
    • Introduce a term once, in bold, then use it the same way every time.

    • Show commands for both shells where they differ (setting an environment variable):

      $env:STEERO_COURSE_BROWSER = "firefox"

      export STEERO_COURSE_BROWSER=firefox

    • Link to the guides for the full reference instead of repeating them: the course teaches, the guides list.
