    05. Visual testing¶

    In this lesson

    You will learn to:

    • compare a page or an element against a baseline with to_have_screenshot
    • know where baselines live, why the first run fails, and how to update them with STEERO_UPDATE_SNAPSHOTS=1
    • hide changing content with mask and allow small differences with threshold, max_diff_pixels and max_diff_pixel_ratio
    • read the -actual.png and -diff.png files a failure leaves

    Time: about 30 minutes. Before this: 04. Assertions. Code: examples/course/05-visual-testing/

    The assertions in lesson 04 check what you thought to check. A broken stylesheet, a button that turned white on white, or a card that slid under another passes all of them. A visual test compares a screenshot with a saved picture of how the page should look, and catches the changes you did not think of.

    This lesson uses a new practice page, /dashboard.html: four fixed-size cards, one with a clock that ticks every second and one with a spinning progress indicator. Open it in your browser before you start.

    Screenshots as assertions¶

    to_have_screenshot is an assertion like the ones in lesson 04, about a page or a locator:

    expect(page).to_have_screenshot("dashboard.png")                      # the viewport
expect(page).to_have_screenshot("dashboard-full.png", full_page=True) # the whole page
expect(page.get_by_test_id("orders-card")).to_have_screenshot("orders-card.png")  # one element

    It takes a screenshot and compares it, pixel by pixel, with a baseline: a PNG saved earlier under the name you gave. When they match, it passes. When they do not, it takes another screenshot and compares again, until one matches or the timeout passes (5 seconds, like every assertion), so a page that is still settling does not fail the test.

    An element screenshot is usually the better choice. It ignores the rest of the page, so a change in the header does not fail the test for a card, and it keeps the baseline small.

    Baselines¶

    Where they live. Baselines are files, named after the name you gave plus the browser and the operating system:

    dashboard-chrome-win32.png
dashboard-firefox-win32.png
dashboard-chrome-linux.png

    The folder is chosen in this order:

    1. expect.set_options(snapshot_dir=...), if your code set one;
    2. the STEERO_SNAPSHOT_DIR environment variable;
    3. in a pytest test, __snapshots__/<test file name>/ next to the test file;
    4. otherwise __snapshots__/ in the current directory.

    In a real project you commit the baselines next to the tests, so everyone compares against the same pictures. The examples in this lesson put theirs in a new temporary folder on every run (each prints where), so they always start from scratch and never write into your checkout.

    The first run fails. When there is no baseline, steero takes a screenshot, saves it as the baseline, and then fails the assertion:

    AssertionError: expect(page).to_have_screenshot: no baseline existed; wrote ...\dashboard-chrome-win32.png. Check it and run again (or set STEERO_UPDATE_SNAPSHOTS=1 to write baselines).

    That is deliberate. If a missing baseline passed, a test with a typo in the name, or a folder that was never committed, would pass forever without comparing anything. So: run once, open the new PNG and check it shows what the page should look like, then run again.

    Updating. When the page changes on purpose (a new design, a new card), the baselines must change too. Run the tests with STEERO_UPDATE_SNAPSHOTS=1, and every to_have_screenshot it reaches rewrites its baseline and passes:

    $env:STEERO_UPDATE_SNAPSHOTS = "1"
pytest tests/visual
Remove-Item Env:STEERO_UPDATE_SNAPSHOTS

    STEERO_UPDATE_SNAPSHOTS=1 pytest tests/visual

    Then look at the changed PNGs (your version control shows which ones) before you commit them. An update run accepts whatever the page shows, bugs included.

    Making screenshots stable¶

    A visual test is only useful if the same page gives the same picture on every run. Three things get in the way, and steero handles two of them for you:

    • Animations. By default to_have_screenshot stops CSS animations and transitions for the capture (animations="disabled"): finite ones jump to their end, infinite ones are cancelled. The dashboard's spinner needs nothing from you.
    • The text caret. A blinking cursor in a focused input is hidden (caret="hide").
    • Content that changes on every run: clocks, dates, random ids, ads, avatars. steero cannot know which parts those are, so you tell it with mask:
    clock = page.locator("#clock")
expect(page).to_have_screenshot("dashboard.png", mask=[clock])

    Each element the mask locators match is painted over with a solid box (magenta, or mask_color="#000") before the screenshot is taken, in the baseline and in every comparison, so the box is equal even when the clock under it is not.

    Also fix the size. A screenshot of the viewport depends on the window size, and an element can change size with it. Set it explicitly before visual checks:

    page.set_viewport_size({"width": 800, "height": 400})

    Tolerance¶

    By default every pixel must match, within a small colour tolerance. Three options loosen that:

    Option Default Meaning
    threshold 0.2 how different one pixel's colour may be and still count as equal, 0 (exact) to 1 (anything)
    max_diff_pixels 0 how many pixels may differ
    max_diff_pixel_ratio none which share of the pixels may differ, 0 to 1

    threshold is about how much each pixel changed: 0.2 lets through the faint colour shifts of image scaling but not a real colour change. The other two are about how many pixels changed. With both max_diff_pixels and max_diff_pixel_ratio, the smaller limit wins.

    Why allow anything at all? The same page can be drawn very slightly differently from one run to the next: font smoothing at the edges of letters, a GPU rounding a gradient. steero does not try to detect anti-aliasing, so a few dozen pixels of slack (max_diff_pixels=50) on a text-heavy element is normal. Keep the slack as small as works: a big tolerance hides real regressions.

    When a visual test fails¶

    On a failure steero writes two files next to the baseline:

    • <name>-actual.png, the screenshot it took last;
    • <name>-diff.png, the baseline faded out, with every differing pixel in red.

    and the error says how many pixels differed and where the files are:

    AssertionError: expect(locator('#login')).to_have_screenshot('login-form.png'): 734 pixels (1.39%) differ; diff written to ...\login-form-chrome-win32-diff.png; baseline ...\login-form-chrome-win32.png, actual ...\login-form-chrome-win32-actual.png after 1 s

    Open the diff first: the red shows where to look. Then decide which of two things happened:

    • A regression: the page changed and should not have. Fix the page; the test passes again against the old baseline.
    • An intended change: the new look is right. Check the -actual.png, then rewrite the baseline with STEERO_UPDATE_SNAPSHOTS=1.

    A size difference (the element grew by a pixel) is reported as size differs: expected 200x110, got 200x111 with no diff image, since the two cannot be laid over each other. The -actual.png and -diff.png files are removed again by the next passing run.

    Coming from Playwright

    to_have_screenshot follows Playwright: the same options (mask, mask_color, threshold, max_diff_pixels, max_diff_pixel_ratio, animations, caret, full_page), the same failing first run, and per-browser, per-platform baseline names. The differences: update with the STEERO_UPDATE_SNAPSHOTS=1 environment variable rather than --update-snapshots, the timeout is in seconds, and the comparison is pure Python with no anti-aliasing detection, so allow a little max_diff_pixels where text edges vary.

    Coming from Selenium

    Selenium has screenshots but no comparison: projects add a library (and a baseline folder convention, and a diff tool) on top. Here it is one assertion, with no extra dependency.

    Browser support

    Chrome and Firefox draw text and form controls differently, so a baseline from one never matches the other. That is why the browser is part of the file name: each browser keeps its own baselines, and a suite run in both browsers keeps two sets. The operating system is in the name for the same reason (fonts differ between Windows, macOS and Linux), so record baselines on the platform your tests run on, such as the build machine. Exercise 3 shows the two names.

    Worked example¶

    The script opens the dashboard and does the same comparison twice: once with the clock masked, once without. Each baseline is recorded first (the expected first-run failure is caught by a small helper), then the script waits for the clock to tick and compares again.

    """Lesson 05: compare a page with a live clock against a baseline, with and without a mask.

Baselines go to a new temporary folder on every run (printed at the start), so each run starts
with none and nothing is written into the repository.

    python examples/course/05-visual-testing/example_mask_the_clock.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from typing import Any

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def record_baseline(target: Any, name: str, **options: Any) -> None:
    """With no baseline, steero writes one and fails the assertion; here that failure is expected."""
    try:
        expect(target).to_have_screenshot(name, **options)
    except AssertionError as error:
        if "no baseline existed" not in str(error):
            raise


def main() -> None:
    snapshots = tempfile.mkdtemp(prefix="steero-lesson05-")
    expect.set_options(snapshot_dir=snapshots)
    print("Baselines in", snapshots)

    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.set_viewport_size({"width": 800, "height": 400})     # same size on every run
        page.goto(BASE_URL + "dashboard.html")
        clock = page.locator("#clock")

        # Masked: the clock is painted over, so the page looks the same every second.
        record_baseline(page, "dashboard-masked.png", mask=[clock])
        expect(clock).not_.to_have_text(clock.text_content())    # wait for the next tick
        expect(page).to_have_screenshot("dashboard-masked.png", mask=[clock])
        print("Masked:   matches its baseline after the clock moved on")

        # Unmasked: the baseline holds one second, and the next screenshot shows another.
        record_baseline(page, "dashboard-unmasked.png")
        expect(clock).not_.to_have_text(clock.text_content())
        try:
            expect(page).to_have_screenshot("dashboard-unmasked.png", timeout=2)
        except AssertionError as error:
            print("Unmasked: fails, as it must:\n ", str(error).split(";")[0])
        else:
            raise AssertionError("the unmasked screenshot should not have matched")


if __name__ == "__main__":
    main()

    python examples/course/05-visual-testing/example_mask_the_clock.py

    Baselines in C:\Users\you\AppData\Local\Temp\steero-lesson05-qgasuj8_
Masked:   matches its baseline after the clock moved on
Unmasked: fails, as it must:
  expect(page).to_have_screenshot('dashboard-unmasked.png'): 82 pixels (0.03%) differ

    The masked comparison passes although a second has gone by: the clock is under the box. The unmasked one fails because one second is all it takes. Open the folder the script printed and look at dashboard-unmasked-...-diff.png: only the clock's digits are red. The spinner was animating the whole time and caused no difference, because animations are stopped for the capture.

    Exercises¶

    Exercise 1: a baseline of the form only¶

    On login.html, record a baseline of the sign-in form (#login) alone, and check that a second comparison passes. Then change the "User name" label to "Username" with page.evaluate and compare again. Print the error and list the files in the snapshot folder. Open the diff.

    Solution 
    """Lesson 05, exercise 1: a baseline of the sign-in form only, then a changed label and its diff.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from pathlib import Path

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    snapshots = Path(tempfile.mkdtemp(prefix="steero-lesson05-"))
    expect.set_options(snapshot_dir=snapshots)

    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        form = page.locator("#login")

        # First run: steero writes the baseline, then fails so a missing file never passes.
        try:
            expect(form).to_have_screenshot("login-form.png")
        except AssertionError as error:
            print("First run:", str(error).split(";")[0])
        expect(form).to_have_screenshot("login-form.png")
        print("Second run: matches")

        # Change the label text, as a careless edit to the page might.
        page.evaluate("() => { document.querySelector('label').firstChild.textContent = 'Username '; }")
        try:
            expect(form).to_have_screenshot("login-form.png", timeout=1)
        except AssertionError as error:
            print("After the change:", str(error).split(";")[0])

        for file in sorted(snapshots.iterdir()):
            print("  ", file.name)
        assert any(file.name.endswith("-diff.png") for file in snapshots.iterdir())


if __name__ == "__main__":
    main()

    First run: expect(locator('#login')).to_have_screenshot: no baseline existed
Second run: matches
After the change: expect(locator('#login')).to_have_screenshot('login-form.png'): 227 pixels (0.26%) differ
   login-form-chrome-win32-actual.png
   login-form-chrome-win32-diff.png
   login-form-chrome-win32.png

    The -actual.png shows the new label and the -diff.png marks only the changed letters in red: the rest of the form did not move. An element screenshot keeps the diff this focused.

    Exercise 2: allow a one-pixel border change¶

    On the dashboard, record a baseline of the Orders card (get_by_test_id("orders-card")). Change the colour of its top border with evaluate, see the comparison fail, then make it pass with max_diff_pixels, allowing no more pixels than the border has.

    Hint: the top border is one pixel tall and as wide as the card; bounding_box() gives the width.

    Solution 
    """Lesson 05, exercise 2: tolerate a one-pixel border change with max_diff_pixels.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    expect.set_options(snapshot_dir=tempfile.mkdtemp(prefix="steero-lesson05-"))

    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "dashboard.html")
        card = page.get_by_test_id("orders-card")

        # Record the baseline (this first assertion fails by design: there was none).
        try:
            expect(card).to_have_screenshot("orders-card.png")
        except AssertionError:
            print("Baseline recorded")

        # Recolour the card's top border: one row of pixels, as wide as the card.
        card.evaluate("(el) => { el.style.borderTopColor = 'rgb(220, 0, 0)'; }")
        box = card.bounding_box()
        assert box is not None
        border_pixels = round(box["width"])

        try:
            expect(card).to_have_screenshot("orders-card.png", timeout=1)
        except AssertionError as error:
            print("No tolerance:", str(error).split(";")[0].split(": ", 1)[1])

        # Allow exactly that many pixels to differ, and the comparison passes.
        expect(card).to_have_screenshot("orders-card.png", max_diff_pixels=border_pixels)
        print(f"With max_diff_pixels={border_pixels}: passes")


if __name__ == "__main__":
    main()

    Baseline recorded
No tolerance: 200 pixels (0.91%) differ
With max_diff_pixels=200: passes

    Allowing exactly the border's pixels documents what the test tolerates. A larger number "just to be safe" would also let through a change to the card's text.

    Exercise 3: one baseline per browser¶

    Record a masked baseline of the dashboard named dashboard.png in Chrome and in Firefox (launch each in turn in the same script), then list the files in the snapshot folder. Why are there two, and why do their sizes differ?

    Solution 
    """Lesson 05, exercise 3: record the same baseline in Chrome and in Firefox, and compare the names.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from pathlib import Path

from steero import LaunchError
from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    snapshots = Path(tempfile.mkdtemp(prefix="steero-lesson05-"))
    expect.set_options(snapshot_dir=snapshots)

    for name in ("chrome", "firefox"):
        try:
            browser = launch(name, headless=HEADLESS)
        except LaunchError as error:  # only one browser installed: say so and carry on
            print(f"{name}: not available ({error})")
            continue
        with browser:
            page = browser.new_page()
            page.set_viewport_size({"width": 800, "height": 400})
            page.goto(BASE_URL + "dashboard.html")
            try:
                expect(page).to_have_screenshot("dashboard.png", mask=[page.locator("#clock")])
            except AssertionError:
                print(f"{name}: baseline recorded")

    # One name in the test, one file per browser (and per operating system) on disk.
    for file in sorted(snapshots.iterdir()):
        print("  ", file.name, f"{file.stat().st_size:,} bytes")


if __name__ == "__main__":
    main()

    chrome: baseline recorded
firefox: baseline recorded
   dashboard-chrome-win32.png 12,417 bytes
   dashboard-firefox-win32.png 12,450 bytes

    One name in the code gives one file per browser, because the two browsers render the same page differently (fonts, anti-aliasing, form controls), and comparing a Firefox screenshot with a Chrome baseline would always fail. The platform part of the name keeps Windows and Linux baselines apart for the same reason. If you have only one browser, the script says so and records one file.

    Common mistakes¶

    Common mistakes

    • Thinking the first failure is a bug. "No baseline existed" means steero just wrote one. Check the PNG, then run again.
    • Updating baselines without looking at them. STEERO_UPDATE_SNAPSHOTS=1 accepts whatever the page shows, bugs included. Look at every changed PNG before committing it.
    • Leaving STEERO_UPDATE_SNAPSHOTS=1 set. Every visual test then passes, because each one rewrites its baseline. Unset it after the update run.
    • A clock, a date or an avatar in the screenshot. The test fails on every run. Mask it, or screenshot a smaller element that does not include it.
    • Not fixing the viewport size. Baselines from a 1280 pixel window fail in a 1024 pixel one with "size differs". Call set_viewport_size before visual checks.
    • Raising the tolerance until the test passes. A big max_diff_pixel_ratio hides real regressions. Find what changes (open the diff) and mask it instead.
    • Recording baselines on your laptop and running on Linux. The platform is in the file name, so the build machine finds no baseline. Record them where the tests run.

    Recap¶

    • expect(page_or_locator).to_have_screenshot("name.png") compares against a baseline and retries until it matches or the timeout passes.
    • Baselines are named <name>-<browser>-<platform>.png; set the folder with expect.set_options(snapshot_dir=...) or STEERO_SNAPSHOT_DIR.
    • A missing baseline is written and the assertion fails; STEERO_UPDATE_SNAPSHOTS=1 rewrites baselines on purpose.
    • Animations and the caret are frozen for you; mask what changes, fix the viewport size, and keep threshold, max_diff_pixels and max_diff_pixel_ratio as small as works.
    • A failure leaves -actual.png and -diff.png next to the baseline: open the diff, then fix the page or update the baseline.
