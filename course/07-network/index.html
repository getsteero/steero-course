    07. Network¶

    In this lesson

    You will learn to:

    • watch requests and responses with page events
    • wait for the response an action triggers with expect_response
    • mock an endpoint with page.route and route.fulfill, block requests with route.abort, and change requests with route.continue_
    • change a real response with route.fetch, and pass a request on with route.fallback
    • answer HTTP authentication, and call APIs directly with steero.request and context.request

    Time: about 60 minutes. Before this: 06. Contexts and emulation. Code: examples/course/07-network/

    A web page is mostly a conversation with servers. Being able to listen to that conversation, and to answer in the server's place, lets you test what a page does when the API is empty, slow, broken or offline, without changing the server at all. This lesson uses the Products page (products.html), which loads its table from /api/products.

    Seeing the traffic¶

    Every request a page makes fires a request event, and every answer a response event. A request that fails without an answer (a refused connection, a blocked request) fires requestfailed instead. Listen with page.on:

    page.on("request", lambda request: print(">>", request.method, request.url))
page.on("response", lambda response: print("<<", response.status, response.url))
page.on("requestfailed", lambda request: print("failed:", request.url, request.failure))
page.goto(BASE_URL + "products.html")

    A Request has url, method, headers, resource_type and, once answered, response. A Response has url, status, ok (true for 200 to 299), headers and its request. Header names are lower case in headers; headers_array() keeps them as sent.

    Lesson 08 covers events in general. For now, one rule: a listener only sees what happens after you register it, so register it before goto.

    Waiting for a response¶

    Often you want one particular response: the one a click causes. page.expect_response(url) wraps the action in a with block. It starts listening when the block starts, so a fast response cannot slip past, and when the block ends it waits (up to 30 seconds) for a matching response:

    with page.expect_response("**/api/products") as waiter:
    page.get_by_role("button", name="Reload").click()
response = waiter.value
print(response.status)          # 200

    The pattern is a glob: ** matches any text, * any text without a slash, ? one character, and {a,b} either alternative. You can also pass a compiled regex (re.compile(r"/api/products$")) or a function that takes the URL and returns True or False. The same patterns work everywhere in this lesson. expect_request is the same for requests.

    To check more than the URL, add predicate=, a function that takes the Response: page.expect_response("**/api/products", predicate=lambda r: r.ok). And expect_response only counts responses to requests that start after the with block begins, so a response from earlier (such as a mocked one you just removed with unroute_all()) never satisfies it.

    Coming from Playwright

    page.goto() returns the main document's Response, as in Playwright (None for about:blank and other pages with no response), so page.goto(url).status works. To wait for any other response, wrap the action in expect_response, as the worked example does. Timeouts are in seconds: expect_response("**/api/*", timeout=5).

    Response bodies¶

    A browser does not keep response bodies around for scripts unless asked, because they can be large. Call browser.collect_response_bodies() once, before the requests you care about, and then response.body(), text() and json() work:

    browser.collect_response_bodies()
with page.expect_response("**/api/products") as waiter:
    page.get_by_role("button", name="Reload").click()
products = waiter.value.json()

    The same collector keeps request bodies, so request.post_data() and request.post_data_json() return what the page sent. Here is all of it in one script:

    """Lesson 07: watch the traffic a page makes, and wait for the response a click triggers.

Logs every request and response of the products page, then reloads the product list with the
Reload button and reads the JSON the page received.

    python examples/course/serve.py                     # terminal 1
    python examples/course/07-network/example_traffic.py # terminal 2

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        browser.collect_response_bodies()  # keep bodies, so response.json() works
        page = browser.new_page()
        page.on("request", lambda request: print(">>", request.method, request.url.replace(BASE_URL, "/")))
        page.on("response", lambda response: print("<<", response.status, response.url.replace(BASE_URL, "/")))

        page.goto(BASE_URL + "products.html")
        expect(page.get_by_role("status")).to_have_text("3 products")

        # Subscribe first, then act: the waiter catches the response the click causes.
        with page.expect_response("**/api/products") as waiter:
            page.get_by_role("button", name="Reload").click()
        response = waiter.value
        products = response.json()
        print(f"Reload answered {response.status} with {len(products)} products:",
              ", ".join(p["name"] for p in products))


if __name__ == "__main__":
    main()

    >> GET /products.html
<< 200 /products.html
>> GET /course.css
<< 200 /course.css
>> GET /api/products
<< 200 /api/products
>> GET /api/products
<< 200 /api/products

    The order of the lines can differ between runs and browsers, because the browser fetches in parallel; Firefox also asks for /favicon.ico.

    Mocking with route¶

    page.route(pattern, handler) intercepts every matching request before it leaves the browser. The handler receives a Route and decides what happens. route.fulfill(...) answers the request itself, so the server never sees it:

    page.route("**/api/products", lambda route: route.fulfill(json=[]))             # an empty list
page.route("**/api/products", lambda route: route.fulfill(status=500))          # a server error
page.route("**/api/user", lambda route: route.fulfill(json={"name": "Ada"}))    # any JSON
page.route("**/logo.png", lambda route: route.fulfill(path="tests/logo.png"))   # a file

    fulfill takes status, headers, body (text or bytes), json (any value, sent as JSON with the right content type), content_type and path. Three rules decide which handler runs:

    • The newest matching route wins. Add a new route for the same pattern and it takes over.
    • Unmatched requests go to the network as usual.
    • page.unroute(pattern) removes a route, page.unroute_all() removes them all.

    context.route(...) works the same for every page of a context; a page's own routes are tried first.

    A one-call handler fits in a lambda, as above. A handler that has to do several things (look at the request, decide, then answer) is an ordinary function:

    def products_or_error(route: Route) -> None:
    if route.request.headers.get("x-break") == "1":
        route.fulfill(status=500)
    else:
        route.continue_()

page.route("**/api/products", products_or_error)

    In the sync API the handler gets a sync Route and runs on a worker thread, so it can call route.fetch(), route.fulfill() or any other sync method, as many times as it needs. With the async API, write the handler as an async def and await each call; the async version of the worked example shows one.

    Blocking and changing requests¶

    route.abort() fails the request as if the network were down. Blocking images, fonts, analytics or third-party scripts makes a test faster and keeps it away from servers you do not control:

    page.route(re.compile(r"\.(png|jpe?g|svg)$"), lambda route: route.abort())
page.route("**/analytics/**", lambda route: route.abort())

    route.continue_(...) sends the request to the network, optionally changed: a different url, method, headers or post_data. (The trailing underscore is because continue is a Python keyword.)

    page.route("**/api/**", lambda route: route.continue_(
    headers={**route.request.headers, "x-test-run": "lesson-07"}))

    Changing a real response¶

    Sometimes you want the real data with one thing changed: an extra product, a feature flag switched on, an error in one field. route.fetch() performs the request and returns the real response without answering the page; you then fulfill with it, changing what you need:

    def add_product(route: Route) -> None:
    response = route.fetch()                             # the real answer
    products = response.json()
    products.append({"id": 4, "name": "Yellow cup", "price": 6.25, "stock": 9})
    route.fulfill(response=response, json=products)      # same status and headers, new body

    fulfill(response=...) keeps the fetched status and headers unless you override them. route.fetch() is made by Python's own HTTP client with the page's headers and cookies, not by the browser, so it does not use the browser's cache or proxy.

    route.fallback() passes the request on to the next matching handler: an older route of the page, then the context's routes. That lets a general route set a default and a specific one step aside:

    context.route("**/api/**", lambda route: route.fulfill(json={"mocked": True}))   # default for every page
page.route("**/api/products", lambda route: route.fallback())                     # this page: let the context decide

    fallback takes the same changes as continue_ (headers=, url=, ...), applied when a later handler continues the request. If no handler is left, the request goes to the network.

    HTTP authentication¶

    Some pages are protected by HTTP authentication: the server answers 401 with a WWW-Authenticate header, and a browser would show a sign-in dialog. A test answers it with credentials instead, for a whole context or for one page:

    context = browser.new_context(http_credentials={"username": "ada", "password": "secret"})
page.set_http_credentials({"username": "ada", "password": "secret"})    # one page only

    The practice site's /api/basic-auth accepts user ada with password secret. Credentials that the server refuses are not retried: the page gets the 401 response, which on the practice site is a page saying "Sign-in required". With no credentials at all the challenge is cancelled the same way, so the page shows the 401 rather than a sign-in dialog. Page credentials win over the context's when both are set. Browsers remember credentials that worked for the rest of the session, so test the failure case in a context of its own.

    The API request context¶

    Not every check needs a page. steero.request is an HTTP client with no browser at all: it is the quickest way to set up test data, call an API, or check one directly.

    from steero.sync_api import expect, request

with request.new_context(base_url=BASE_URL) as api:
    response = api.post("api/echo", data={"name": "Ada"})   # a dict or list is sent as JSON
    expect(response).to_be_ok()
    print(response.json())

    It has get, post, put, patch, delete, head and fetch. data= sends JSON, form= a form, params= a query string. A 404 or 500 comes back as a response (check response.ok or response.status) rather than raising, unless you pass fail_on_status_code=True. expect(response).to_be_ok() fails with the status and the URL.

    context.request is the same client attached to a browser context: it shares the context's cookies. Sign in through the API and the context's pages are signed in too, which is faster than filling in a form:

    """Lesson 07: sign in through the API with context.request, and the pages are signed in too.

``context.request`` sends HTTP requests from Python that share the context's cookies. The
script posts to /api/login, then opens a page in the same context: it already has the cookie.

    python examples/course/07-network/example_api_request.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        context = browser.new_context(base_url=BASE_URL)

        refused = context.request.post("api/login", data={"user": "ada", "password": ""})
        print("Without a password:", refused.status, refused.json())

        response = context.request.post("api/login", data={"user": "ada", "password": "lovelace"})
        expect(response).to_be_ok()
        print("Signed in through the API:", response.json())

        page = context.new_page()
        page.goto("whoami.html")  # relative to base_url
        expect(page.get_by_test_id("cookies")).to_have_text("session=ada")
        print("The page has the cookie:", page.get_by_test_id("cookies").text_content())
        print("The API agrees:", context.request.get("api/me").json())


if __name__ == "__main__":
    main()

    Without a password: 401 {'error': 'user and password are required'}
Signed in through the API: {'user': 'ada'}
The page has the cookie: session=ada
The API agrees: {'user': 'ada'}

    base_url= on the context makes page.goto("whoami.html") and context.request.post("api/login") relative to the practice site.

    Coming from Selenium

    Selenium cannot see or change network traffic without a proxy or CDP-only extras. In steero events, routes and context.request are part of the core API and work the same in Chrome and Firefox, because they are WebDriver BiDi commands.

    Worked example¶

    The products page shows a table when /api/products returns products, "No products yet" for an empty list, and an error message when the request fails or returns an error status. Testing those states against a real server would mean emptying its database or breaking it. With route, each state is one line. The script:

    1. loads the page normally, waits for the real /api/products response, and checks the table;
    2. routes the endpoint to an empty list and reloads;
    3. routes it to a 500, which replaces the empty list because the newest route wins;
    4. aborts it, so the page sees a network failure;
    5. removes every route, and the real data comes back.
    """Lesson 07: mock an API with page.route and check every state the page can show.

The products page loads /api/products. The script checks the real answer first, then answers
the same request itself: with an empty list, with a server error, and with a network failure.

    python examples/course/07-network/example_mock_products.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        state = page.get_by_role("status")

        # 1. The real server: wait for its response, then for the page to show it.
        with page.expect_response("**/api/products") as waiter:
            page.goto(BASE_URL + "products.html")
        print("Real API answered", waiter.value.status)
        expect(state).to_have_text("3 products")

        # 2. An empty list, without touching the server.
        page.route("**/api/products", lambda route: route.fulfill(json=[]))
        page.reload()
        expect(state).to_have_text("No products yet")
        print("Empty list:", state.text_content())

        # 3. A server error. The newest matching route wins, so this one replaces the empty list.
        page.route("**/api/products", lambda route: route.fulfill(status=500))
        page.get_by_role("button", name="Reload").click()
        expect(state).to_have_text("Could not load products (HTTP 500)")
        print("Server error:", state.text_content())

        # 4. No answer at all: the request fails as a network error.
        page.route("**/api/products", lambda route: route.abort())
        page.get_by_role("button", name="Reload").click()
        expect(state).to_contain_text("Could not load products")
        print("Network failure:", state.text_content())

        # Remove every route: the real server answers again.
        page.unroute_all()
        page.get_by_role("button", name="Reload").click()
        expect(state).to_have_text("3 products")
        print("Routes removed:", state.text_content())


if __name__ == "__main__":
    main()

    python examples/course/07-network/example_mock_products.py

    Real API answered 200
Empty list: No products yet
Server error: Could not load products (HTTP 500)
Network failure: Could not load products (Failed to fetch)
Routes removed: 3 products

    The network failure text comes from the browser: Chrome says "Failed to fetch", Firefox "NetworkError when attempting to fetch resource.", which is why that step checks with to_contain_text.

    Async version

    Here the route handler is an async def that counts the requests and answers each one differently: an empty list first, then a 503.

    """Lesson 07: the routing example with the async API and async route handlers.

A handler that does more than one thing (look at the request, decide, answer) reads best as an
``async def``. This one sends an empty list for the first request and a server error after that.

    python examples/course/07-network/example_mock_products_async.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import asyncio
import os

import steero
from steero import expect

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        page = await browser.new_page()
        calls = 0

        async def products(route: steero.Route) -> None:
            nonlocal calls
            calls += 1
            print(f"Request {calls}: {route.request.method} {route.request.url.replace(BASE_URL, '/')}")
            if calls == 1:
                await route.fulfill(json=[])
            else:
                await route.fulfill(status=503)

        await page.route("**/api/products", products)
        await page.goto(BASE_URL + "products.html")
        state = page.get_by_role("status")
        await expect(state).to_have_text("No products yet")
        print("First load:", await state.text_content())

        await page.get_by_role("button", name="Reload").click()
        await expect(state).to_have_text("Could not load products (HTTP 503)")
        print("Reload:", await state.text_content())


if __name__ == "__main__":
    asyncio.run(main())

    The handler awaits route.fulfill(...). A handler that returns without fulfilling, continuing or aborting is continued for you, so a mistake in a handler cannot hang the page.

    Exercise 1: no pictures¶

    The Gallery page (gallery.html) shows three pictures and a line saying how many loaded. Block every image with one route, check that the page reports "0 of 3 pictures loaded", and that its Like button still works. Print the names of the blocked files.

    Hint: the pictures are .svg files; a regex can match several extensions at once.

    Solution 
    """Lesson 07, exercise 1: block every image with one route and check the page still works.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import re

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        blocked: list[str] = []
        page.on("requestfailed", lambda request: blocked.append(request.url.rsplit("/", 1)[-1]))
        # A regex matches anywhere in the URL; this one catches the usual image types.
        page.route(re.compile(r"\.(png|jpe?g|gif|webp|svg)$"), lambda route: route.abort())

        page.goto(BASE_URL + "gallery.html")
        expect(page.get_by_role("status")).to_have_text("0 of 3 pictures loaded")

        # The rest of the page still works without its pictures.
        page.get_by_role("button", name="Like").click()
        expect(page.get_by_test_id("likes")).to_have_text("1")
        print("Blocked:", ", ".join(sorted(blocked)))
        print("The Like button still works")


if __name__ == "__main__":
    main()

    Every aborted request fires requestfailed, which is how the solution collects the names.

    Exercise 2: one more product¶

    Use route.fetch to get the real product list, add a fourth product to it, and fulfil the request with the changed list. Check that the page shows "4 products" and the new row.

    Hint: the handler fetches, changes and fulfils: three calls in one ordinary function. Each row has the test id product-<id>.

    Solution 
    """Lesson 07, exercise 2: fetch the real product list and add a fourth product to it.

``route.fetch()`` gets the real response; ``route.fulfill(response=..., json=...)`` sends it on
with a changed body. The handler does three steps, so it is an ordinary function: in the sync
API it gets a sync ``Route`` and runs on a worker thread, so each call simply blocks.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (a plain sync handler now that sync route handlers get a sync Route)
"""

import os

from steero.sync_api import Route, expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

YELLOW_CUP = {"id": 4, "name": "Yellow cup", "price": 6.25, "stock": 9}


def add_product(route: Route) -> None:
    response = route.fetch()  # the real answer from the server
    products = response.json()
    products.append(YELLOW_CUP)
    route.fulfill(response=response, json=products)  # same status and headers, new body


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.route("**/api/products", add_product)
        page.goto(BASE_URL + "products.html")

        expect(page.get_by_role("status")).to_have_text("4 products")
        row = page.get_by_test_id("product-4")
        expect(row).to_contain_text("Yellow cup")
        expect(row).to_contain_text("$6.25")
        print("The page shows 4 products, the last one:", row.get_by_role("cell").first.text_content())


if __name__ == "__main__":
    main()

    The first three products come from the server, so if someone changes them there, this test still checks the real data plus the one you added.

    Exercise 3: an echo, no browser¶

    Post the JSON {"product": "Blue mug", "quantity": 2} to /api/echo with steero.request, and assert that the server echoes the method, the body and the Content-Type it received. Add an X-Course header to every request of the client and check that it arrives too. Then show that /api/status/404 comes back as a response with status 404.

    Solution 
    """Lesson 07, exercise 3: post JSON to /api/echo with steero.request, no browser at all.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, request

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with request.new_context(base_url=BASE_URL, extra_http_headers={"X-Course": "lesson-07"}) as api:
        order = {"product": "Blue mug", "quantity": 2}
        response = api.post("api/echo", data=order)  # a dict is sent as JSON
        expect(response).to_be_ok()

        echoed = response.json()
        assert echoed["method"] == "POST"
        assert echoed["body"] == order
        headers = {name.lower(): value for name, value in echoed["headers"].items()}
        assert headers["content-type"] == "application/json"
        assert headers["x-course"] == "lesson-07"
        print("The server echoed:", echoed["body"])

        missing = api.get("api/status/404")  # 4xx and 5xx come back as responses, not errors
        assert missing.status == 404 and not missing.ok
        print("A 404 is a response too:", missing.status)


if __name__ == "__main__":
    main()

    The echo shows header names as the client sent them, so the solution compares them in lower case.

    Exercise 4: members only¶

    Open /api/basic-auth once with the wrong password and once with the right one (ada / secret). Assert the 401 and the "Sign-in required" heading the first time, and the 200 and "Welcome, ada" the second time.

    Solution 
    """Lesson 07, exercise 4: HTTP basic authentication, refused and accepted.

Each attempt uses a context of its own, because a browser remembers credentials that worked.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        for password, status, heading in (("wrong", 401, "Sign-in required"), ("secret", 200, "Welcome, ada")):
            context = browser.new_context(http_credentials={"username": "ada", "password": password})
            page = context.new_page()
            with page.expect_response("**/api/basic-auth") as waiter:
                page.goto(BASE_URL + "api/basic-auth")
            assert waiter.value.status == status, waiter.value.status
            expect(page.get_by_role("heading")).to_have_text(heading)
            print(f"Password {password!r}: {status} {heading}")
            context.close()


if __name__ == "__main__":
    main()

    Each attempt gets a fresh context, so the browser cannot reuse credentials that worked earlier.

    Common mistakes¶

    Common mistakes

    • Starting expect_response after the click. The response may already have arrived, and the waiter times out with no 'response' event within 30 s. Put the action inside the with block.
    • response.json() raises UnsupportedOnBrowser: response bodies are off. Bodies are only kept after browser.collect_response_bodies(); call it before the request is made.
    • A route that never matches. "/api/products" is compared with the full URL (http://127.0.0.1:8765/api/products) and matches nothing. Start globs with **/, or use a regex.
    • Two routes for one URL, and the older one seems ignored. The newest matching route wins. Remove the newer one with unroute, or have it call route.fallback().
    • Mixing the two APIs in a handler. A sync handler (def or lambda) gets a sync Route and calls it without await. An async def handler gets the async Route, even when you register it with the sync API, and must await every call; forgetting one sends the request to the real server.
    • Expecting a sign-in dialog for a protected page. A test never sees one: with no credentials steero cancels the challenge and the page shows the 401 response. Assert that response, or give credentials.
    • Expecting route.fetch() to go through the browser's proxy or cache. It is made from Python. Use route.continue_() when the browser itself must send the request.

    Recap¶

    • page.on("request" / "response" / "requestfailed") shows the traffic; expect_response waits for the one an action causes, if you start it before the action.
    • page.route(pattern, handler) intercepts requests: fulfill answers, abort fails, continue_ sends on (changed), fallback passes to the next handler. The newest route wins.
    • route.fetch() plus fulfill(response=..., json=...) changes a real response.
    • http_credentials (context) and set_http_credentials (page) answer HTTP authentication.
    • steero.request calls APIs with no browser; context.request shares the context's cookies.
