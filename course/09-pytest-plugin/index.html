    09. The pytest plugin¶

    In this lesson

    You will learn to:

    • write tests with the steero_page, steero_context and steero_browser fixtures
    • run one suite in several browsers with --browser (or --steero-browser)
    • use the options that matter day to day: headed, timeout, base URL, screenshots, video and tracing
    • find and read the failure artifacts (screenshot, HTML, diagnostics)
    • customise launch options and add your own fixtures in conftest.py

    Time: about 45 minutes. Before this: 08. Events, dialogs, downloads and popups. Code: examples/course/09-pytest-plugin/

    Up to now every lesson has been a script: launch, do something, close. A real test suite has dozens of tests that each need a clean browser state, run in more than one browser, and leave evidence behind when they fail. steero's pytest plugin does all of that for you, so a test is only the part you care about.

    Your first test¶

    Installing steero also installs a pytest plugin; there is nothing to enable. A test asks for a page by naming the steero_page fixture as an argument:

    from steero.sync_api import Page, expect


def test_sign_in(steero_page: Page) -> None:
    steero_page.goto("http://127.0.0.1:8765/login.html")
    steero_page.get_by_label("User name").fill("ada")
    steero_page.get_by_label("Password").fill("lovelace")
    steero_page.get_by_role("button", name="Sign in").click()
    expect(steero_page.get_by_role("status")).to_have_text("Welcome, ada")

    Save it as test_sign_in.py and run pytest test_sign_in.py. pytest finds the function because its name starts with test_, sees that it wants steero_page, and asks the plugin for one. The plugin launches Chrome (headless), opens a page, runs the test, and closes everything afterwards. There is no launch() and no with block in the test.

    Tests use the sync API (from steero.sync_api import ...), like the scripts in earlier lessons. The plugin's fixtures are sync objects, so there is no await anywhere.

    Coming from Playwright

    pytest-playwright calls its fixtures page, context and browser. steero prefixes its own with steero_ so that both plugins can be installed side by side without fighting over page. If you prefer the short name, add a one-line alias (shown in Configuring). For an existing pytest-playwright suite, lesson 15 shows the opt-in plugin -p steero.compat.playwright.pytest, which provides Playwright's exact fixture names and millisecond timeouts.

    Coming from Selenium

    You do not write a driver fixture with yield and driver.quit(): the plugin owns the browser's lifetime, and it always closes it, even when a test fails or you press Ctrl+C.

    The fixtures¶

    The plugin provides a small family of fixtures. Each has a scope: how long one instance lives before pytest makes a new one.

    Fixture Scope What you get
    steero_browser session one browser, shared by every test in the run (per browser chosen)
    steero_context test a fresh, isolated browser context: its own cookies, storage and cache
    steero_page test a page in that context, with the default action timeout set
    steero_launch_options session the keyword arguments passed to launch(); override it to customise
    steero_healer test a self-healing helper for steero_page (lesson 12)

    Starting a browser takes a second or two, so it happens once per session. A context is cheap (milliseconds), so every test gets a new one. That gives you isolation for free: a test that signs in cannot leave a cookie or a localStorage entry behind for the next test, and tests can run in any order.

    When a test needs two pages in the same context (a popup, say), ask for steero_context and call steero_context.new_page(). When it needs two separate users at once, ask for steero_browser and create a second context with steero_browser.new_context(); close that one yourself at the end of the test.

    Several browsers¶

    Choose browsers on the command line, once per browser:

    pytest --browser chrome --browser firefox

    The plugin parametrizes every steero test over the browsers, so each test runs once per browser and its test id ends with the browser in square brackets:

    tests/test_shop.py::test_products_table_loads[chrome] PASSED
tests/test_shop.py::test_products_table_loads[firefox] PASSED

    Use the id to run one combination, for example pytest "tests/test_shop.py::test_products_table_loads[firefox]", or -k firefox for every Firefox run. Without any --browser, tests run in Chrome.

    To skip one browser in one test, ask for steero_browser_name, the name the current run was parametrized with:

    import pytest


def test_print_to_pdf(steero_browser_name: str, steero_page: Page) -> None:
    if steero_browser_name != "chrome":
        pytest.skip("printing to PDF is a Chrome-only feature")
    ...

    Browser support

    --browser accepts chrome, firefox and edge, plus Playwright's spellings chromium (meaning Chrome) and msedge (meaning Edge). --browser webkit is a usage error rather than a silent skip: Safari has no WebDriver BiDi, so steero cannot drive it. Add --steero-backend chromium-bidi to reach Chrome without chromedriver (lesson 13).

    Options worth knowing¶

    All of these are command-line options. The table shows pytest-playwright's names, which steero accepts too, with the --steero- spelling that always works:

    Option Meaning
    --browser NAME / --steero-browser NAME browser to run in; repeat for several
    --headed / --steero-headed show the browser window
    --steero-timeout 10 default action timeout for steero_page, in seconds
    --base-url URL / --steero-base-url URL relative goto() URLs resolve against it
    --screenshot on\|off\|only-on-failure save a screenshot when each test ends
    --video on\|off\|retain-on-failure record a video of each test
    --tracing on\|off\|retain-on-failure record a trace of each test (lesson 10)
    --output DIR where those per-test files go (default test-results)

    --base-url is the one to adopt first. With it, a test says steero_page.goto("login.html") and the same suite runs against your laptop, a test server or staging by changing one option.

    --steero-timeout sets how long each action on steero_page (a click, a fill) may wait. It is 10 seconds by default; assertions keep their own default of 5 seconds.

    --screenshot, --video and --tracing each record something per test into --output/<test id>/: test-failed-1.png or test-finished-1.png, a video/ folder, and trace.zip. only-on-failure and retain-on-failure record every test but keep the file only when the test failed, which is the setting you want on a build server.

    Put options you always use in your project's configuration rather than typing them each time:

    # pytest.ini
[pytest]
addopts = --browser chrome --base-url http://127.0.0.1:8765/ --screenshot only-on-failure

    When pytest-playwright is installed too

    The plain names (--browser, --headed, --base-url, --screenshot and the rest) are registered by steero only when pytest-playwright is not installed; when it is, those names belong to pytest-playwright and steero registers only its --steero- spellings. --base-url likewise belongs to pytest-base-url if that is installed. The course's example scripts use the --steero- spellings so they work either way.

    When a test fails¶

    A failing test that used steero_page gets a folder of evidence under steero-artifacts/ (change it with --steero-artifacts DIR), named after its test id:

    File What it holds
    screenshot.png the whole page, at the moment the test failed
    page.html the page's HTML at that moment
    diagnostics.json the page URL, console messages, uncaught page errors and failed requests

    The folder's path is printed in the failure report, in a section headed steero, so you do not have to search for it. diagnostics.json is often the fastest clue: an uncaught JavaScript error or a request that failed with a 500 usually explains a test that "suddenly" cannot find a button.

    These failure artifacts are always on; --screenshot, --video and --tracing add the per-test files in --output on top.

    Configuring¶

    pytest loads a file called conftest.py automatically for every test in its folder and below. Fixtures defined there are available to those tests without an import. Three things people usually put there:

    A short page name. A fixture that returns another fixture is an alias:

    import pytest
from steero.sync_api import Page


@pytest.fixture
def page(steero_page: Page) -> Page:
    return steero_page

    Launch options. Override steero_launch_options and build on the plugin's own value, which already carries --headed and --steero-backend:

    from typing import Any


@pytest.fixture(scope="session")
def steero_launch_options(steero_launch_options: dict[str, Any]) -> dict[str, Any]:
    return {**steero_launch_options, "window_size": (1024, 768)}

    A fixture may ask for the fixture it replaces, by the same name: pytest gives it the plugin's version. The override must keep the plugin's session scope.

    A fixture that does the boring part. Most tests of an app start signed in, so put the signing in into a fixture and let tests ask for signed_in_page. Exercise 4 builds exactly that. When signing in is slow (a real login page, two-factor), do it once per session instead: sign in, save the context's storage state with context.storage_state(path=...), and start each test's context with steero_browser.new_context(storage_state=...). Lesson 06 covers storage state.

    Parallel runs¶

    pytest-xdist runs tests in several processes at once: pip install pytest-xdist, then pytest -n 4. It works with steero unchanged. Each worker is a separate Python process with its own session, so each launches its own browser and its tests get their own contexts, as before. Self-healing baselines (lesson 12) are written to one file per worker and merged when the run ends, so workers never overwrite each other.

    Because every test already gets a fresh context, a suite that passes in order passes in parallel, as long as the tests do not share something outside the browser (a database row, a file).

    The lesson's folder holds a small suite, tests/test_shop.py: three tests against the practice site, where the last one is written to fail.

    """Lesson 09: a small test suite for the practice site, run by ``example_run_tests.py``.

Three tests use the ``steero_page`` fixture. The last one is written to fail, so a run shows

from steero.sync_api import Page, expect


def test_home_page_lists_the_course_pages(steero_page: Page) -> None:
    steero_page.goto("index.html")
    expect(steero_page.get_by_role("heading", name="Practice site")).to_be_visible()
    expect(steero_page.get_by_role("heading", name="Course pages")).to_be_visible()


def test_products_table_loads(steero_page: Page) -> None:
    steero_page.goto("products.html")
    expect(steero_page.get_by_role("status")).to_have_text("3 products")
    expect(steero_page.get_by_role("row")).to_have_count(4)  # the header row and three products


def test_deliberately_wrong_title(steero_page: Page) -> None:
    steero_page.goto("login.html")
    steero_page.evaluate("console.log('checking the title')")  # shows up in diagnostics.json
    # The real title is "Sign in - steero practice site", so this fails after 2 seconds.
    expect(steero_page, timeout=2).to_have_title("Log in - steero practice site")

    You can run the suite yourself, with the practice site running in another terminal:

    pytest examples/course/09-pytest-plugin/tests -v --base-url http://127.0.0.1:8765/

    The course test runs every example_*.py and solution_*.py file as a script, so the worked example is a script that runs pytest for you, exactly as you would in a terminal, and then checks the result. It uses a small helper, pytest_run.py, that runs python -m pytest in a child process with a JUnit XML report and reads the pass and fail counts back from it. All output goes to a steero-course folder in your temporary directory.

    """Lesson 09: run the lesson's test suite with the steero pytest plugin, and check what it did.

Runs ``tests/test_shop.py`` in the course browser against the practice site, then checks that two
tests passed, one failed, and that the plugin saved artifacts for the failure. Everything is
written to a ``steero-course`` folder in your temporary directory, never into the repository.

    python examples/course/09-pytest-plugin/example_run_tests.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import shutil
import tempfile
from pathlib import Path

from pytest_run import run_pytest

# course: timeout=180

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

HERE = Path(__file__).resolve().parent
OUT = Path(tempfile.gettempdir()) / "steero-course" / "09-pytest-plugin"


def main() -> None:
    shutil.rmtree(OUT, ignore_errors=True)
    args = [str(HERE / "tests"), "-v", "--tb=short",
            "--steero-browser", BROWSER, "--steero-base-url", BASE_URL,
            "--steero-screenshot", "only-on-failure", "--steero-output", str(OUT / "test-results"),
            "--steero-artifacts", str(OUT / "steero-artifacts")]
    if not HEADLESS:
        args.append("--steero-headed")
    outcome = run_pytest(*args, out=OUT)

    print(f"exit code {outcome.exit_code}: {outcome.passed} passed, {outcome.failures} failed")
    assert (outcome.passed, outcome.failures, outcome.errors) == (2, 1, 0), outcome
    assert outcome.exit_code == 1, "pytest exits 1 when a test failed"

    # The plugin's failure artifacts: one folder per failed test, named after its test id.
    (failure,) = (OUT / "steero-artifacts").iterdir()
    print("Failure artifacts:", failure)
    for file in sorted(failure.iterdir()):
        print("   ", file.name)
    assert {"screenshot.png", "page.html", "diagnostics.json"} <= {f.name for f in failure.iterdir()}

    # --screenshot only-on-failure: one more picture, in the per-test --output folder.
    (screenshot,) = (OUT / "test-results").glob("*/test-failed-1.png")
    print("Per-test screenshot:", screenshot)


if __name__ == "__main__":
    main()

    assert signed_in_page.evaluate("localStorage.getItem('user')") == "ada"

    """Lesson 09, exercise 4: tests that start signed in, through a fixture in ``conftest.py``.

Runs ``exercises/test_signed_in.py``; its ``signed_in_page`` fixture comes from
``exercises/conftest.py``, which also overrides ``steero_launch_options``.

    python examples/course/09-pytest-plugin/solution_4_signed_in_fixture.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from pathlib import Path

from pytest_run import run_pytest

# course: timeout=180

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

HERE = Path(__file__).resolve().parent
OUT = Path(tempfile.gettempdir()) / "steero-course" / "09-pytest-plugin" / "exercise-4"


def main() -> None:
    args = [str(HERE / "exercises" / "test_signed_in.py"), "-v",
            "--steero-browser", BROWSER, "--steero-base-url", BASE_URL]
    if not HEADLESS:
        args.append("--steero-headed")
    outcome = run_pytest(*args, out=OUT)
    assert outcome.exit_code == 0 and outcome.passed == 2, outcome
    print("Both tests started on a signed-in page.")


if __name__ == "__main__":
    main()

    The fixture ends with an expect, so a test never starts on a page that is still signing in. Each test still gets its own context: the second test is signed in because the fixture ran again, not because the first test's state leaked into it.

    Common mistakes¶

    Common mistakes

    • fixture 'page' not found. steero's fixture is steero_page. Use that name, or add the page alias to conftest.py.
    • unrecognized arguments: --browser (or --base-url), or the option seems ignored. pytest-playwright or pytest-base-url is installed and owns the plain name. Use the --steero- spelling: --steero-browser, --steero-base-url.
    • ProtocolError: browsingContext.navigate: invalid argument: Invalid URL: login.html. A relative goto() with no base URL to resolve against. Pass --base-url, or put it in addopts in pytest.ini.
    • ScopeMismatch when overriding steero_launch_options. The override must be scope="session", like the original, because the session-wide browser depends on it.
    • A test passes alone and fails in the full run. Something is shared outside the browser, or a test created its own context with steero_browser.new_context() and never closed it. Contexts from steero_context are closed for you; your own are not.
    • Looking for artifacts in the wrong folder. Failure artifacts go to steero-artifacts/; --screenshot, --video and --tracing files go to --output (test-results/). Both are relative to the folder you ran pytest from.
    • timeout=5000 in a test. Timeouts are seconds here too, also in --steero-timeout.

    Recap¶

    • Ask for steero_page in a test and the plugin launches, isolates and cleans up for you: one browser per session, a fresh context per test.
    • --browser chrome --browser firefox runs every test in each browser; the browser is part of the test id.
    • --base-url keeps addresses out of tests; --screenshot, --video and --tracing keep evidence per test in --output.
    • A failing test always leaves screenshot.png, page.html and diagnostics.json in steero-artifacts/<test id>/.
    • Put shared fixtures and option overrides in conftest.py.
