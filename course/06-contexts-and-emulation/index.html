    06. Contexts and emulation¶

    In this lesson

    You will learn to:

    • explain what a browser context is, and use one per user or per test
    • emulate a device with devices[...], and set the viewport, locale, time zone and color scheme
    • grant permissions and set a geolocation
    • work with cookies (add_cookies, cookies, clear_cookies), extra headers and init scripts
    • log in once and reuse the session with storage_state

    Time: about 45 minutes. Before this: 05. Visual testing. Code: examples/course/06-contexts-and-emulation/

    So far every script has used one browser and one page. Real tests need more: a clean session for each test, two users at once, a phone instead of a laptop, a visitor from Berlin, a user who is already signed in. All of these are one idea, the browser context, plus a handful of options you pass when you create it.

    What a context is¶

    A browser context is an isolated session inside one browser, like a private window. Each context has its own cookies, localStorage, cache and permissions. What one context stores, no other context can see, even though they all run in the same browser process.

    with launch(BROWSER, headless=HEADLESS) as browser:
    context = browser.new_context()      # a fresh, empty session
    page = context.new_page()            # a tab inside it
    page.goto(BASE_URL + "whoami.html")
    context.close()                      # closes its pages and throws its data away

    Creating a context takes milliseconds; launching a browser takes a second or more. That is why the usual pattern is one browser per test run and one context per test: every test starts with no cookies and no storage, and none of them pays for a new browser. The pytest plugin in lesson 09 does exactly this for you.

    Every browser also has a default context, browser.contexts[0]. browser.new_page() with no arguments opens a tab there, which is what lessons 01 to 05 did. The default context lives as long as the browser and cannot be closed, so use browser.new_context() whenever isolation matters.

    Coming from Playwright

    The same model and names: browser.new_context(...), context.new_page(), context.close(), browser.contexts. browser.new_page(locale="de-DE") with any context option also works: the page gets a context of its own, closed together with the page.

    Coming from Selenium

    Selenium has one session per driver, so isolating two users means two browsers. A context gives you the same isolation without a second browser: open as many as you like.

    Two users at once¶

    Because contexts do not share anything, two users can be signed in side by side: an admin and a guest, a buyer and a seller, or a chat between two people. This script signs Ada in, leaves a guest signed out, and checks what the Who am I page (whoami.html) tells each of them:

    """Lesson 06: two users at once, in two contexts of one browser.

Ada signs in in one context; a guest browses in another. Neither sees the other's
cookies or localStorage, although both pages run in the same browser process.

    python examples/course/06-contexts-and-emulation/example_two_users.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        ada = browser.new_context()
        guest = browser.new_context()
        ada_page = ada.new_page()
        guest_page = guest.new_page()

        ada_page.goto(BASE_URL + "login.html")
        ada_page.get_by_label("User name").fill("ada")
        ada_page.get_by_label("Password").fill("lovelace")
        ada_page.get_by_role("button", name="Sign in").click()
        expect(ada_page.get_by_role("status")).to_have_text("Welcome, ada")

        ada_page.goto(BASE_URL + "whoami.html")
        guest_page.goto(BASE_URL + "whoami.html")
        expect(ada_page.get_by_test_id("user")).to_have_text("ada")
        expect(guest_page.get_by_test_id("user")).to_have_text("nobody")

        print("Ada's cookies:  ", [c["name"] for c in ada.cookies()])
        print("Guest's cookies:", [c["name"] for c in guest.cookies()])
        print("Open pages:", len(browser.pages), "in", len(browser.contexts), "contexts (one is the default)")

        ada.close()  # closes Ada's page and throws her cookies and storage away
        guest.close()


if __name__ == "__main__":
    main()

    Ada's cookies:   ['session']
Guest's cookies: []
Open pages: 3 in 3 contexts (one is the default)

    The guest's page never sees Ada's session cookie or her localStorage entry. Three pages are open: the blank tab the browser started with in the default context, and one tab in each new context. context.pages lists only the pages of one context.

    Devices and viewports¶

    The same page can look completely different on a phone. Context options tell the browser what kind of device to pretend to be:

    Option What the page sees
    viewport={"width": 390, "height": 664} the size of the visible area, in CSS pixels
    screen={"width": 390, "height": 844} what window.screen reports
    device_scale_factor=3 window.devicePixelRatio
    user_agent="..." the User-Agent header and navigator.userAgent
    is_mobile=True honour <meta name=viewport> the way a phone does (Chrome only)
    has_touch=True a touch screen, navigator.maxTouchPoints (Chrome only)
    color_scheme="dark" prefers-color-scheme: dark in CSS and matchMedia

    Setting all of these by hand is tedious, so steero has device presets: devices maps a name to the options of a real device.

    from steero.sync_api import devices

print(devices["Pixel 7"]["viewport"])         # {'width': 412, 'height': 839}
context = browser.new_context(**devices["Pixel 7"], color_scheme="dark")

    There are iPhones, iPads, Pixel and Galaxy phones and tablets (each also as "<name> landscape") and desktop presets such as "Desktop Chrome"; list(devices) prints them all. The ** spreads the preset into keyword arguments, so you can add more options next to it.

    page.viewport_size reads the size back: the context's viewport (from the options or the preset), or None when the browser window decides. To resize a page that is already open, use page.set_viewport_size:

    page = context.new_page()
print(page.viewport_size)                               # {'width': 412, 'height': 839}
page.set_viewport_size({"width": 1024, "height": 768})
print(page.viewport_size)                               # {'width': 1024, 'height': 768}

    Browser support

    Firefox cannot emulate is_mobile or has_touch over WebDriver BiDi, so passing a phone preset there raises UnsupportedOnBrowser, naming the option. desktop_only drops those two keys and keeps the viewport, screen, scale factor and user agent, which is enough for most responsive layouts:

    from steero.api.devices import desktop_only

phone = devices["Pixel 7"]
if browser.name == "firefox":
    phone = desktop_only(phone)

    The other Chrome-only options are java_script_enabled=False, reduced_motion and forced_colors. steero never quietly ignores an option: if the browser cannot apply it, you get the error. The full table is in Emulation.

    Locale, time zone, geolocation and permissions¶

    locale sets the language the page sees (navigator.language, the Accept-Language header) and how Intl formats dates and numbers. timezone_id sets the clock's time zone, with an IANA name such as "Europe/Berlin" or "Asia/Tokyo". Together they let you test the page a visitor from another country sees, from your own machine:

    context = browser.new_context(locale="ja-JP", timezone_id="Asia/Tokyo")

    Permissions are what a browser normally asks the user about: location, notifications, the clipboard. A test cannot click "Allow" in a browser prompt, so grant the permission up front. geolocation is the position the Geolocation API then reports:

    context = browser.new_context(
    geolocation={"latitude": 48.8584, "longitude": 2.2945},
    permissions=["geolocation"],
)
context.set_geolocation({"latitude": 51.5007, "longitude": -0.1246})  # move, later
context.grant_permissions(["clipboard-read"])                          # grant more, later
context.clear_permissions()                                            # back to "ask"

    A position without the permission is useless: the page asks, nobody answers. Grants apply to every origin the context visits; pass origin="https://example.com" to grant to one only.

    Cookies, headers and init scripts¶

    You can read and change a context's cookies directly:

    context.add_cookies([{"name": "theme", "value": "dark", "url": BASE_URL}])
print(context.cookies())          # [{'name': 'theme', 'value': 'dark', 'domain': '127.0.0.1', ...}]
context.clear_cookies()           # all of them; or clear_cookies(name="theme")

    A cookie needs a name, a value, and either a url or a domain (with an optional path). Adding cookies before the first page loads is a quick way to set a preference or a consent banner's "already answered" flag.

    Two more tools change every page of a context:

    context.set_extra_http_headers({"X-Test-Run": "lesson-06"})       # sent with every request
context.add_init_script("localStorage.setItem('user', 'grace')")  # runs before the page's own scripts

    An init script runs in every new document, before any script of the page itself. Use it to seed storage, stub a browser API, or switch on a test mode the page checks for. page has the same two methods, for one page only.

    Log in once¶

    Signing in through the form at the start of every test is slow, and it tests the login page a hundred times instead of once. The better pattern: sign in once, save the session, and start every later context from it.

    A site remembers you in cookies and in localStorage. context.storage_state() returns both, and with path= also writes them to a JSON file. new_context(storage_state=...) takes the file (or the dict) and starts a context with that state already in place:

    state = context.storage_state(path=state_file)     # after signing in
signed_in = browser.new_context(storage_state=state_file)

    The file uses Playwright's storage-state format, so files move between the two tools. localStorage is read from the origins of the pages open at the moment you call storage_state(), so call it while the signed-in page is still open.

    Keep the state file private

    The file holds a live session cookie: anyone with the file is signed in as that user. Write it to a temporary or gitignored folder, never into the repository.

    Worked example¶

    This script signs Ada in on the practice login page, saves the storage state to a file in a temporary folder, and closes that context. Then it opens a new context from the file: the Who am I page shows Ada as the stored user with her session cookie, and the login page greets her as a returning user. A third context without the file is a stranger.

    """Lesson 06: log in once, save the storage state, and start a second context already signed in.

Signs in on the practice site in one context, saves its cookies and localStorage with
``context.storage_state()``, then opens a fresh context from that file and shows the page
already knows the user.

    python examples/course/serve.py                                          # terminal 1
    python examples/course/06-contexts-and-emulation/example_log_in_once.py  # terminal 2

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from pathlib import Path

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    # The state file holds a live session: keep it out of the repository.
    with tempfile.TemporaryDirectory() as folder, launch(BROWSER, headless=HEADLESS) as browser:
        state_file = Path(folder) / "state.json"

        # 1. Sign in once, in a context of its own, and save what the site stored.
        context = browser.new_context()
        page = context.new_page()
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Welcome, ada")
        state = context.storage_state(path=state_file)
        context.close()
        print(f"Saved {len(state['cookies'])} cookie(s) and localStorage for "
              f"{len(state['origins'])} origin(s)")

        # 2. Any later context can start from the file, already signed in.
        signed_in = browser.new_context(storage_state=state_file)
        page = signed_in.new_page()
        page.goto(BASE_URL + "whoami.html")
        expect(page.get_by_test_id("user")).to_have_text("ada")
        expect(page.get_by_test_id("cookies")).to_have_text("session=ada")
        page.goto(BASE_URL + "login.html")
        expect(page.get_by_test_id("returning")).to_have_text("Welcome back, ada. You are already signed in.")
        print("The new context is signed in as", page.evaluate("() => localStorage.getItem('user')"))

        # 3. A context without the state is a stranger.
        guest = browser.new_context()
        page = guest.new_page()
        page.goto(BASE_URL + "whoami.html")
        expect(page.get_by_test_id("user")).to_have_text("nobody")
        print("A fresh context is signed in as nobody")


if __name__ == "__main__":
    main()

    Run it with the practice site running:

    python examples/course/06-contexts-and-emulation/example_log_in_once.py

    Saved 1 cookie(s) and localStorage for 1 origin(s)
The new context is signed in as ada
A fresh context is signed in as nobody

    In a test suite you would sign in once per run (in a session fixture, lesson 09), keep the file for the rest of the run, and pass storage_state= to every test's context. When the session expires, delete the file and the next run signs in again.

    Async version

    The same three steps with the async API; only the awaits differ:

    context = await browser.new_context()
page = await context.new_page()
# ... sign in ...
await context.storage_state(path=state_file)
await context.close()
signed_in = await browser.new_context(storage_state=state_file)

    A second example puts several options together: a Pixel 7 in Tokyo, in Japanese, with a dark theme. On Firefox it uses desktop_only, as the note above explains.

    """Lesson 06: emulate a phone with a locale, a time zone and a dark color scheme.

Opens the "Who am I" page in a context built from the Pixel 7 device preset, set to
Japanese in Tokyo with a dark theme, and prints what the page sees.

    python examples/course/06-contexts-and-emulation/example_emulation.py

Firefox cannot emulate a phone's mobile viewport or touch screen, so on Firefox the
script drops those two settings with ``desktop_only`` and keeps the rest.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.api.devices import desktop_only
from steero.sync_api import devices, expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        phone = devices["Pixel 7"]
        if browser.name == "firefox":
            phone = desktop_only(phone)  # no is_mobile or has_touch on Firefox

        context = browser.new_context(**phone, locale="ja-JP", timezone_id="Asia/Tokyo", color_scheme="dark")
        page = context.new_page()
        page.goto(BASE_URL + "whoami.html")

        expect(page.get_by_test_id("locale")).to_have_text("ja-JP")
        expect(page.get_by_test_id("timezone")).to_have_text("Asia/Tokyo")
        expect(page.get_by_test_id("scheme")).to_have_text("dark")
        # The page shows a menu button instead of links below 600 pixels wide.
        expect(page.get_by_role("button", name="Menu")).to_be_visible()

        for field in ("viewport", "dpr", "touch", "date"):
            print(f"{field:>8}:", page.get_by_test_id(field).text_content())

        # Resize the running page: wide enough for the desktop links again.
        page.set_viewport_size({"width": 1024, "height": 768})
        expect(page.get_by_role("button", name="Menu")).to_be_hidden()
        print("At 1024 pixels wide the menu button is hidden")
        context.close()


if __name__ == "__main__":
    main()

    viewport: 412 x 839
     dpr: 2.625
   touch: 5
    date: 2026年11月7日土曜日 21:00
At 1024 pixels wide the menu button is hidden

    On Firefox, touch prints 0, because has_touch was dropped. The date is the same moment in every run (12:00 UTC on 7 November 2026), so the only thing that changes it is the context's locale and time zone: 21:00 in Tokyo.

    """Lesson 06, exercise 1: the same moment, formatted for a German user in Berlin.

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")

    Exercise 3: cookies stay home¶

    Create two contexts. Add a cookie theme=dark to the first only, open whoami.html in both, and check that the first page sees the cookie and the second does not. Then clear the first context's cookies and check that it sees none either.

    Solution 
    """Lesson 06, exercise 3: a cookie added to one context is invisible to another.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        first = browser.new_context()
        second = browser.new_context()
        # "url" sets the domain and path from an address; "domain" and "path" work too.
        first.add_cookies([{"name": "theme", "value": "dark", "url": BASE_URL}])

        first_page = first.new_page()
        second_page = second.new_page()
        first_page.goto(BASE_URL + "whoami.html")
        second_page.goto(BASE_URL + "whoami.html")

        expect(first_page.get_by_test_id("cookies")).to_have_text("theme=dark")
        expect(second_page.get_by_test_id("cookies")).to_have_text("none")
        assert [c["name"] for c in first.cookies()] == ["theme"]
        assert second.cookies() == []
        print("First context has theme=dark, the second has no cookies")

        first.clear_cookies()
        first_page.reload()
        expect(first_page.get_by_test_id("cookies")).to_have_text("none")
        print("After clear_cookies() the first context has none either")


if __name__ == "__main__":
    main()

    The page reads document.cookie when it loads, so after clear_cookies() the solution reloads it before checking again.

    Exercise 4: where am I?¶

    Start a context at the Eiffel Tower (latitude 48.8584, longitude 2.2945) with the geolocation permission. Click Show my location and assert the coordinates. Then move the context to Big Ben (51.5007, -0.1246) and check again.

    Solution 
    """Lesson 06, exercise 4: set a geolocation, read it back, then move.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

EIFFEL_TOWER = {"latitude": 48.8584, "longitude": 2.2945}
BIG_BEN = {"latitude": 51.5007, "longitude": -0.1246}


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        # Without the permission the page is never told where it is.
        context = browser.new_context(geolocation=EIFFEL_TOWER, permissions=["geolocation"])
        page = context.new_page()
        page.goto(BASE_URL + "whoami.html")
        locate = page.get_by_role("button", name="Show my location")
        location = page.get_by_test_id("location")

        locate.click()
        expect(location).to_have_text("48.8584, 2.2945")
        print("In Paris:", location.text_content())

        context.set_geolocation(BIG_BEN)
        locate.click()
        expect(location).to_have_text("51.5007, -0.1246")
        print("In London:", location.text_content())


if __name__ == "__main__":
    main()

    set_geolocation changes the position of a running context; the page sees it the next time it asks.

    Common mistakes¶

    Common mistakes

    • Using browser.new_page() and expecting a clean session. Pages without options share the default context, so cookies from one test leak into the next. Create a context per test (or per user) with browser.new_context().
    • Passing a phone preset on Firefox. It raises UnsupportedOnBrowser: is_mobile is not supported on firefox. Wrap the preset in desktop_only(...) when browser.name is "firefox".
    • Setting geolocation without permissions=["geolocation"]. The page asks for the position and is never answered: Chrome refuses it ("User denied Geolocation") and Firefox keeps waiting for a prompt nobody sees. Grant the permission too.
    • Calling storage_state() after closing the page. localStorage is read from the pages that are open, so the file has the cookies but no origins. Save the state while the signed-in page is still open.
    • Committing state.json. It is a working session. Write it to a temporary or gitignored folder.
    • Adding a cookie with only a name and a value. add_cookies raises ValueError: cookie 'theme' needs 'domain' or 'url'. Give it the site's url.

    Recap¶

    • A context is an isolated session (cookies, storage, cache, permissions) inside one browser: cheap to create, so use one per test or per user.
    • browser.new_context(...) takes the emulation options: viewport, locale, time zone, color scheme, geolocation, permissions, user agent; devices[...] fills in a whole device.
    • Firefox lacks is_mobile, has_touch, java_script_enabled=False, reduced_motion and forced_colors; steero raises UnsupportedOnBrowser rather than ignoring them.
    • add_cookies, cookies, clear_cookies, set_extra_http_headers and add_init_script shape what every page of a context starts with.
    • Log in once: context.storage_state(path=...), then new_context(storage_state=...).
