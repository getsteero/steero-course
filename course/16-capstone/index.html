    16. Capstone: a ControlLab suite¶

    In this lesson

    You will learn to:

    • plan a test suite for a real application: journeys, page objects and test data
    • write tests with the pytest plugin against ControlLab, using everything from the course
    • sign in once per session, use storage state, mock one request, and add a visual check
    • run the suite in Chrome and Firefox with traces kept on failure
    • build a small local gate script that runs it all and fails clearly

    Time: about 90 minutes. Before this: 15. Migrating from Playwright. Code: examples/course/16-capstone/

    Every lesson so far drove a small page built for that lesson. Real applications are bigger, change under you, and need a suite someone else can read and run. This lesson builds one: about ten tests against ControlLab, a single-page app with menus, a data grid, forms and dialogs, with the structure, fixtures and gate a team would keep.

    The application¶

    ControlLab is a demo app that ships with steero's own test suite. The practice server serves it at /controllab/v1/, so with python examples/course/serve.py running, open http://127.0.0.1:8765/controllab/v1/index.html and sign in as admin / Admin@123 (or viewer / Viewer@123, a read-only user).

    Take ten minutes to click around before writing anything:

    • Sign in (#/login): validation, a lockout after three wrong passwords, "Remember me", a "Forgot password?" dialog.
    • The shell: a menubar (Controls and Widgets open on hover, Data and Planner on click), side navigation, breadcrumbs, an account menu (Profile, Logout), toasts in the corner.
    • Data > Data Grid (#/grid): 200 employees, paging, sorting, a quick filter.
    • Widgets > Rich content: media, a chart, and images that load only when scrolled near.
    • Account: a profile form with a display name and an avatar showing its initials.

    It is a hash-routed single-page app: every page is index.html#/<route>, and moving between pages changes the hash without reloading. Two details matter for testing. Its data is generated from a fixed seed, so every run sees the same 200 employees. And it keeps the signed-in session in sessionStorage, which you will meet again below.

    /controllab/v2/ and /controllab/v3/ are the same app with catalogued markup changes (renamed ids, relabelled buttons, moved columns), made to test self-healing (lesson 12).

    Planning the suite¶

    Start from journeys, what a user does, not from pages or functions. For ControlLab:

    Journey Tests Why it matters
    Sign in success, wrong password, empty fields, password reset nothing else works without it
    Get around the menus reach a page; logout closes the app navigation breaks quietly
    Find data the grid shows its first page; the quick filter narrows it the app's main job
    Come back later "Remember me" survives in saved storage state across sessions
    Survive the network a mocked image response is used the app copes with what the server sends
    Look right the sign-in card matches its baseline layout regressions no assertion catches

    Three rules keep such a suite readable:

    • One behaviour per test, named as a sentence: test_wrong_password_shows_attempts_left. The name is what you read in a failure report.
    • Assert what the user sees: the heading, the message, the URL, the row count. Not the internal state.
    • Each test starts from scratch: its own context, its own sign-in. A test that depends on the one before it fails for the wrong reason.

    The folder looks like this:

    examples/course/16-capstone/
    runner.py            builds the pytest command line, runs it in-process
    example_run_suite.py the worked example: record the baseline, run the suite
    suite/
        pytest.ini       markers and options; makes this folder pytest's rootdir
        conftest.py      fixtures
        pages.py         two page objects
        test_login.py  test_navigation.py  test_grid.py
        test_storage.py  test_network.py  test_visual.py
        exercises/       tests for the exercises (not collected by default)

    Page objects, lightly¶

    A page object is a class that names the locators of one screen and the few actions a user takes there. It saves repeating page.get_by_label("Password", exact=True) in ten tests, and when the form changes, one file changes.

    """Lesson 16: two light page objects for ControlLab, the sign-in page and the app shell.

A page object here only names locators and a few actions a user takes. Assertions stay in the
tests, so a failing test still reads as a list of what the user saw.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

from __future__ import annotations

from steero.sync_api import Healer, Locator, Page, expect


class LoginPage:
    """The sign-in form at ``#/login``.

    Args:
        page: The page to drive.
        healer: When given, the submit button heals under the key ``login.submit`` if its
            markup changes (lesson 12).
    """

    def __init__(self, page: Page, healer: Healer | None = None):
        self.page = page
        self.username = page.get_by_label("Username")
        self.password = page.get_by_label("Password", exact=True)  # not the "Show password" button
        self.remember = page.get_by_label("Remember me")
        submit = page.get_by_role("button", name="Login", exact=True)
        self.submit = healer.locator("login.submit", submit) if healer else submit
        self.error = page.get_by_test_id("login-error")

    def open(self) -> None:
        """Load the app at the sign-in route."""
        self.page.goto("index.html#/login")
        expect(self.username).to_be_visible()

    def sign_in(self, user: str, password: str, *, remember: bool = False) -> None:
        """Fill in the form and submit it."""
        self.username.fill(user)
        self.password.fill(password)
        if remember:
            self.remember.check()
        self.submit.click()


class Shell:
    """Everything around a signed-in page: heading, menus, account menu, toasts."""

    def __init__(self, page: Page):
        self.page = page
        self.heading = page.get_by_role("heading", level=1)
        self.account_menu = page.get_by_role("button", name="Account menu")

    def navigate(self, menu: str, item: str) -> None:
        """Open a top-level menu and choose an item, as a user would."""
        self.page.get_by_role("menubar").get_by_role("menuitem", name=menu, exact=True).click()
        self.page.get_by_role("menu", name=menu).get_by_role("menuitem", name=item, exact=True).click()

    def logout(self) -> None:
        """Log out through the account menu."""
        self.account_menu.click()
        self.page.get_by_role("menuitem", name="Logout").click()

    def toast(self, text: str) -> Locator:
        """The notification that contains ``text``."""
        return self.page.get_by_test_id("toast").filter(has_text=text)

    Keep them light. These hold locators and actions, but no assertions: a test that reads login.sign_in("admin", "nope") then expect(login.error).to_have_text(...) still tells you what was checked. A page object that grows methods like verify_login_failed() hides the check, and a suite of them reads like a list of function names. Make one only for screens that several tests use; a one-off page is clearer inline.

    Two details in LoginPage. get_by_label("Password", exact=True) matters because the "Show password" button's label also contains "password". And the submit button goes through a healer when the test has one, under the stable key login.submit (lesson 12), which pays off in exercise 3.

    Coming from Selenium

    Selenium page objects often wrap every element in a method and wait explicitly in each one. Here a locator is the element description, and every action and expect waits by itself, so a page object is mostly a list of attributes.

    Fixtures for the suite¶

    The suite uses steero's pytest plugin (lesson 09): steero_page gives each test a fresh page in its own context, steero_browser is one browser for the session, and the plugin reads --steero-base-url, so page.goto("index.html#/login") resolves against the ControlLab folder. conftest.py builds the suite's own fixtures on top:

    """Lesson 16: fixtures for the ControlLab suite, built on steero's pytest plugin.

* ``page``: steero's ``steero_page`` with a desktop viewport. Relative URLs resolve against
  ``--steero-base-url`` (the ControlLab folder, ending in ``/``).
* ``login``: the sign-in page object, its submit button guarded by ``steero_healer``.
* ``admin_session``: signs in once per session and keeps the session ControlLab stored.
* ``signed_in``: a page that starts signed in, by giving the new context that session.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

from __future__ import annotations

import json
import re

import pytest
from pages import LoginPage, Shell

from steero.heal import FingerprintStore
from steero.sync_api import Browser, BrowserContext, Healer, Page, expect, healer

ADMIN = ("admin", "Admin@123")


@pytest.fixture(scope="session")
def app_url(pytestconfig: pytest.Config) -> str:
    """The ControlLab folder the suite runs against, from ``--steero-base-url``."""
    url = pytestconfig.getoption("steero_base_url")
    if not url:
        raise pytest.UsageError("pass --steero-base-url http://127.0.0.1:8765/controllab/v1/")
    return str(url)


@pytest.fixture
def page(steero_page: Page) -> Page:
    """A fresh page in its own context, sized like a laptop screen."""
    steero_page.set_viewport_size({"width": 1366, "height": 900})
    return steero_page


@pytest.fixture
def login(page: Page, steero_healer: Healer) -> LoginPage:
    """The sign-in page, already open."""
    login_page = LoginPage(page, steero_healer)
    login_page.open()
    return login_page


@pytest.fixture(scope="session")
def admin_session(steero_browser: Browser, steero_store: FingerprintStore, app_url: str) -> str:
    """Sign in through the form once, and return the session ControlLab saved.

    ControlLab keeps its session in ``sessionStorage``, which ``storage_state`` does not
    capture, so the value is read directly and handed to each test's context below.
    """
    context = steero_browser.new_context(base_url=app_url)
    try:
        page = context.new_page()
        form = LoginPage(page, healer(page, steero_store))
        form.open()
        form.sign_in(*ADMIN)
        expect(page).to_have_url(re.compile(r"#/home$"))
        session = page.evaluate("sessionStorage.getItem('cl.session')")
    finally:
        context.close()
    assert session, "signing in stored no session"
    return str(session)


@pytest.fixture
def signed_in(page: Page, steero_context: BrowserContext, admin_session: str) -> Shell:
    """A page on Home, signed in as admin without going through the form again."""
    steero_context.add_init_script(
        "try { if (!sessionStorage.getItem('cl.session'))"
        f" sessionStorage.setItem('cl.session', {json.dumps(admin_session)}); }} catch (e) {{}}")
    page.goto("index.html#/home")
    shell = Shell(page)
    expect(shell.heading).to_have_text("Home")
    return shell
    • page is steero_page with a laptop-sized viewport, so the menubar is shown (narrow windows get a drawer instead).
    • login opens the sign-in page and hands back the page object.
    • admin_session is session-scoped: it signs in through the form once for the whole run and keeps what ControlLab stored.
    • signed_in gives a test's context that session before the page loads, and lands on Home. Ten tests that need a signed-in user do not each type a password.

    Why not storage_state here? context.storage_state() saves cookies and localStorage, the way Playwright does. ControlLab keeps its session in sessionStorage, which belongs to one tab and is not part of storage state. So the fixture reads the value once and writes it back with context.add_init_script(), which runs before the app's own scripts on every page of the context. Check where your own application keeps its session before choosing: for a cookie or localStorage session, new_context(storage_state="state.json") is all you need, and test_storage.py shows it with ControlLab's "Remember me", which does live in localStorage.

    Writing the tests¶

    The sign-in tests use the page object and assert what appears:

    """Lesson 16: the sign-in journey, through the form a user sees.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

from __future__ import annotations

import re

from pages import LoginPage, Shell

from steero.sync_api import Page, expect


def test_admin_signs_in_and_lands_on_home(page: Page, login: LoginPage) -> None:
    login.sign_in("admin", "Admin@123")
    expect(page).to_have_url(re.compile(r"#/home$"))
    expect(Shell(page).heading).to_have_text("Home")
    expect(page.get_by_text("Welcome back")).to_contain_text("Alex Admin")


def test_wrong_password_shows_attempts_left(page: Page, login: LoginPage) -> None:
    login.sign_in("admin", "nope")
    expect(login.error).to_have_text("Invalid username or password (2 attempts left)")
    expect(page).to_have_url(re.compile(r"#/login$"))


def test_empty_fields_show_inline_errors(page: Page, login: LoginPage) -> None:
    login.submit.click()
    expect(page.get_by_text("Username is required")).to_be_visible()
    expect(page.get_by_text("Password is required")).to_be_visible()


def test_forgot_password_sends_a_reset_link(page: Page, login: LoginPage) -> None:
    page.get_by_role("link", name="Forgot password?").click()
    dialog = page.get_by_role("dialog", name="Reset your password")
    dialog.get_by_label("Email address").fill("not-an-email")
    dialog.get_by_role("button", name="Send link").click()
    expect(dialog.get_by_text("Enter a valid email address")).to_be_visible()

    dialog.get_by_label("Email address").fill("ada@example.com")
    dialog.get_by_role("button", name="Send link").click()
    expect(dialog).to_be_hidden()
    expect(Shell(page).toast("Reset link sent to ada@example.com")).to_be_visible()

    The password reset test is the suite's form: it fills the dialog wrong, checks the inline error, fills it right, and checks that the dialog closed and a toast confirmed it. Scoping the locators to page.get_by_role("dialog", name="Reset your password") keeps them from matching anything behind the dialog.

from __future__ import annotations

import re

from pages import Shell

from steero.sync_api import expect


def test_menus_reach_the_data_grid(signed_in: Shell) -> None:

    The grid tests read a column by its header, not by a fixed position. ControlLab v2 moves the Department column, and a test that counted columns would then read the wrong one:

    """Lesson 16: the data grid, its paging status and the quick filter.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

from __future__ import annotations

import pytest
from pages import Shell

from steero.sync_api import Locator, Page, expect


def department_cells(page: Page) -> Locator:
    """The Department cell of every row on the current grid page, found by its column header."""
    grid = page.get_by_role("grid", name="Employees")
    headers = [text.strip() for text in grid.get_by_role("columnheader").all_inner_texts()]
    column = headers.index("Department") + 1  # read the position each time: columns can move
    return grid.locator(f"tbody tr td:nth-child({column})")


@pytest.fixture
def grid(signed_in: Shell) -> Page:
    """The Data Grid page, reached through the menus."""
    signed_in.navigate("Data", "Data Grid")
    expect(signed_in.page.get_by_test_id("grid-status")).to_contain_text("Showing")
    return signed_in.page


def test_grid_shows_the_first_page_of_200_employees(grid: Page) -> None:
    expect(grid.get_by_test_id("grid-status")).to_have_text("Showing 1 to 25 of 200")
    expect(department_cells(grid)).to_have_count(25)


def test_quick_filter_narrows_to_one_department(grid: Page) -> None:
    grid.get_by_label("Quick filter").fill("Engineering")
    expect(grid.get_by_test_id("grid-status")).not_to_have_text("Showing 1 to 25 of 200")
    departments = {text.strip() for text in department_cells(grid).all_inner_texts()}
    assert departments == {"Engineering"}, departments

    Storage state, with a second context made from the saved file:

    """Lesson 16: "Remember me" survives in a saved storage state.

ControlLab stores the remembered user name in ``localStorage``, which ``storage_state``
captures. A new context started from that state opens the form with the name filled in.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

from __future__ import annotations

import re
from pathlib import Path

from pages import LoginPage

from steero.sync_api import Browser, BrowserContext, Page, expect


def test_remember_me_survives_in_storage_state(page: Page, login: LoginPage, steero_context: BrowserContext,
                                               steero_browser: Browser, app_url: str, tmp_path: Path) -> None:
    login.sign_in("viewer", "Viewer@123", remember=True)
    expect(page).to_have_url(re.compile(r"#/home$"))
    state = tmp_path / "state.json"
    steero_context.storage_state(path=state)

    later = steero_browser.new_context(storage_state=str(state), base_url=app_url)
    try:
        again = LoginPage(later.new_page())
        again.open()
        expect(again.username).to_have_value("viewer")
        expect(again.remember).to_be_checked()
    finally:
        later.close()

    One mocked request. ControlLab has no server API: everything it loads is a file. Its lazy-loaded images are the requests whose result a user can see, so the test answers the first one itself, with a small SVG, and checks that the page used it (the real picture is 320 pixels wide, the mock 64):

    """Lesson 16: one mocked request. The first lazy-loaded image is answered by the test itself.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (sync route handlers get a sync Route now)
"""

from __future__ import annotations

import re

from pages import Shell

from steero.sync_api import expect

PICTURE = ('<svg xmlns="http://www.w3.org/2000/svg" width="64" height="36">'
           '<rect width="64" height="36" fill="teal"/></svg>')


def test_a_mocked_image_counts_as_loaded(signed_in: Shell) -> None:
    page = signed_in.page
    # One call, so a lambda; a handler with several steps would be an ordinary def.
    page.route("**/assets/lazy-1.svg", lambda route: route.fulfill(body=PICTURE, content_type="image/svg+xml"))
    signed_in.navigate("Widgets", "Rich content")
    for image in page.get_by_role("img", name=re.compile(r"^Lazy image")).all():
        image.scroll_into_view_if_needed()  # they load only near the viewport, 400 px apart

    expect(page.get_by_test_id("lazy-status")).to_have_text("Loaded 3 of 3")
    width = page.get_by_role("img", name="Lazy image A").evaluate("img => img.naturalWidth")
    assert width == 64, f"the page shows the real picture, not the mock (width {width})"

    One visual check, of the sign-in card only (the Home page shows the time of day, which would never match). It is marked visual, so it can be run, or left out, on its own:

Baselines are per browser and platform (``login-card-chrome-win32.png``); where they live is

from __future__ import annotations

import pytest
from pages import LoginPage

from steero.sync_api import Page, expect


@pytest.mark.visual
def test_login_card_looks_unchanged(page: Page, login: LoginPage) -> None:
    card = page.locator(".login-card")
    expect(card).to_have_screenshot("login-card.png", max_diff_pixel_ratio=0.01)

    Baselines are per browser and platform (login-card-chrome-win32.png), as lesson 05 explained. In a project you commit them; the course scripts record them in a temporary folder first, through STEERO_SNAPSHOT_DIR and STEERO_UPDATE_SNAPSHOTS=1, so they never write into the repository.

    Browser support

    Every test runs in Chrome (both backends), Edge and Firefox without a browser check. The one browser difference that showed up while writing them was lazy loading: Firefox loads a lazy image only when it is close to the viewport, so the network test scrolls each image into view rather than just the section heading.

    Running it well¶

    runner.py builds the command line in one place, so every script runs the suite the same way:

    """Lesson 16: build the pytest command line for the capstone suite, and run it in this process.

Imported by the lesson's scripts; not an example on its own. Every output (per-test traces,
failure artifacts, heal baselines and reports, screenshot baselines) goes under one folder
the caller chooses, never into the repository.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

from __future__ import annotations

import os
import sys
from collections.abc import Sequence
from pathlib import Path

import pytest

SUITE = Path(__file__).resolve().parent / "suite"


def suite_args(output: Path, *, browsers: Sequence[str], base_url: str, version: str = "v1",
               targets: Sequence[str] = (), extra: Sequence[str] = (), headed: bool = False) -> list[str]:
    """The pytest arguments for one run of the suite.

    Args:
        output: Folder for everything the run writes.
        browsers: Browsers to run every test in (``chrome``, ``firefox``, ``edge``).
        base_url: The practice site's address, ending in ``/``.
        version: ControlLab version to test: ``v1``, ``v2`` or ``v3``.
        targets: Test files or node ids; the whole suite when empty.
        extra: More pytest arguments, such as ``-m visual`` or ``--steero-strict-heal``.
        headed: Show the browser windows.
    """
    args = [*(targets or [str(SUITE)]), "-q",
            "--steero-base-url", f"{base_url}controllab/{version}/",
            "--steero-output", str(output / "test-results"),
            "--steero-tracing", "retain-on-failure",
            "--steero-artifacts", str(output / "steero-artifacts"),
            "--steero-baselines", str(output / "heal-baselines")]
    for browser in browsers:
        args += ["--steero-browser", browser]
    if headed:
        args.append("--steero-headed")
    return [*args, *extra]


def run(args: Sequence[str], *, snapshots: Path, update_snapshots: bool = False) -> int:
    """Run pytest in this process with screenshot baselines in ``snapshots``; return its exit code."""
    sys.dont_write_bytecode = True  # keep __pycache__ out of the examples folder
    os.environ["STEERO_SNAPSHOT_DIR"] = str(snapshots)
    if update_snapshots:
        os.environ["STEERO_UPDATE_SNAPSHOTS"] = "1"
    try:
        return int(pytest.main(list(args)))
    finally:
        os.environ.pop("STEERO_UPDATE_SNAPSHOTS", None)


def traces(output: Path) -> list[Path]:
    """The traces kept for failed tests (``--steero-tracing retain-on-failure``)."""
    return sorted((output / "test-results").glob("*/trace.zip"))

    The options worth knowing:

    Option Effect
    --steero-browser chrome --steero-browser firefox every test runs once per browser (the test id ends in [chrome] or [firefox])
    --steero-base-url URL relative goto() URLs resolve against it
    --steero-tracing retain-on-failure record a trace of every test, keep it only for failures (steero show-trace, lesson 10)
    --steero-output DIR per-test folders for traces, screenshots and video
    --steero-artifacts DIR failure screenshot, HTML and console output; the heal report
    --steero-baselines DIR the self-healing fingerprints
    --steero-strict-heal a test that needed healing fails, so a heal is fixed rather than forgotten
    -m visual, -m "not visual" only, or all but, the visual check

    The --steero- spellings always work; the plain --browser, --tracing and so on also work when pytest-playwright is not installed (lesson 15). From a terminal, the same run is:

    pytest examples/course/16-capstone/suite --steero-browser firefox --steero-base-url http://127.0.0.1:8765/controllab/v1/ --steero-tracing retain-on-failure

    Worked example¶

    example_run_suite.py runs the suite in the course browser, in two pytest runs: first it records the visual baseline, then it runs everything and exits non-zero if any test failed.

    """Lesson 16: run the capstone suite against ControlLab v1 in the course browser.

Two pytest runs, as a real project does them. First the visual baseline is recorded (a
project commits it; here it goes to a temporary folder), then the whole suite runs with

    Exercise 4: a gate¶

    Write one script a developer runs before pushing: it runs the whole suite in every installed browser (skipping any that is missing), records the visual baselines first, uses --steero-strict-heal, keeps traces on failure, exits non-zero on any failure, and prints where the traces are.

    Solution 
    """Lesson 16, exercise 4: a local gate that runs the whole suite in every installed browser.

One command a developer runs before pushing. It records the visual baselines, runs every
test in Chrome and Firefox (whichever are installed) with ``--steero-strict-heal``, so a test
that only passed thanks to healing fails the gate, and keeps a trace for every failure. It
exits non-zero on any failure and prints where the traces are.

    python examples/course/16-capstone/solution_4_gate.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

# course: browsers=chrome
# course: timeout=400

import os
import tempfile
from pathlib import Path

from runner import run, suite_args, traces

from steero import LaunchError
from steero.launch.discover import find_browser

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def installed(names: list[str]) -> list[str]:
    """The browsers from ``names`` that steero can find on this machine."""
    found = []
    for name in names:
        try:
            find_browser(name)
        except LaunchError:
            print(f"gate: {name} is not installed, skipped")
        else:
            found.append(name)
    return found


def main() -> None:
    browsers = installed(["chrome", "firefox"])
    if not browsers:
        raise SystemExit("gate: no browser to run in")
    output = Path(tempfile.mkdtemp(prefix="capstone-gate-"))
    snapshots = output / "snapshots"
    common = {"browsers": browsers, "base_url": BASE_URL, "headed": not HEADLESS}

    steps = [("visual baselines", suite_args(output, **common, extra=["-m", "visual"]), True),
             ("suite", suite_args(output, **common, extra=["--steero-strict-heal"]), False)]
    for title, args, update in steps:
        print(f"gate: {title} in {', '.join(browsers)}")
        code = run(args, snapshots=snapshots, update_snapshots=update)
        if code != 0:
            print(f"gate: FAILED at {title} (pytest exit {code})")
            for trace in traces(output):
                print(f"  trace: {trace}   open it with: steero show-trace \"{trace}\"")
            print(f"  failure artifacts: {output / 'steero-artifacts'}")
            raise SystemExit(1)
    print(f"gate: passed in {', '.join(browsers)}; outputs in {output}")


if __name__ == "__main__":
    main()

    Common mistakes¶

    Common mistakes

    • Tests that depend on each other. The second test passes only after the first signed in. Each test gets its own context; build what it needs with fixtures, never with test order.
    • Expecting storage_state to keep a sessionStorage session. It saves cookies and localStorage only, so the "signed-in" context lands on the sign-in page. Find where the app keeps its session; seed sessionStorage with add_init_script, as conftest.py does.
    • An async def route handler in this sync suite. It is given the async Route and must await route.fulfill(...); a forgotten await leaves the request to the real server (RuntimeWarning: coroutine 'Route.fulfill' was never awaited). In sync code write the handler as a lambda or an ordinary def: it gets a sync Route and runs on a worker thread, so it can make as many calls as it needs.
    • Reading grid cells by a fixed column number. It breaks the day a column moves. Find the column from its header, as test_grid.py does.
    • A visual check of a page with the time on it. It never matches. Check a stable element, or mask= the moving parts.
    • no baseline existed; wrote ... on the first run. That is deliberate: a missing baseline never passes silently. Look at the file, then run again (or record with STEERO_UPDATE_SNAPSHOTS=1).
    • Leaving outputs in the repository. Point --steero-output, --steero-artifacts, --steero-baselines and STEERO_SNAPSHOT_DIR at a folder you mean (the scripts use a temporary one), and keep -p no:cacheprovider or ignore .pytest_cache.

    Recap¶

    • Plan by journeys; one behaviour per test, named as a sentence, asserting what the user sees.
    • Keep page objects light: locators and actions, assertions in the tests.
    • Session-scoped fixtures do expensive setup once; each test still gets a fresh context.
    • --steero-browser twice, --steero-tracing retain-on-failure and --steero-strict-heal make a suite that runs everywhere, explains its failures and does not hide changes.
    • A small gate script that exits non-zero is the whole release check.
