    10. Debugging¶

    In this lesson

    You will learn to:

    • run headed to watch a script work, and outline elements with locator.highlight()
    • stop a run with page.pause() and look around
    • record a trace with context.tracing and open it with steero show-trace
    • export a trace as one HTML file to attach to a bug report
    • record a video of a page and save it
    • read steero's errors (timeouts, strictness, failed assertions) and find the cause quickly

    Time: about 40 minutes. Before this: 09. The pytest plugin. Code: examples/course/10-debugging/

    Sooner or later a script fails and the reason is not obvious: it worked yesterday, or it works on your machine and not on the build server. This lesson gives you four tools, from the quickest to the most thorough: watch the run, stop it and look, record a trace you can replay step by step, and record a video. It ends with how to read the error message, which is where you should always start.

    Watch it run¶

    The first thing to try is to see what the browser sees. Launch headed:

    with launch("chrome", headless=False) as browser:
    ...

    For the course examples, set STEERO_COURSE_HEADED=1 (lesson 01); for a pytest suite, pass --headed or --steero-headed (lesson 09).

    A headed script runs at full speed, which is often too fast to follow. Two helpers make it easier to see where it is:

    fields = page.get_by_role("textbox")
fields.highlight(seconds=3)  # outline every element the locator matches, for 3 seconds

    highlight() draws an outline around every element the locator matches right now, and returns at once. The outline never intercepts clicks, so the script carries on underneath it. It is the fastest way to answer "what does this locator actually find?": if the outline is on the wrong element, or on two elements, you know where the problem is.

    Slow motion¶

    To follow a headed run by eye, launch with slow_mo: steero waits that many seconds before every action (goto, click, fill, press ...).

    with launch("chrome", headless=False, slow_mo=0.5) as browser:  # half a second per action
    ...

    With the pytest plugin, --slowmo 500 does the same (it takes milliseconds, as in pytest-playwright). Slow motion only helps you watch; to look closely at one moment, stop there with page.pause(), or record a trace and step through it afterwards.

    Coming from Playwright

    slow_mo is in seconds here, like every steero time: Playwright's slow_mo=50 is slow_mo=0.05.

    Pause¶

    page.pause() stops the script until you press Enter in the terminal. While it waits, the browser is yours: click around, open its developer tools (F12), inspect the element your locator should have found.

    page.get_by_label("User name").fill("ada")
page.pause()  # look at the form, then press Enter to carry on
page.get_by_role("button", name="Sign in").click()

    In a headless run there is no window to look at, so pause() logs a warning and returns at once instead of waiting for input that nobody can usefully give. That means a forgotten pause() can never hang a test run on a build server. You see the warning only if logging is switched on, for example with logging.basicConfig(level=logging.WARNING).

    Coming from Selenium

    The usual Selenium trick is a breakpoint or an input() in the test. page.pause() is the same idea, with the headless case handled for you.

    Tracing¶

    A trace is a recording of everything a browser context did, saved as one zip file: every action with its locator, timing and error; a screenshot before and after each action; a snapshot of the page's HTML after each action; console messages, page errors, navigations and network requests. You can open it after the run, on another machine, days later.

    Tracing belongs to a context. Start it before the actions you want, stop it with a path:

    context = browser.new_context()
context.tracing.start(screenshots=True, snapshots=True, sources=True)
page = context.new_page()
...                                   # everything here is recorded
context.tracing.stop(path="trace.zip")
    Option Default Adds
    screenshots True a picture after each action, and before it when the page changed
    snapshots True the page's HTML after each action, rendered without scripts
    sources False the line of your script that ran each action, and the script itself
    title, name none a title for the viewer, a short name stored in the trace

    stop() without a path throws the recording away. While tracing is off it costs nothing; while it is on, each action takes a few milliseconds longer.

    Chunks split one tracing session into several files, for example one per test:

    context.tracing.start()                       # opens the first chunk
...
context.tracing.stop_chunk(path="step-1.zip")  # saves it; tracing stays on
context.tracing.start_chunk()
...
context.tracing.stop_chunk(path="step-2.zip")
context.tracing.stop()

    You rarely need to write this yourself in a test suite: --tracing retain-on-failure makes the pytest plugin trace every test and keep trace.zip only for those that failed.

    The trace viewer¶

    Open a trace with the steero command:

    steero show-trace trace.zip

    serving trace.zip at http://127.0.0.1:54123/ (Ctrl+C to stop)

    It starts a small local server (on 127.0.0.1 only), opens the viewer in your web browser, and runs until you press Ctrl+C. Add --no-open to print the address without opening a browser, and --port 9323 to choose the port.

    The viewer is one page:

    • the action list down the side: each action with its locator and duration, and failed actions marked with their error;
    • a timeline filmstrip of screenshots across the top;
    • for the selected action, the before and after screenshots and the DOM snapshot, which is the page's real HTML at that moment: you can inspect it to see why a locator did or did not match;
    • tabs for the console, the network requests, page errors and the source line that ran the action.

    To attach a trace to a bug report, export it as a single HTML file that opens in any browser with no server and no steero install:

    steero show-trace --html bug-1234.html trace.zip

    wrote bug-1234.html

    A trace holds what the page held

    A trace contains screenshots, page HTML, console output and request headers. steero redacts text typed into password fields (and fields whose locator mentions a password, token or PIN), never writes password values into snapshots, and replaces Authorization, Cookie and Set-Cookie header values with <redacted>. Everything else is recorded as it was. Share a trace only where its contents may go.

    See the tracing guide for the file format and the full option list.

    Video¶

    A video is less detailed than a trace but easier to show someone. Ask for it when you create the context, then save it after the page is closed:

    context = browser.new_context(record_video_dir="videos", record_video_size={"width": 800, "height": 500})
page = context.new_page()
...
video = page.video          # None when the context was not recording
page.close()                # closing the page finishes the recording
print(video.path())
video.save_as("sign-in.webm")

    Every page of the context is recorded into record_video_dir. video.path() and save_as() wait until the recording is finished, so call them after page.close() (or after context.close()).

    Browser support

    The two browsers record video differently, and the file you get can differ:

    • Firefox records the page itself (a BiDi screencast) and writes a .webm.
    • Chrome has no screencast over BiDi yet, so steero collects a frame each time the page repaints (CDP Page.startScreencast; every page, the ones behind another tab too) and encodes them with ffmpeg when ffmpeg is on your PATH, giving a .webm. Without ffmpeg the video is saved as <id>.frames.zip, a set of frames that steero show-trace plays, and steero logs one warning.

    So a script that copies the video should keep the suffix it was given (video.path().suffixes) rather than assume .webm.

    Reading errors¶

    Before any of the tools above, read the error. steero's messages are written to tell you the cause, and they have a fixed shape: the action, the locator, how long it waited, and the last reason it could not go on.

    click get_by_role('button', name='Sign out'): timed out after 2 s: no element matches

    The reason at the end is the part to read:

    Error ends with It means Look at
    no element matches the locator found nothing the text, role or label in the locator against the page (highlight(), or the trace's DOM snapshot)
    element is not visible found, but hidden whether the page shows it yet; a menu or tab that must be opened first
    element is disabled found, but disabled what enables it: a field still empty, a request still running
    element is not stable (still moving) found, but animating an animation or a layout that keeps shifting
    element is covered by <div#overlay> something is on top a dialog, a cookie banner or a loading overlay
    matched 3 elements; use .first, .nth() or a more specific locator (a StrictModeViolation) the locator is ambiguous make it more specific (lesson 02)
    expected 'X', got 'Y' after 5 s (an AssertionError from expect) the page never reached the state Y is what it really showed: often the answer
    self-healing refused: ... a healing locator would not guess lesson 12

    Two habits help. Read the last value seen in a failed assertion: "got ''" means the thing never happened at all, "got 'Signing in...'" means it was still on its way. And notice which action failed: if a click times out with "no element matches" straight after a navigation, the page may simply be a different page than you think, which the trace will show you.

    Worked example¶

    This script signs in with tracing on, then tries to click a "Sign out" button that does not exist, so the trace holds a failed action after four that worked. It saves trace.zip and exports it with steero show-trace --html, running the command through python -m steero so it uses the same Python as the script. Both files go to a steero-course folder in your temporary directory.

    """Lesson 10: record a trace of a sign-in where one step fails, and export it as one HTML file.

Signs in with tracing on, then clicks a button that does not exist, so the trace holds a failed
action next to the ones that worked. The trace is saved as ``trace.zip`` and exported with
``steero show-trace --html`` to ``trace.html``, which opens in any browser with no server.

    python examples/course/10-debugging/example_trace_failure.py
    steero show-trace <the trace.zip path it prints>

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import subprocess
import sys
import tempfile
from pathlib import Path

from steero import SteeroTimeoutError
from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

OUT = Path(tempfile.gettempdir()) / "steero-course" / "10-debugging"


def main() -> None:
    OUT.mkdir(parents=True, exist_ok=True)
    trace = OUT / "trace.zip"
    with launch(BROWSER, headless=HEADLESS) as browser:
        context = browser.new_context()
        context.tracing.start(title="sign in, then a missing button", screenshots=True, snapshots=True,
                              sources=True)
        page = context.new_page()
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Welcome, ada")
        try:
            page.get_by_role("button", name="Sign out").click(timeout=2)  # there is no such button
        except SteeroTimeoutError as error:
            print("Failed as planned:", error)
        context.tracing.stop(path=trace)
        context.close()
    print("Trace:", trace)

    # The same as typing: steero show-trace --html trace.html trace.zip
    html = OUT / "trace.html"
    subprocess.run([sys.executable, "-m", "steero", "show-trace", "--html", str(html), str(trace)], check=True)
    print("Open this file in any browser:", html)


if __name__ == "__main__":
    main()

    A second example shows highlight() and pause(). Run it headed to see the outline and to have the script stop until you press Enter; headless, it prints the warning and finishes:

    """Lesson 10: outline an element with ``highlight()`` and stop the script with ``page.pause()``.

Headless (the default), ``pause()`` logs a warning and carries on, so the script finishes. Run it
headed to see the outline and to have the script wait for Enter in the terminal:

    python examples/course/10-debugging/example_highlight_and_pause.py
    STEERO_COURSE_HEADED=1 python examples/course/10-debugging/example_highlight_and_pause.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import logging
import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    logging.basicConfig(level=logging.WARNING)  # so pause()'s headless warning is printed
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")

        fields = page.get_by_role("textbox")
        print("Text boxes on the page:", fields.count())
        fields.highlight(seconds=3)  # outlines every match for 3 seconds; it never blocks a click

        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        page.pause()  # headed: waits for Enter. Headless: a warning, then on we go.

        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Welcome, ada")
        print("Signed in")


if __name__ == "__main__":
    main()

    Exercise 1: one trace per step¶

    Sign in with tracing on, but save the filling in and the submitting as two separate trace files, using chunks. Print how many actions each file holds and how big it is.

    Solution 
    """Lesson 10, exercise 1: one tracing session, one trace file per step, using chunks.

``start()`` opens the first chunk; ``stop_chunk(path)`` saves it and keeps tracing on, and
``start_chunk()`` opens the next. The script prints how many actions and bytes each file holds.

    python examples/course/10-debugging/solution_1_trace_chunks.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from pathlib import Path

import steero.tracing
from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

OUT = Path(tempfile.gettempdir()) / "steero-course" / "10-debugging" / "chunks"


def main() -> None:
    OUT.mkdir(parents=True, exist_ok=True)
    with launch(BROWSER, headless=HEADLESS) as browser:
        context = browser.new_context()
        page = context.new_page()

        context.tracing.start(name="fill-in")  # opens the first chunk
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        first = context.tracing.stop_chunk(path=OUT / "1-fill-in.zip")

        context.tracing.start_chunk(name="submit")
        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Welcome, ada")
        second = context.tracing.stop_chunk(path=OUT / "2-submit.zip")

        context.tracing.stop()  # no chunk is open any more, so there is nothing to save
        context.close()

    for path in (first, second):
        assert path is not None
        actions = steero.tracing.load(path).document["actions"]
        print(f"{path.name}: {len(actions)} actions, {path.stat().st_size:,} bytes:",
              ", ".join(a["name"] for a in actions))


if __name__ == "__main__":
    main()

    1-fill-in.zip: 3 actions, 67,478 bytes: goto, fill, fill
2-submit.zip: 1 actions, 40,101 bytes: click

    expect(...) is not an action, so it is not in the list; it is the check that the submit worked. The final stop() has nothing left to save because the last chunk was already closed.

    Exercise 3: read a trace from code¶

    A trace is a zip with a JSON document inside, and steero.tracing.load(path) reads it. Record a short trace with one failing action, load it, and print each action's name, target, duration in seconds and error type.

    Hint: the actions are in trace.document["actions"]; each one has name, target, duration and error (None, or a dict with type and message).

    Solution 
    """Lesson 10, exercise 3: read a trace from code and print each action with its duration.

Records a short trace (one action fails on purpose), then opens it with ``steero.tracing.load``
and prints a table: action, target, seconds, and the error if there was one.

    python examples/course/10-debugging/solution_3_read_trace.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import tempfile
from pathlib import Path

import steero.tracing
from steero import SteeroTimeoutError
from steero.sync_api import launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

OUT = Path(tempfile.gettempdir()) / "steero-course" / "10-debugging"


def record(path: Path) -> None:
    """Sign in with tracing on; the last click fails after 1 second."""
    with launch(BROWSER, headless=HEADLESS) as browser:
        context = browser.new_context()
        context.tracing.start(screenshots=False, snapshots=False)  # actions only: a small file
        page = context.new_page()
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        page.get_by_role("button", name="Sign in").click()
        try:
            page.get_by_role("button", name="Sign out").click(timeout=1)
        except SteeroTimeoutError:
            pass  # the point is to see it in the trace
        context.tracing.stop(path=path)
        context.close()


def main() -> None:
    OUT.mkdir(parents=True, exist_ok=True)
    path = OUT / "read-me.zip"
    record(path)

    trace = steero.tracing.load(path)
    print(f"{trace.document['meta']['browser']}: {len(trace.document['actions'])} actions")
    for action in trace.document["actions"]:
        error = action["error"]["type"] if action["error"] else ""
        print(f"  {action['name']:6} {action['target'] or '':45} {action['duration']:6.3f} s  {error}")
    failed = [a for a in trace.document["actions"] if a["error"]]
    assert len(failed) == 1 and failed[0]["error"]["type"] == "SteeroTimeoutError"


if __name__ == "__main__":
    main()

    chrome: 5 actions
  goto                                                  0.132 s
  fill   get_by_label('User name')                      0.088 s
  fill   get_by_label('Password')                       0.045 s
  click  get_by_role('button', name='Sign in')          0.133 s
  click  get_by_role('button', name='Sign out')         1.036 s  SteeroTimeoutError

    Reading traces from code is handy on a build server: a few lines can list the slowest actions of every failed test without opening a viewer.

    Exercise 4: find the cause from the message¶

    Each of these three fragments runs on the sign-in page and fails. Before running them, read each one and predict the error. Then run them and check your diagnosis against the message.

    page.locator("input").fill("ada", timeout=2)                          # 1
page.get_by_label("Username").fill("ada", timeout=2)                   # 2
page.get_by_label("User name").fill("ada")                             # 3
page.get_by_label("Password").fill("lovelace")
expect(page.get_by_role("status"), timeout=2).to_have_text("Welcome, ada")
    Solution 
    """Lesson 10, exercise 4: three broken scripts, and what each error message says is wrong.

Each function is one of the lesson's broken scripts. The script runs all three, catches the
error each one raises and prints it, so you can compare it with your diagnosis.

    python examples/course/10-debugging/solution_4_read_errors.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
from collections.abc import Callable

from steero import SteeroTimeoutError, StrictModeViolation
from steero.sync_api import Page, expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def broken_1(page: Page) -> None:
    page.locator("input").fill("ada", timeout=2)


def broken_2(page: Page) -> None:
    page.get_by_label("Username").fill("ada", timeout=2)


def broken_3(page: Page) -> None:
    page.get_by_label("User name").fill("ada")
    page.get_by_label("Password").fill("lovelace")
    expect(page.get_by_role("status"), timeout=2).to_have_text("Welcome, ada")


CASES: list[tuple[Callable[[Page], None], type[Exception], str]] = [
    (broken_1, StrictModeViolation, "the locator matches three inputs: say which one"),
    (broken_2, SteeroTimeoutError, "no element matches: the label is 'User name', with a space"),
    (broken_3, AssertionError, "the status stayed empty: nobody clicked Sign in"),
]


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        for script, expected, diagnosis in CASES:
            context = browser.new_context()  # a clean start for each broken script
            page = context.new_page()
            page.goto(BASE_URL + "login.html")
            try:
                script(page)
            except expected as error:
                print(f"{script.__name__}: {type(error).__name__}")
                print(f"    {error}")
                print(f"    cause: {diagnosis}")
            else:
                raise AssertionError(f"{script.__name__} was expected to fail")
            context.close()


if __name__ == "__main__":
    main()

    broken_1: StrictModeViolation
    locator('input') matched 3 elements; use .first, .nth() or a more specific locator

    The first fails at once: being ambiguous is not something waiting can fix. The second waits the full 2 seconds, because the element might still appear. The third says "got ''": the welcome never started, so look for the step that should have caused it, here the missing click.

    Common mistakes¶

    Common mistakes

    • page.pause() does nothing. The browser is headless; pause() only waits in a headed run. Launch with headless=False (or STEERO_COURSE_HEADED=1, --headed).
    • SteeroError: tracing is already started on this context. start() was called twice. Call stop() first, or use stop_chunk() and start_chunk() to split a recording.
    • The trace file is missing. stop() was called without a path, which discards the recording, or the script failed before stop(). Put stop(path=...) in a finally, or let the pytest plugin do it with --tracing retain-on-failure.
    • steero show-trace says the file is not a steero trace. It reads steero traces and steero frame sets; it cannot open a Playwright trace, and Playwright's viewer cannot open a steero trace.
    • Chrome's video is a .frames.zip. ffmpeg is not on PATH. Install it, or play the frame set with steero show-trace.
    • video.path() blocks or the file is empty. The page is still open. Close the page (or the context) first: that is what finishes the recording.
    • Sharing a trace with secrets in it. Passwords and auth headers are redacted, but page text, other headers and console output are not. Check before attaching one to a public issue.

    Recap¶

    • Run headed and use highlight() to see what a locator finds; page.pause() stops a headed run until Enter and is ignored headless.
    • context.tracing.start() and stop(path="trace.zip") record actions, screenshots, DOM snapshots, console and network; chunks split one session into several files.
    • steero show-trace trace.zip opens the viewer; --html out.html writes one file to attach to a bug.
    • new_context(record_video_dir=...) records video; Firefox writes .webm itself, Chrome needs ffmpeg for .webm and otherwise saves a .frames.zip.
    • Read the error first: action, locator, time waited and the last reason.
