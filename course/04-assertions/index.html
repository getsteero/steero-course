    04. Assertions¶

    In this lesson

    You will learn to:

    • write web-first assertions with expect for locators, pages and responses
    • use the common matchers: text, value, visibility, count, URL, title, attribute, enabled and checked
    • negate with not_ (or not_to_*) and set a timeout per assertion or for all of them
    • collect several failures at once with expect.soft, and assert on any value with expect.poll
    • check structure with aria_snapshot and to_match_aria_snapshot

    Time: about 40 minutes. Before this: 03. Actions and auto-waiting. Code: examples/course/04-assertions/

    A script that clicks through a page proves only that nothing crashed. Assertions are what turn it into a test: they say what the page must show. This lesson teaches steero's expect, which checks the page the way the actions in lesson 03 act on it, by waiting until the page is ready.

    Why web-first assertions¶

    Here are two ways to check the welcome message on the sign-in page:

    page.get_by_role("button", name="Sign in").click()

assert page.get_by_role("status").text_content() == "Welcome, ada"   # reads once
expect(page.get_by_role("status")).to_have_text("Welcome, ada")      # waits until true

    The first line reads the text once, straight after the click. The page answers half a second later, so the read sees "Signing in..." and the assert fails, although nothing is wrong. The usual "fix" is a sleep before the read, with all the problems lesson 03 described.

    The second line is a web-first assertion. expect(locator) builds an assertion about what the locator finds, and to_have_text(...) keeps checking, about ten times a second, until the text matches or 5 seconds pass. On a fast page it returns at once; on a slow one it waits as long as needed; and when the text really is wrong, it fails with both values:

    AssertionError: expect(get_by_role('status')).to_have_text: expected 'Welcome, ada', got 'Signing in...' after 5 s

    State assertions name the states instead, for example expect(get_by_text('Saved')).to_be_hidden: expected hidden, got visible after 5 s, or got no element matches when the locator found nothing.

    expect comes from the same import as launch:

    from steero.sync_api import expect, launch

    It takes a locator, a page (expect(page).to_have_title(...)) or a response (expect(response).to_be_ok(), for lesson 07).

    The everyday matchers¶

    Matcher Passes when
    to_have_text(text) the element's whole text equals text (whitespace squashed; a regex is searched)
    to_contain_text(text) the text contains text
    to_have_value(value) an input, textarea or select has this value
    to_be_visible(), to_be_hidden() the element is shown; or hidden or absent
    to_have_count(n) exactly n elements match
    to_be_enabled(), to_be_disabled() the control can, or cannot, be used
    to_be_checked() a checkbox or radio is ticked (checked=False: it is not)
    to_be_editable(), to_be_empty(), to_be_focused() accepts typing; has no text or value; has focus
    to_have_attribute(name, value) an attribute has this value
    to_have_class(...), to_contain_class(...) the class attribute is exactly, or includes, these classes
    expect(page).to_have_url(url) the page's URL equals url (or matches a regex)
    expect(page).to_have_title(title) the document title equals title

    A few notes on using them well:

    • Text matchers take a string or a compiled regex. A string compares the whole text (to_have_text) or a part (to_contain_text); re.compile(r"Welcome, \w+") is searched. ignore_case=True makes either kind case-insensitive.
    • A list checks several elements at once. expect(page.locator("li")).to_have_text(["Apple", "Banana", "Cherry"]) passes only when there are exactly three items with those texts, in that order. Exercise 1 uses this.
    • Assertions are strict, like actions. to_have_text("x") on a locator that matches several elements raises StrictModeViolation. to_have_count and the list forms are made for several.
    • Hidden includes absent. to_be_hidden() passes when nothing matches, which is what you want for "the spinner has gone".

    The visual comparison guide lists the less common matchers (to_have_values, to_have_role, to_have_accessible_name, to_have_css, and others).

    Negation and timeouts¶

    Every matcher can be turned around with .not_, which then waits until the condition is false:

    expect(page.get_by_role("alert")).not_.to_be_visible()
expect(page.get_by_role("status")).not_.to_have_text("Signing in...")

    Playwright's spelling works too: not_to_be_visible(), not_to_have_text(...), and so on for every matcher. Pick one style per project.

    The 5-second default can be changed per assertion, for every assertion made afterwards, or for a named group:

    expect(page.locator("#report"), timeout=30).to_be_visible()   # this assertion: 30 seconds
expect.set_options(timeout=10)                                  # every expect() from now on
slow = expect.configure(timeout=60)                             # a separate expect with its own default
slow(page.locator("#export")).to_have_text("Export finished")

    As everywhere in steero, timeouts are seconds. And as with actions, a long timeout costs nothing when the page is quick: the assertion returns as soon as it passes.

    Coming from Playwright

    expect and its matchers have Playwright's names and behaviour, including the 5-second default, .not_, expect.soft, expect.poll, expect.configure and the custom message. The differences: timeouts are seconds (timeout=10, not timeout=10_000), and soft failures are raised by expect.raise_soft_failures() (or by the pytest plugin in lesson 09) rather than by a test runner you cannot see.

    Coming from Selenium

    You may be used to WebDriverWait(driver, 10).until(EC.text_to_be_present_in_element(...)) followed by a plain assert. expect(...) is both in one: the wait and the check, with a failure message that says what was expected and what the page showed.

    Messages¶

    A failure says what was checked, but not why. When a script has many similar checks, add a message as the second argument of expect; it is printed above the details:

    expect(page.get_by_test_id("cart-count"), "cart updated after adding the teapot").to_have_text("1")

    AssertionError: cart updated after adding the teapot
expect(get_by_test_id('cart-count')).to_have_text: expected '1', got '0' after 5 s

    Write the message as the step's purpose, not a restatement of the matcher: "cart updated after adding the teapot" helps the person reading a failure at midnight; "cart count is 1" does not.

    Soft assertions¶

    Normally the first failed assertion stops the script, which is right when later steps depend on it. Some pages have several independent things to check, though, such as the fields of a profile page, and you would like to see every wrong one in a single run. That is what soft assertions are for:

    expect.soft(page.get_by_label("Name")).to_have_value("Ada")
expect.soft(page.get_by_label("Email")).to_have_value("ada@example.com")
expect.soft(page.get_by_label("City")).to_have_value("London")
expect.raise_soft_failures()

    A failed expect.soft(...) waits as usual, then records the failure and lets the script go on. expect.raise_soft_failures() raises one AssertionError listing everything recorded, and clears the list; it does nothing when every check passed:

    AssertionError: 2 soft assertion(s) failed:
  1. expect(get_by_label('Email')).to_have_value: expected 'ada@example.com', got 'ada@example.org' after 5 s
  2. expect(get_by_label('City')).to_have_value: expected 'London', got '' after 5 s

    Always end a group of soft checks with raise_soft_failures(); without it, the failures are collected and never reported, and the script passes.

    Polling any value¶

    expect(...) works on things in a page. For anything else (a row in a database, a file a job writes, a count an API returns) use expect.poll(fn). It calls fn again and again until the matcher holds or the timeout passes:

    expect.poll(lambda: len(api.get("api/orders").json()), timeout=10).to_equal(3)

    The poll matchers are to_be, to_equal, to_be_truthy, to_be_falsy, to_be_none, to_be_greater_than (and _or_equal), to_be_less_than (and _or_equal), to_contain, to_match and to_have_length, each with .not_. In the sync API, fn is called on your own thread, so it can use any sync code; it waits a little longer between calls each time (0.1, 0.25, 0.5, then 1 second; change it with intervals=[...]).

    ARIA snapshots¶

    Checking a whole form one matcher at a time gets long. An ARIA snapshot describes the structure of a part of the page as assistive technology sees it: roles, names and states, in a small YAML-like format. locator.aria_snapshot() prints it:

    print(page.locator("#login").aria_snapshot())

    - form:
  - text: User name
  - textbox "User name"
  - alert
  - text: Password
  - textbox "Password"
  - alert
  - checkbox "Remember me"
  - text: Remember me
  - button "Sign in"

    Each line is a role, then the accessible name in quotes, then states in brackets ([checked], [disabled], [level=1]). Children are indented under their parent. Plain containers such as div and span are left out, and so is hidden content.

    expect(locator).to_match_aria_snapshot(template) compares the snapshot against a template in the same format. The template is partial, which makes it robust:

    • the nodes it lists must appear in that order, but the page may have more;
    • a role without a name (- textbox) matches any name;
    • states are checked only when you write them;
    • a name written as /regex/ is searched instead of compared.
    expect(page.locator("#login")).to_match_aria_snapshot("""
    - textbox "User name"
    - textbox "Password"
    - checkbox "Remember me"
    - button "Sign in"
""")

    That one assertion checks that the form has these four controls, with these names, in this order. When it fails, the error includes the actual snapshot, so you can see at a glance what changed.

    Browser support

    Snapshots are computed by steero's own script inside the page, so Chrome and Firefox produce the same text for the same page. The accessible names are an approximation of the W3C algorithm; in rare cases (nested labels, aria-owns, CSS generated content) they can differ from Playwright's, so write templates against what steero prints.

    Worked example¶

    The script signs in on the practice site, then checks the result five ways: the welcome text, the page title, that the URL did not change, that the button is usable again, and the form's structure. Three details that do not depend on each other are checked softly, and reported together.

    """Lesson 04: sign in, then check the result five ways, with one group of soft checks.

    python examples/course/04-assertions/example_check_sign_in.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        button = page.get_by_role("button", name="Sign in")

        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        button.click()

        # 1 to 4: each assertion waits (up to 5 seconds) for the half-second round trip.
        expect(page.get_by_role("status")).to_have_text("Welcome, ada")
        expect(page).to_have_title("Welcome - steero practice site")
        expect(page).to_have_url(BASE_URL + "login.html")          # signing in did not navigate
        expect(button).to_be_enabled()

        # 5: the structure of the form, as assistive technology sees it (a partial template).
        expect(page.locator("#login")).to_match_aria_snapshot("""
            - textbox "User name"
            - textbox "Password"
            - checkbox "Remember me"
            - button "Sign in"
        """)

        # Soft checks: independent details, all reported together at the end.
        expect.soft(page.get_by_label("User name")).to_have_value("ada")
        expect.soft(page.get_by_label("Remember me")).not_.to_be_checked()
        expect.soft(page.get_by_role("alert").first).to_be_empty()
        expect.raise_soft_failures()                                # raises if any of them failed
        print("Signed in, and all checks passed")


if __name__ == "__main__":
    main()

    python examples/course/04-assertions/example_check_sign_in.py

    Signed in, and all checks passed

    A passing run says little, so break it on purpose: change "Welcome, ada" to "Welcome, Ada" and run it again to see a hard failure; then change the soft to_have_value("ada") to to_have_value("grace") to see the soft report.

    example_matchers.py uses most of the matchers in the table above, plus not_, the not_to_* spelling and a per-assertion timeout, on /testsite/form.html:

    """Lesson 04: the everyday matchers, their negations and per-assertion timeouts.

    python examples/course/04-assertions/example_matchers.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import re

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")

        # The page
        expect(page).to_have_title("Form")
        expect(page).to_have_url(re.compile(r"/testsite/form\.html$"))

        # Visibility: both assertions wait for the page's timers.
        expect(page.locator("#late")).to_be_visible()                # shown after 0.6 seconds
        expect(page.locator("#overlay")).to_be_hidden()              # removed after 0.7 seconds
        expect(page.locator("#overlay")).not_.to_be_visible()        # the same check, negated

        # Text: to_have_text is the whole text, to_contain_text a part of it.
        expect(page.get_by_role("heading", level=1)).to_have_text("Sign in")
        expect(page.locator("#items")).to_contain_text("Banana")
        expect(page.locator("#items li")).to_have_count(3)

        # Values, states and attributes of form controls
        user = page.get_by_label("User name")
        user.fill("ada")
        expect(user).to_have_value("ada")
        expect(user).to_have_attribute("placeholder", "you@example.com")
        expect(page.get_by_label("Free")).to_be_checked()
        expect(page.get_by_label("Pro")).not_to_be_checked()          # Playwright's spelling of not_
        expect(page.get_by_role("button", name="Disabled")).to_be_disabled()
        expect(page.get_by_label("Fixed")).to_be_editable(editable=False)

        # A shorter timeout for one assertion, in seconds.
        expect(page.get_by_role("status"), timeout=1).to_be_empty()
        print("Every assertion passed")


if __name__ == "__main__":
    main()

    Exercises¶

    Exercise 1: a whole list in one assertion¶

    On /testsite/form.html, check that the fruit list (#items li) has exactly three items, "Apple", "Banana" and "Cherry", with a single to_have_text([...]) call. Then check that the list contains "Banana" with to_contain_text, and that "Cherry" does not come before "Apple".

    Solution 
    """Lesson 04, exercise 1: check a whole list in one assertion.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")
        fruit = page.locator("#items li")

        # A list checks every match, in order: exactly three items, Banana second.
        expect(fruit).to_have_text(["Apple", "Banana", "Cherry"])
        print("The list is Apple, Banana, Cherry")

        # to_contain_text with a list: these texts appear in this order, other items allowed.
        expect(fruit).to_contain_text(["Banana"])
        expect(fruit).not_.to_contain_text(["Cherry", "Apple"])     # wrong order
        print("Banana is in it, and Cherry does not come before Apple")


if __name__ == "__main__":
    main()

    With a list, to_contain_text looks for each text in order, skipping elements in between, so ["Cherry", "Apple"] fails (and .not_ passes) because Apple comes first.

    Exercise 2: read the message¶

    On the practice sign-in page (login.html), enter a user name but no password and click Sign in. Assert that the status says "Welcome, ada" with a timeout of 1 second: it never will. Catch the AssertionError and print it. Then do the same with a message saying what the step was for, and compare the two outputs.

    Solution 
    """Lesson 04, exercise 2: read a failing assertion's message, then add your own.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("ada")
        page.get_by_role("button", name="Sign in").click()     # no password, so this never signs in
        status = page.get_by_role("status")

        # Catching AssertionError is only for this exercise, so both messages can be printed.
        try:
            expect(status, timeout=1).to_have_text("Welcome, ada")
        except AssertionError as error:
            print("Without a message:\n ", error)

        try:
            expect(status, "signing in as ada with an empty password", timeout=1).to_have_text("Welcome, ada")
        except AssertionError as error:
            print("With a message:\n ", str(error).replace("\n", "\n  "))


if __name__ == "__main__":
    main()

    Without a message:
  expect(get_by_role('status')).to_have_text: expected 'Welcome, ada', got '' after 1 s
With a message:
  signing in as ada with an empty password
  expect(get_by_role('status')).to_have_text: expected 'Welcome, ada', got '' after 1 s

    The details are the same; the message says which step of the test they belong to. Catching the error is only for this exercise.

    Exercise 3: poll an API¶

    The practice site serves its product list at /api/products. Without opening a browser, use expect.poll to wait until the API reports three products, with a message and a timeout of 10 seconds. Count how many times your function was called.

    Hint: from steero.sync_api import request, then with request.new_context(base_url=BASE_URL) as api: gives you api.get("api/products"), whose .json() is the list. Lesson 07 covers the request API properly.

    Solution 
    """Lesson 04, exercise 3: poll a value that is not on any page, here an API's product count.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, request

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    # No browser needed: a request context sends HTTP requests straight from Python.
    with request.new_context(base_url=BASE_URL) as api:
        calls = 0

        def product_count() -> int:
            nonlocal calls
            calls += 1
            return len(api.get("api/products").json())

        # Calls product_count until it returns 3, for up to 10 seconds.
        expect.poll(product_count, "the catalogue has three products", timeout=10).to_equal(3)
        expect.poll(product_count).to_be_greater_than(0)
        print(f"The API reports 3 products ({calls} calls)")


if __name__ == "__main__":
    main()

    Here the count is right on the first call. In a real system the value would change over time (a background job importing products), and the poll would keep asking until it did.

    Exercise 4: a template that ignores the errors¶

    On the sign-in page, write an ARIA snapshot template for the form that passes both before and after clicking Sign in on the empty form, when the two error messages appear. Print aria_snapshot() first to see what you are matching.

    Hint: after the click, the snapshot shows textbox "User name User name is required", because the error text sits inside the label.

    Solution 
    """Lesson 04, exercise 4: a partial ARIA snapshot template that ignores the error messages.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

# Unlisted nodes (the alert spans, the label texts) are ignored. The names are regular
# expressions, because an error inside a label becomes part of the field's accessible name.
TEMPLATE = """
- form:
  - textbox /^User name/
  - textbox /^Password/
  - checkbox "Remember me"
  - button "Sign in"
"""


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        form = page.locator("#login")
        print(form.aria_snapshot())

        expect(form).to_match_aria_snapshot(TEMPLATE)               # before: no errors shown

        page.get_by_role("button", name="Sign in").click()         # empty form: both errors appear
        expect(page.get_by_text("Password is required")).to_be_visible()
        expect(form).to_match_aria_snapshot(TEMPLATE)               # after: still matches
        print("The template matches with and without the error messages")


if __name__ == "__main__":
    main()

    Leaving the alert lines out makes the template ignore them, because templates are partial. The regular expressions /^User name/ and /^Password/ accept the name with or without the error text appended.

    Common mistakes¶

    Common mistakes

    • assert locator.text_content() == ... after an action. It reads once and fails while the page is still updating. Use expect(locator).to_have_text(...).
    • Forgetting expect.raise_soft_failures(). Soft failures are recorded and never reported, and the script passes. End every group of soft checks with it.
    • Using to_have_text for a part of the text. It compares the whole text, so "Welcome" does not match "Welcome, ada". Use to_contain_text, or a regex.
    • Asserting on a locator that matches several elements. to_have_text("x") raises StrictModeViolation. Narrow the locator, or use the list form or to_have_count.
    • timeout=5000. Seconds, so that is 83 minutes. Write timeout=5.
    • Mixing the sync and async expect. from steero import expect is the async one (it needs await); a sync script imports expect from steero.sync_api.
    • Checking a moment that passes. A state that lasts half a second (a "Saving..." label, a disabled button during a request) may be over before the assertion first looks. Assert on the end state instead.

    Recap¶

    • expect(locator), expect(page) and expect(response) start assertions that retry until they pass or 5 seconds go by, so there is no need to wait before checking.
    • The common matchers cover text, values, visibility, counts, states, attributes, URL and title; .not_ (or not_to_*) inverts any of them.
    • Timeouts are seconds: per assertion, with expect.set_options, or with expect.configure.
    • expect.soft collects failures until expect.raise_soft_failures(); expect.poll asserts on any value; to_match_aria_snapshot checks a whole structure with a partial template.
