    11. Recording with codegen¶

    In this lesson

    You will learn to:

    • record a script with steero codegen in Chrome or Firefox
    • choose a target (sync script, async script or pytest test) and write it to a file
    • use the toolbar: pause, pick a locator, add assertions
    • explain how the recorder chooses locators, and ask it from code with generate_locator
    • tidy a recording into a good test

    Time: about 25 minutes. Before this: 10. Debugging. Code: examples/course/11-codegen/

    Writing the first draft of a test by hand means looking up every label and role on the page. codegen does that part for you: you use the page in a real browser, and steero writes the script that does the same thing, with the user-facing locators you learned in lesson 02. What it cannot do is decide what your test should check. This lesson covers both halves.

    Recording¶

    Start the practice site, then:

    steero codegen http://127.0.0.1:8765/login.html

    A visible Chrome window opens on the sign-in page, with a small toolbar at the bottom. Type a user name and a password, click Sign in, and watch the terminal: the script appears as you go. Close the window (or press Ctrl+C in the terminal) to finish. Either way the browser is shut down and its profile deleted.

    """Recorded with steero codegen."""

from steero.sync_api import launch

with launch("chrome", headless=False) as browser:
    page = browser.new_page()
    page.goto("http://127.0.0.1:8765/login.html")
    page.get_by_test_id("username").fill("ada")
    page.get_by_test_id("password").fill("lovelace")
    page.get_by_role("button", name="Sign in").click()

    Typing is recorded as one fill() per field with its final value, not one line per key. The script runs unmodified: save it and run it with python.

    The options:

    Option Meaning
    url the first page, recorded as page.goto(...); optional
    --browser chrome\|firefox which browser to record in (default chrome)
    --target python a sync script (the default)
    --target python-async an async with steero.launch(...) script
    --target python-pytest a pytest test using the steero_page fixture (lesson 09)
    --output FILE also write the script to FILE, rewritten after every change
    --viewport 1280x720 the page's viewport size
    --device "iPhone 13" the viewport of a common device (only its size is applied)
    --test-id-attribute data-qa the attribute get_by_test_id reads (default data-testid)

    For a test you will keep, record straight into a test file:

    steero codegen http://127.0.0.1:8765/login.html --target python-pytest --output test_sign_in.py

    Coming from Playwright

    steero codegen is the counterpart of playwright codegen, with the same idea of targets and a toolbar. It records with the stock browser you have installed, and the script it writes uses steero's API (seconds for timeouts, steero_page in pytest). There is no separate inspector window: the script streams to the terminal and to --output.

    Browser support

    Recording works the same in Chrome and Firefox: the recorder is a script steero installs in every frame over WebDriver BiDi, not a browser extension. A script recorded in one browser runs in the other once you change the name in launch(...) (or pass --browser to pytest).

    The toolbar¶

    The toolbar at the bottom of the page controls the recorder. It sits in a closed shadow root, so the page's CSS cannot restyle it, its buttons are invisible to locators, and its clicks never reach the page's own event handlers.

    • Pause / Record stops and resumes recording. Use it to get the page into the right state (close a cookie banner, scroll to a section) without those steps ending up in the script.
    • Pick locator shows, as you move the pointer, the locator the recorder would write for the element under it. Clicking prints it in the terminal (and copies it to the clipboard when the browser allows); the click does not reach the page. This is the quickest way to get a good locator for a test you are writing by hand.
    • Assert visible, Assert text and Assert value: click one, then click an element, and the recorder adds expect(...).to_be_visible(), to_contain_text(...) or to_have_value(...) for it, instead of a click. Escape leaves these modes.

    How locators are chosen¶

    For each action, the page proposes candidate locators for the element, and steero counts each candidate with its own selector engine. A locator is written only if steero resolves it to exactly that element, so a recorded locator is never ambiguous and never relies on a difference between the browser's idea of a role and steero's. The first unique candidate wins, in this order:

    1. get_by_test_id
    2. get_by_role(role, name=...)
    3. get_by_label
    4. get_by_placeholder
    5. get_by_alt_text
    6. get_by_text
    7. get_by_title
    8. get_by_role(role) without a name
    9. short CSS: an id, then stable attributes
    10. .first or .nth(i) on the best candidate, as a last resort

    Ids and class names that look generated by a framework or a build (css-1x2y3z, :r1:, ember1234, hashes) are never used, because they change from one build to the next.

    That order explains the recording above: the sign-in form's inputs have data-testid attributes, so they are recorded as get_by_test_id("username"), while the button has none and is recorded by its role and name.

    Locators from code¶

    The same choice is available as a coroutine, for tools and for your own curiosity:

    from steero.codegen import generate_locator

code = await generate_locator(page.locator("#sign-in"))  # 'page.get_by_role("button", name="Sign in")'

    It takes any locator that matches exactly one element and returns source code. Pass test_id_attribute= to match your project's attribute, and receiver= to start the chain with another variable name than page.

    From a recording to a test¶

    A recording is a first draft. Before it becomes a test, go through it once:

    1. Remove the noise. Clicks that only focused a field, a scroll that does not matter, a step you made by mistake. (Pause the recorder next time.)
    2. Add the checks. The recorder writes what you did, not what should be true afterwards. A recorded sign-in clicks the button and stops; the test must also assert the welcome message. Use the toolbar's assert buttons, or write expect(...) yourself.
    3. Prefer the assertion you mean. An Assert text click locates the element by what it is (a test id, a role, a label, CSS) rather than by the text it checks, so the status line here becomes expect(page.get_by_role("status")).to_contain_text("Welcome, ada"). When the element's own text is the only way to find it, the recorder writes to_be_visible() on get_by_text(...) instead, because to_contain_text of the same text could never fail. Tighten to_contain_text to to_have_text when the whole text matters.
    4. Replace literal data. The user name you typed, today's date, an order number: move them into variables or fixtures, and the URL into --base-url (lesson 09).
    5. Name it. test_recorded becomes test_sign_in_shows_welcome.

    The tidied version of the recording above:

    from steero.sync_api import Page, expect


def test_sign_in_shows_welcome(steero_page: Page) -> None:
    steero_page.goto("login.html")
    steero_page.get_by_test_id("username").fill("ada")
    steero_page.get_by_test_id("password").fill("lovelace")
    steero_page.get_by_role("button", name="Sign in").click()
    expect(steero_page.get_by_role("status")).to_have_text("Welcome, ada")

    Limits¶

    What is recorded: clicks (with modifier keys) and double clicks; typing; Enter, Tab, Escape and shortcuts as press(); checking, select_option and file uploads (file names only); navigations you make from the address bar; popups and new tabs; actions inside iframes, through frame_locator(...) chains.

    What is not recorded:

    • hover, drag and drop, scrolling and right clicks. Add them by hand (lesson 03).
    • The files themselves for an upload: the script names the files, and they must exist next to it.
    • Waits. The recorder does not know that you waited for a message before clicking on; the auto-waiting of actions covers most of this, and assertions cover the rest.

    Navigations are told apart by timing: a navigation shortly after a click or a key press is left to that action, and one that happens on its own a few seconds after your last action is recorded as a goto. A page that redirects itself late may therefore get an extra goto line; delete it.

    Worked example¶

    steero codegen needs you at the keyboard, so the course cannot run it as it is. Instead, the example uses the same Recorder class the command uses, headless, and drives the page with steero's own actions. Those reach the page as real input, exactly as your clicks would, so the recorder cannot tell the difference. The script records signing in, prints what was recorded, saves it to your temporary directory and runs it in a fresh Python process, unmodified.

    Notice that it drives the page with brittle #id locators, and the recording comes out with good ones: the recorder chooses its own locators from the element, not from how you found it.

    """Lesson 11: record signing in with the codegen recorder, then run the script it wrote.

``steero codegen`` is interactive: you click in a visible browser. To run unattended, this
example uses the same ``Recorder`` headless and drives the page with steero's own actions, which
reach the page as real input, exactly like yours. The script it records is saved to your
temporary directory and run in a new Python process, unmodified.

    python examples/course/11-codegen/example_record_sign_in.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import asyncio
import os
import subprocess
import sys
import tempfile
from pathlib import Path

import steero
from steero.codegen import Recorder

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

OUT = Path(tempfile.gettempdir()) / "steero-course" / "11-codegen"


async def record() -> str:
    """What you would do by hand after ``steero codegen <url>/login.html``."""
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        recorder = Recorder(browser, target="python", headless=True)
        try:
            page = await recorder.start(BASE_URL + "login.html")
            await page.locator("#username").fill("ada")
            await page.locator("#password").fill("lovelace")
            await page.locator("#sign-in").click()
            await steero.expect(page.locator("#status")).to_have_text("Welcome, ada")
        finally:
            script = await recorder.stop()
    return script


def main() -> None:
    script = asyncio.run(record())
    print(script, flush=True)
    OUT.mkdir(parents=True, exist_ok=True)
    path = OUT / "recorded_sign_in.py"
    path.write_text(script, encoding="utf-8")
    subprocess.run([sys.executable, str(path)], check=True)
    print("Saved and replayed:", path)


if __name__ == "__main__":
    main()

    A second example asks generate_locator about every control on the sign-in form:

    """Lesson 11: which locator would the recorder write for each control on the sign-in form?

``generate_locator`` runs the recorder's own choice (test id, then role and name, then label ...)
on any element you point at, so you can see its decisions without recording anything.

    python examples/course/11-codegen/example_generate_locators.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import asyncio
import os

import steero
from steero.codegen import generate_locator

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

# The sign-in form's controls, found by id: the brittle way the recorder improves on.
CONTROLS = ["#username", "#password", "#remember", "#sign-in", "#status", "header a[href='products.html']"]


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        page = await browser.new_page()
        await page.goto(BASE_URL + "login.html")
        for selector in CONTROLS:
            code = await generate_locator(page.locator(selector))
            print(f"{selector:32} -> {code}")

        # A different test id attribute changes the choice (this page has none called data-qa).
        code = await generate_locator(page.locator("#username"), test_id_attribute="data-qa")
        print(f"{'#username (data-qa)':32} -> {code}")


if __name__ == "__main__":
    asyncio.run(main())

    #username                        -> page.get_by_test_id("username")
#password                        -> page.get_by_test_id("password")
#remember                        -> page.get_by_role("checkbox", name="Remember me")
#sign-in                         -> page.get_by_role("button", name="Sign in")
#status                          -> page.get_by_role("status")
header a[href='products.html']   -> page.get_by_role("link", name="Products")
#username (data-qa)              -> page.get_by_role("textbox", name="User name")

    The last line shows the order at work: with data-qa as the test id attribute, the field has no test id, so the next rule, role and name, wins.

    Exercises¶

    Exercise 1: record a pytest test¶

    Record signing in on the practice site as a pytest test, into a file, and run it with pytest.

    steero codegen http://127.0.0.1:8765/login.html --target python-pytest --output test_recorded.py
pytest test_recorded.py
    Solution

    The solution does the same unattended, with Recorder(..., target="python-pytest"), and then runs the recorded file with pytest:

    """Lesson 11, exercise 1: record signing in as a pytest test, then run the test with pytest.

The same as ``steero codegen <url>/login.html --target python-pytest --output test_recorded.py``,
driven headless. The recorded test uses the ``steero_page`` fixture from lesson 09.

    python examples/course/11-codegen/solution_1_record_pytest.py

Date: Nov-07-2026
"""

import asyncio

import subprocess
import sys
import tempfile
from pathlib import Path

import steero
from steero.codegen import Recorder

# course: timeout=180

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")

        recorder = Recorder(browser, target="python-pytest", headless=True)
        try:
            page = await recorder.start(BASE_URL + "login.html")

    main()

    Exercise 2: an assertion from the toolbar¶

    Record signing in again. When the welcome message appears, click Assert text in the toolbar and then click the message. Check that the script gained an expect(...) line, and run it.

    Solution

    The toolbar's button switches the recorder's mode; from code that is set_mode("assert-text"):

    """Lesson 11, exercise 2: add a text assertion while recording, the way the toolbar does.

Clicking the toolbar's **Assert text** button switches the recorder to ``assert-text`` mode; the
next click on the page adds an assertion instead of a click. ``set_mode`` is what that button
calls. The recorded script is then replayed, so the assertion is checked for real.

    python examples/course/11-codegen/solution_2_assert_text.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (the assertion target is structural now)
"""

import asyncio
import os
import subprocess
import sys
import tempfile
from pathlib import Path

import steero
from steero.codegen import Recorder

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

OUT = Path(tempfile.gettempdir()) / "steero-course" / "11-codegen"


async def record() -> str:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        recorder = Recorder(browser, headless=True)
        try:
            page = await recorder.start(BASE_URL + "login.html")
            await page.get_by_label("User name").fill("ada")
            await page.get_by_label("Password").fill("lovelace")
            await page.get_by_role("button", name="Sign in").click()
            status = page.get_by_role("status")
            await steero.expect(status).to_have_text("Welcome, ada")  # wait, as you would by eye

            await recorder.set_mode("assert-text")  # the Assert text button
            await status.click()  # this click becomes an assertion, and never reaches the page
        finally:
            script = await recorder.stop()
    return script


def main() -> None:
    script = asyncio.run(record())
    print(script, flush=True)
    # The recorder finds the status line by its role, not by the text it checks.
    assert 'expect(page.get_by_role("status")).to_contain_text("Welcome, ada")' in script
    OUT.mkdir(parents=True, exist_ok=True)
    path = OUT / "recorded_with_assertion.py"
    path.write_text(script, encoding="utf-8")
    subprocess.run([sys.executable, str(path)], check=True)
    print("Replayed, assertion included:", path)


if __name__ == "__main__":
    main()

        page.get_by_role("button", name="Sign in").click()
    expect(page.get_by_role("status")).to_contain_text("Welcome, ada")

    The assertion finds the message by its role, not by the text it checks, so it fails if the status line shows anything else. The script imports expect because it now has an assertion; a recording without one imports only launch.

    Exercise 3: what would the recorder write?¶

    Open /testsite/form.html and print the locator the recorder would choose for at least five of its elements, found by CSS: the user name field, the password, the search box, the country list, the submit button, the logo and the second list item.

    Solution 
    """Lesson 11, exercise 3: the locators the recorder would choose on steero's test form.

Points ``generate_locator`` at seven elements of ``/testsite/form.html`` by CSS and prints the
user-facing locator the recorder would write instead.

    python examples/course/11-codegen/solution_3_form_locators.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import asyncio
import os

import steero
from steero.codegen import generate_locator

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

ELEMENTS = ["#user", "#pass", "#search", "#country", "button[type=submit]", "img", "#items li:nth-child(2)"]


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        page = await browser.new_page()
        await page.goto(BASE_URL + "testsite/form.html")
        chosen = {}
        for selector in ELEMENTS:
            chosen[selector] = await generate_locator(page.locator(selector))
            print(f"{selector:24} -> {chosen[selector]}")
        # #user has a data-testid, so the test id wins over its label.
        assert chosen["#user"] == 'page.get_by_test_id("user-input")', chosen


if __name__ == "__main__":
    asyncio.run(main())

    #user                    -> page.get_by_test_id("user-input")
#pass                    -> page.get_by_role("textbox", name="Password")
#search                  -> page.get_by_role("searchbox", name="Search")
#country                 -> page.get_by_role("combobox", name="Country")
button[type=submit]      -> page.get_by_role("button", name="Sign in")
img                      -> page.get_by_role("img", name="Company logo")
#items li:nth-child(2)   -> page.get_by_role("listitem", name="Banana")

    Every positional or id-based CSS locator became a user-facing one. #user has a data-testid, so the test id wins over its label.

    Common mistakes¶

    Common mistakes

    • Nothing is recorded. The recorder is paused (the toolbar shows Record), or a pick or assert mode is still on. Click Record, or press Escape.
    • The script has a goto you did not type. The page navigated by itself late (a redirect, a timed refresh) and the timing rule read it as yours. Delete the line.
    • A recorded test passes but proves nothing. Recordings hold actions, not checks. Add at least one expect(...) for the outcome the test is about.
    • set_input_files fails with a missing file. Only the file names were recorded; put the files next to the script or fix the paths.
    • The recorded locator uses .nth(1). Nothing about the element was unique. Add a test id or an accessible name to the page if you can; otherwise check the position is really stable.
    • generate_locator raises StrictModeViolation. The locator you passed matched more than one element; it needs exactly one.
    • <coroutine object generate_locator ...> is printed instead of a locator. generate_locator is async: call it with await inside async def, as in the examples.

    Recap¶

    • steero codegen <url> records what you do in a visible browser and streams a runnable script; --target python-pytest --output test_x.py writes a test.
    • The toolbar pauses, picks locators and adds to_be_visible, to_contain_text and to_have_value assertions.
    • Locators are chosen in a fixed order (test id, role and name, label, ...) and only if steero's engine resolves them to exactly that element; generated ids and classes are never used.
    • generate_locator(locator) gives the same choice from code.
    • A recording is a draft: remove noise, add the checks, replace data, and name the test.
