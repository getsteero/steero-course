    12. Self-healing locators¶

    In this lesson

    You will learn to:

    • explain what self-healing does and, just as important, when it refuses
    • wrap locators in a healer with stable keys and a FingerprintStore
    • use the steero_healer fixture and --steero-strict-heal in pytest
    • read a heal event and its suggested replacement, and fix the test
    • tune HealConfig, and use risk="destructive" for dangerous actions

    Time: about 35 minutes. Before this: 11. Recording with codegen. Code: examples/course/12-self-healing/

    A redesign lands, and half the suite fails. Not because anything is broken for users, but because an id was renamed and a class changed. Self-healing keeps such a test running when the answer is clear, tells you exactly which locator to fix, and refuses when the answer is not clear. The second half matters more than the first: a healer that guesses clicks the wrong button, and a wrong click is worse than a red test.

    Why tests break¶

    Lesson 02 recommended user-facing locators because markup changes more often than what users see. Real suites still contain brittle ones: #submit-btn, .btn.btn-primary, div > form > button:nth-child(3), written before anyone knew better or copied from a browser's "copy selector". When the page is redesigned:

    • an id is renamed (#submit-btn becomes #login-submit);
    • classes are restyled (btn btn-primary becomes button button--primary);
    • a wrapper <div> appears, so a positional path no longer leads anywhere.

    For the user, nothing changed: the button still says "Sign in" in the same place. For the test, the locator matches nothing and every test that signs in fails.

    How healing decides¶

    Healing works in two phases.

    While the locator still works, steero records a fingerprint of the element it finds, under a key you choose, such as login.submit. A fingerprint is everything that describes the element apart from the locator: tag, id, test id, role, accessible name, label, classes, the headings and landmarks around it, and its position on the page.

    When the locator matches nothing, for at least 1 second (heal_after), steero scores every visible element on the page against the fingerprint. Each feature gives a similarity from 0 to 1, and the score is their weighted average. Then a fixed rule decides:

    Rule Default Why
    best score at least warn_threshold 0.65 below that, nothing on the page is really like the original
    best leads the runner-up by at least margin 0.10 two close candidates means the healer would be guessing
    best score at least auto_threshold 0.80 heal silently (auto); between 0.65 and 0.80, heal with a SelfHealWarning (warn)

    If the rule accepts, the action goes ahead on the healed element and a heal event records what happened. If not, nothing is guessed: the action times out as it would have without healing, and its error says why healing refused.

    The rule is deterministic: the same page and the same fingerprint give the same decision every time. There is no model and no network call involved.

    Using a healer¶

    Wrap each locator you want healed, with a key that stays the same when the markup changes:

    from steero.heal import FingerprintStore
from steero.sync_api import healer

with FingerprintStore(".steero/baselines") as store:    # saved when the block ends
    heal = healer(page, store)
    submit = heal.locator("login.submit", page.locator("#submit-btn"))
    submit.click()

    heal.locator(...) returns an ordinary locator: you call click(), fill() and expect(...) on it as before. It only behaves differently when the original stops matching.

    The FingerprintStore keeps fingerprints by key. Given a folder, it reads fingerprints.json from it when created. New fingerprints are kept in memory until they are saved: the with block saves them into fingerprints.json when it ends (even if the code inside failed), or call store.save() yourself. The pytest plugin saves for you at the end of a session, with one shard per pytest-xdist worker. FingerprintStore() with no folder keeps everything in memory.

    A fingerprint is recorded the first time a key's locator matches exactly one element, and is not overwritten afterwards, so the baseline stays what the page looked like when the test was known good. Pass update_baselines=True to healer() (or --steero-update-baselines in pytest) to re-record after a redesign you have accepted.

    Async version 
    from steero.heal import FingerprintStore, Healer

with FingerprintStore(".steero/baselines") as store:
    heal = Healer(page, store)
    submit = heal.locator("login.submit", page.locator("#submit-btn"))
    await submit.click()

    Coming from Playwright

    Playwright has no built-in self-healing. Healing in steero is opt-in per locator: a plain page.locator(...) never heals, so nothing changes in a suite until you wrap a locator.

    Coming from Selenium

    Selenium healing tools usually heal any find_element and pick the best match automatically. steero heals only the locators you name, and refuses rather than picks when two candidates are close. Expect fewer heals and no silent wrong clicks.

    Refusals¶

    There are three kinds of refusal, and each one is the healer doing its job.

    Ambiguous. Two candidates are about equally good, for example two identical "Save" buttons. The error ends with:

    self-healing refused: ambiguous: best 0.91 vs runner-up 0.90 (margin 0.10)

    Low score. Nothing on the page is similar enough, for example the button was removed:

    self-healing refused: best score 0.41 below warn threshold 0.65

    Destructive. A locator wrapped with risk="destructive" heals only to an element with the same id or the same data-testid as the original. Use it for Delete, Pay, Send and anything else you could not undo:

    delete = heal.locator("account.delete", page.locator("#delete-btn"), risk="destructive")

    self-healing refused: destructive action: no exact id/data-testid match

    A lookalike Delete button is never clicked, however high it scores.

    One more message is not a refusal: self-healing never ran: it waits 1 s for the original locator before trying, so give this action a longer timeout. An action with a timeout shorter than heal_after gives up before healing starts.

    Fixing the test¶

    A heal is a warning, not a fix. Every decision is a heal event; heal.report() returns them as dictionaries:

    Field Meaning
    key the stable name, login.submit
    locator the original locator, locator('#submit-btn')
    outcome healed or refused
    band auto, warn or refused
    score, runner_up the best and second-best scores
    reason why the decision was made
    suggestion a robust replacement, such as page.get_by_role('button', name='Sign in')
    url the page the decision was made on

    The suggestion is the code to paste into the test, in place of the brittle locator. It follows the same preference as codegen: test id, then role and name, then label.

    In pytest¶

    The plugin provides a steero_healer fixture for steero_page:

    def test_sign_in(steero_page: Page, steero_healer: Healer) -> None:
    steero_page.goto("login.html")
    steero_healer.locator("login.submit", steero_page.locator("#submit-btn")).click()

    Baselines live in --steero-baselines (default .steero/baselines) and are saved when the session ends. After a run with heals, pytest prints a summary and writes steero-artifacts/heal-report.json:

    ========================= steero self-healing =========================
HEALED  login.submit [warn 0.74] locator('#submit-btn') -> page.get_by_role('button', name='Sign in')
report: steero-artifacts/heal-report.json

    --steero-strict-heal fails any test that needed healing, after it ran. Use it in your release gate: day to day the suite stays green through a redesign, and the gate makes sure someone replaces each healed locator before release. Commit fingerprints.json with the tests, so every machine heals from the same baselines.

    Tuning¶

    HealConfig holds the numbers from the table above:

    from steero.heal import HealConfig

config = HealConfig(auto_threshold=0.85, warn_threshold=0.70, margin=0.15, heal_after=2.0)
heal = healer(page, store, config)

    Raising the thresholds trades heals for safety; lowering them does the opposite, and some of the extra heals will be wrong clicks. Change them only when you have measured on your own app, as below.

    Measured on ControlLab¶

    steero's own suite includes ControlLab, a larger single-page app with 279 tests written against version 1 with deliberately brittle locators. Versions 2 and 3 apply 18 catalogued changes: renamed ids, moved markup, reordered columns, a removed button, a relabelled delete. (The practice site serves all three at /controllab/v1/, /controllab/v2/ and /controllab/v3/.) With fingerprints from a v1 run and the default thresholds, on Chrome:

    App Healing off Healing on
    v2 1 test passes (every test signs in, and the sign-in button's id changed) 235 of 279 pass
    v3 252 pass 270 pass

    What still fails is the useful part of the result:

    • Changes that are not about locators. A menu that moved under a submenu (the old element exists but is hidden, so healing never runs), a <select> that became a custom listbox (select_option cannot work on a button). The test needs updating, not healing.
    • Correct refusals. The relabelled Delete button is refused as destructive, the removed Export button has nothing to heal to, two row checkboxes that became indistinguishable are refused as ambiguous (1.00 against 0.97).
    • Real misses. A few elements scored just under the 0.65 floor. Lowering the floor would rescue some and misclick others, which is why it is a setting.
    • Positional locators that still match. After the grid columns were reordered, td:nth-child(7) still finds a cell, just the wrong one. No healer can notice, because nothing failed to match: only a user-facing locator would have avoided it.

    The self-healing guide has the details and the commands to reproduce the numbers.

    Worked example¶

    The script signs in on /testsite/heal/v1.html with brittle #id locators wrapped in a healer, which records three fingerprints and saves them to a baseline folder in your temporary directory. Then it runs the same sign-in on v2.html, the redesign, where every id and class changed, with a fresh store read from that folder. All three locators match nothing; the healer finds each element again and the sign-in succeeds.

    """Lesson 12: a sign-in script survives a redesign that renamed every id and class.

Run 1 signs in on ``/testsite/heal/v1.html`` with brittle id locators wrapped in a healer, which
records a fingerprint of each element and saves them to a baseline folder. Run 2 uses the same
script on ``v2.html``, where the ids changed: the locators match nothing, the healer finds each
element again by its fingerprint, and the script prints every heal and its suggested locator.

    python examples/course/12-self-healing/example_heal_redesign.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (the store saves itself in a with block)
"""

import os
import shutil
import tempfile
from pathlib import Path

from steero.heal import FingerprintStore
from steero.sync_api import Browser, expect, healer, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

BASELINES = Path(tempfile.gettempdir()) / "steero-course" / "12-self-healing" / "baselines"


def sign_in(browser: Browser, version: str) -> list[dict[str, object]]:
    """Sign in on heal/<version>.html with id locators; return the healer's events."""
    page = browser.new_context().new_page()
    # Reads fingerprints.json from earlier runs; saves what this run recorded when the block ends.
    with FingerprintStore(BASELINES) as store:
        heal = healer(page, store)
        user = heal.locator("login.user", page.locator("#username"))
        password = heal.locator("login.password", page.locator("#password"))
        submit = heal.locator("login.submit", page.locator("#submit-btn"))

        page.goto(BASE_URL + f"testsite/heal/{version}.html")
        user.fill("ada")
        password.fill("lovelace")
        submit.click()
        expect(page.get_by_role("status")).to_have_text("signed in")
    page.context.close()
    return heal.report()


def main() -> None:
    shutil.rmtree(BASELINES, ignore_errors=True)  # start with no baselines
    with launch(BROWSER, headless=HEADLESS) as browser:
        events = sign_in(browser, "v1")
        print(f"v1: signed in, {len(events)} heal events; baselines in {BASELINES}")
        assert events == []

        events = sign_in(browser, "v2")
        print(f"v2: signed in after {len(events)} heals:")
        for event in events:
            print(f"  {event['key']:15} {event['band']:5} {event['score']:.2f}  "
                  f"{event['locator']} -> {event['suggestion']}")
        assert {e["key"] for e in events if e["outcome"] == "healed"} == {"login.user", "login.password",
                                                                           "login.submit"}


if __name__ == "__main__":
    main()

    v1: signed in, 0 heal events; baselines in C:\Users\you\AppData\Local\Temp\steero-course\12-self-healing\baselines
SelfHealWarning: healed login.password (score 0.77 (warn)); use page.get_by_role('textbox', name='Password')
SelfHealWarning: healed login.submit (score 0.74 (warn)); use page.get_by_role('button', name='Sign in')
v2: signed in after 3 heals:
  login.user      auto  0.82  locator('#username') -> page.get_by_role('textbox', name='User name')
  login.password  warn  0.77  locator('#password') -> page.get_by_role('textbox', name='Password')
  login.submit    warn  0.74  locator('#submit-btn') -> page.get_by_role('button', name='Sign in')

    The user name field heals in the auto band. The password field and the button heal in the warn band, so Python prints a SelfHealWarning for each: they changed more (new id, new classes and a new wrapper) and the healer wants a person to look. The suggestions are what the test should have said in the first place.

    A second example shows tuning. The same Sign in button heals at the default thresholds, and is refused with warn_threshold=0.80, because its score of 0.74 is now under the floor:

    """Lesson 12: the same redesign under two ``HealConfig`` settings, the default and a stricter one.

Records fingerprints on ``/testsite/heal/v1.html``, then clicks the renamed Sign in button on
``v2.html`` twice: with the default thresholds it heals (score 0.74, in the warn band), and with
``warn_threshold=0.80`` the same candidate is below the floor, so the click is refused.

    python examples/course/12-self-healing/example_heal_config.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import warnings

from steero import SteeroTimeoutError
from steero.heal import FingerprintStore, HealConfig, SelfHealWarning
from steero.sync_api import Browser, healer, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def click_sign_in(browser: Browser, config: HealConfig) -> str:
    """Record on v1, click on v2 under ``config``; return the outcome and reason."""
    page = browser.new_context().new_page()
    heal = healer(page, FingerprintStore(), config)
    submit = heal.locator("login.submit", page.locator("#submit-btn"))
    page.goto(BASE_URL + "testsite/heal/v1.html")
    submit.click()
    page.goto(BASE_URL + "testsite/heal/v2.html")
    try:
        submit.click(timeout=10)  # healing starts after 1 s; leave it time to run
    except SteeroTimeoutError:
        if not heal.report():
            raise  # healing never got to decide: that is a real failure
        # otherwise it refused, and the event below says why
    page.context.close()
    (event,) = heal.report()
    return f"{event['outcome']} ({event['reason']})"


def main() -> None:
    warnings.simplefilter("ignore", SelfHealWarning)  # the events say the same thing
    with launch(BROWSER, headless=HEADLESS) as browser:
        default = click_sign_in(browser, HealConfig())
        strict = click_sign_in(browser, HealConfig(auto_threshold=0.90, warn_threshold=0.80))
    print("default thresholds:", default)
    print("warn_threshold 0.80:", strict)
    assert default.startswith("healed") and strict.startswith("refused")


if __name__ == "__main__":
    main()

    default thresholds: healed (score 0.74 (warn))
warn_threshold 0.80: refused (best score 0.74 below warn threshold 0.80)

    Exercise 1: two lookalikes¶

    The practice page heal-lookalikes.html has one Save button, #save. Its version 2, heal-lookalikes.html?v=2, renamed the id and added a second, identical Save button. Wrap #save in a healer, click it on version 1, then try again on version 2. What happens, and which button was clicked?

    Solution 
    """Lesson 12, exercise 1: two lookalike buttons, and a healer that refuses to pick one.

Version 1 of ``heal-lookalikes.html`` has one Save button, ``#save``; the healer records it.
Version 2 renamed the id and added a second, identical Save button. Both candidates score the
same, so the click is refused and times out with the reason, and nothing is saved.

    python examples/course/12-self-healing/solution_1_ambiguous_refusal.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero import SteeroTimeoutError
from steero.heal import FingerprintStore
from steero.sync_api import expect, healer, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    store = FingerprintStore()  # in memory: this script records and heals in one run
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        heal = healer(page, store)
        save = heal.locator("notes.save", page.locator("#save"))

        page.goto(BASE_URL + "heal-lookalikes.html")
        save.click()  # works, and records the fingerprint
        expect(page.get_by_role("status")).to_have_text("Saved by #save")

        page.goto(BASE_URL + "heal-lookalikes.html?v=2")
        try:
            save.click(timeout=10)  # healing waits 1 s before it tries, so allow well more than that
        except SteeroTimeoutError as error:
            print("Refused, as it should be:")
            print("   ", error)
        else:
            raise AssertionError("the healer guessed between two identical buttons")
        expect(page.get_by_role("status")).to_have_text("")  # neither button was clicked

        (event,) = heal.report()
        print(f"{event['outcome']}: best {event['score']:.2f}, runner-up {event['runner_up']:.2f}")
        assert event["outcome"] == "refused" and "ambiguous" in event["reason"], event


if __name__ == "__main__":
    main()

    Refused, as it should be:
    click locator('#save'): timed out after 10 s: no element matches; self-healing refused: ambiguous: best 0.91 vs runner-up 0.90 (margin 0.10)
refused: best 0.91, runner-up 0.90

    Neither button was clicked. Both score high (0.91 is well inside auto), but they are only 0.01 apart, so choosing one would be a coin toss. The click is given 10 seconds, well over the 1 second healing waits before it tries.

    Exercise 2: a destructive action¶

    On /testsite/heal/v1.html, wrap the Delete account button (#delete-btn) twice: once normally, once with risk="destructive". On v2.html the button has a new id and a new data-testid. Show that the normal locator heals (without clicking it) and that the destructive one refuses to click.

    Solution 
    """Lesson 12, exercise 2: a Delete button marked ``risk="destructive"`` is never healed to a lookalike.

On ``/testsite/heal/v2.html`` the Delete account button has a new id and a new data-testid. A
normal healing locator finds it again (here only asked whether it is enabled, so nothing is
deleted). The same locator marked destructive refuses, because neither the id nor the test id
matches exactly, and the click times out with the reason.

    python examples/course/12-self-healing/solution_2_destructive.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero import SteeroTimeoutError
from steero.heal import FingerprintStore
from steero.sync_api import expect, healer, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        heal = healer(page, FingerprintStore())
        normal = heal.locator("danger.delete.normal", page.locator("#delete-btn"))
        destructive = heal.locator("danger.delete", page.locator("#delete-btn"), risk="destructive")

        page.goto(BASE_URL + "testsite/heal/v1.html")
        assert normal.is_enabled() and destructive.is_enabled()  # both record a fingerprint

        page.goto(BASE_URL + "testsite/heal/v2.html")
        print("Normal locator healed, enabled:", normal.is_enabled(timeout=10))
        try:
            destructive.click(timeout=10)
        except SteeroTimeoutError as error:
            print("Destructive locator refused:")
            print("   ", error)
        else:
            raise AssertionError("a destructive action was healed to a different element")
        expect(page.get_by_role("status")).to_have_text("")  # the account was not deleted

        outcomes = {e["key"]: e["outcome"] for e in heal.report()}
        print(outcomes)
        assert outcomes == {"danger.delete.normal": "healed", "danger.delete": "refused"}, outcomes


if __name__ == "__main__":
    main()

    Normal locator healed, enabled: True
Destructive locator refused:
    click locator('#delete-btn'): timed out after 10 s: no element matches; self-healing refused: destructive action: no exact id/data-testid match
{'danger.delete.normal': 'healed', 'danger.delete': 'refused'}

    The normal heal is probably right here, it is the same button renamed. But "probably" is not good enough for deleting an account, and risk="destructive" makes that a rule.

    The script that runs it three times:

    """Lesson 12, exercise 3: ``steero_healer`` in pytest, and why ``--steero-strict-heal`` fails a healed test.

Runs ``heal_tests/test_heal_sign_in.py`` three times, all writing to your temporary directory:

1. on v1: the test passes and the plugin records baselines in ``--steero-baselines``;
2. on v2: the test passes by healing, and the plugin writes ``heal-report.json``;
3. on v2 with ``--steero-strict-heal``: the test body passes, but the healer fixture then fails
   it, so a heal can never slip through a gate unnoticed.

    python examples/course/12-self-healing/solution_3_strict_heal.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import json
import os
import shutil
import subprocess
import sys
import tempfile
from pathlib import Path

# course: timeout=240

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

HERE = Path(__file__).resolve().parent
OUT = Path(tempfile.gettempdir()) / "steero-course" / "12-self-healing" / "pytest"


def run(version: str, *extra: str) -> subprocess.CompletedProcess[str]:
    """Run the healing test on one page version and print pytest's summary line."""
    command = [sys.executable, "-m", "pytest", str(HERE / "heal_tests"), "-q", "-p", "no:cacheprovider",
               "--steero-browser", BROWSER, "--steero-base-url", BASE_URL,
               "--steero-baselines", str(OUT / "baselines"), "--steero-artifacts", str(OUT / "artifacts"), *extra]
    if not HEADLESS:
        command.append("--steero-headed")
    env = dict(os.environ, HEAL_VERSION=version, PYTHONDONTWRITEBYTECODE="1")
    result = subprocess.run(command, env=env, capture_output=True, text=True, encoding="utf-8", errors="replace",
                            check=False)
    print(f"{' '.join([version, *extra])}: exit {result.returncode}: {result.stdout.strip().splitlines()[-1]}")
    return result

    Common mistakes¶

    Common mistakes

    • Nothing heals on the second run. The baselines were never saved. In a script, use with FingerprintStore(folder) as store: or call store.save() before it ends; in pytest, check that --steero-baselines points at the same folder both times.
    • self-healing never ran: it waits 1 s .... The action's timeout is shorter than heal_after. Give it a few seconds, or lower heal_after in HealConfig.
    • no baseline fingerprint recorded for 'login.submit'. The locator never worked while wrapped under that key, so there is nothing to compare with. Run once against the version where it works.
    • Two locators share a key. The second one heals towards the first one's element. Give every wrapped locator its own key.
    • A heal clicks the right button but the test fails later. The interaction changed (a <select> became a custom list, a menu moved). Healing finds elements; it does not rewrite steps. Update the test.
    • Keeping a heal forever. Healed tests are slower (each one waits heal_after first) and depend on old baselines. Paste the suggestion in and let --steero-strict-heal enforce it.
    • Expecting healing to catch a wrong match. td:nth-child(7) that still matches the wrong cell never triggers healing. Use user-facing locators.

    Recap¶

    • A healer records a fingerprint per key while a locator works, and when it stops matching, scores the page against it.
    • It heals only with a clear winner: at least 0.65, and 0.10 ahead of the runner-up; 0.80 and above is silent, below that it warns.
    • Ambiguous, low-score and destructive cases are refused, and the action fails with the reason.
    • Every heal comes with a suggested locator; heal-report.json collects them in pytest and --steero-strict-heal fails a gate until they are applied.
    • HealConfig tunes the thresholds; risk="destructive" heals only to the same id or test id.
