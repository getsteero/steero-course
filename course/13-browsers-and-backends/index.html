    13. Browsers and backends¶

    In this lesson

    You will learn to:

    • explain why steero's main API works the same in Chrome and Firefox, and where CDP still appears
    • choose a Chrome backend (chromedriver or chromium-bidi) and know the trade-offs
    • launch Edge and release channels such as channel="chrome-beta" or firefox-nightly
    • pin browser versions with steero install chrome@<version> and STEERO_CHROME_VERSION
    • use the Chrome-only extras in steero.chromium and handle UnsupportedOnBrowser
    • know the Firefox specifics: no driver, Firefox preferences, emulation gaps, video by screencast

    Time: about 35 minutes. Before this: 12. Self-healing locators. Code: examples/course/13-browsers-and-backends/

    Until now you have switched browsers with one environment variable and never thought about what happens underneath. This lesson opens that box: how steero reaches each browser, how to pick the exact build you test against, and what to do with the few features only one browser has.

    One protocol, two browsers¶

    Every page action in this course (navigate, click, fill, evaluate, screenshot, route) travels over WebDriver BiDi, the W3C standard protocol that Chrome, Edge and Firefox all implement. steero has one implementation of each feature, written against the standard, so a script that passes in Chrome is not a different program in Firefox.

    The older Chrome DevTools Protocol (CDP) still exists in Chrome and Edge, and it can do a few things BiDi cannot yet: performance counters, CPU throttling, JavaScript coverage. Firefox removed CDP entirely. So steero keeps CDP out of its main API and puts those extras in one module, steero.chromium, which says plainly that it is Chrome only. If you never import steero.chromium, nothing in your script depends on CDP.

    from steero import chromium

metrics = await chromium.performance_metrics(page)  # Chrome and Edge only

    Coming from Playwright

    Playwright drives Chromium mostly over CDP and Firefox through a patched build ("Juggler"). steero drives the stock browsers you install, over the standard. The price is that a few Chrome features only exist where CDP does, and they are marked as such.

    Chrome backends¶

    steero can reach Chrome in two ways. Both end at the same BiDi connection, so the rest of your script cannot tell them apart. You pick one with backend= or the STEERO_CHROME_BACKEND environment variable.

    Backend How it works Good for
    chromedriver (default) steero starts chromedriver, the Chrome team's own driver, matched to your Chrome version and downloaded from Chrome for Testing Google's supported path; the safest default
    chromium-bidi steero starts Chrome alone and loads the chromium-bidi mapper (the same code chromedriver runs) into a hidden tab no driver binary on disk; useful where you cannot run extra executables 
    with launch("chrome", backend="chromium-bidi") as browser:
    ...

    $env:STEERO_CHROME_BACKEND = "chromium-bidi"
python examples/course/01-getting-started/example_first_script.py

    STEERO_CHROME_BACKEND=chromium-bidi python examples/course/01-getting-started/example_first_script.py

    The mapper is a JavaScript file published on npm. steero downloads it on first use, checks it against npm's SHA-512 hash and caches it, just as it caches chromedriver. To fetch it ahead of time (for example on a build machine):

    steero install chromium-bidi

    chromium-bidi 158.0.8110-0: 1,018,728 bytes cached

    STEERO_CHROMIUM_BIDI_VERSION pins another mapper version, and STEERO_CHROMIUM_BIDI_PATH points at a local mapperTab.js and skips the download. The course test runs every example on both backends (STEERO_BROWSERS=chrome,chrome:chromium-bidi,firefox), which is a cheap way to make sure a suite does not depend on one of them.

    Coming from Selenium

    The chromedriver backend is the driver you know, but you never download, start or match it yourself: steero reads the Chrome version, fetches the right driver and stops it when the browser closes.

    Edge and channels¶

    Microsoft Edge is Chromium, so steero drives it like Chrome, through msedgedriver (downloaded the same way) or through backend="chromium-bidi":

    with launch("edge") as browser:   # "msedge" works too
    print(browser.name, browser.version)   # edge 157.0.4341.42

    A release channel is a separately installed build: Chrome Beta, Dev or Canary, Edge Beta, Firefox Nightly. channel= picks its executable, using Playwright's channel names:

    launch("chrome", channel="chrome-beta")
launch("chrome", channel="msedge")          # switches the browser to Edge
launch("firefox", channel="firefox-nightly")

    A channel that is not installed raises LaunchError, naming the environment variable to set if it lives somewhere unusual (STEERO_CHROME_BETA_PATH, STEERO_FIREFOX_NIGHTLY_PATH ...). For a binary steero does not know at all, executable_path= names it directly. steero doctor (lesson 01) lists Chrome, Firefox and Edge with their versions, so it is the first thing to run when a launch cannot find a browser.

    Browser support

    Edge has the same BiDi support as Chrome (same engine), and steero.chromium works in it. A channel must belong to the browser you launch: launch("firefox", channel="msedge") raises LaunchError.

    Pinned versions¶

    The browser on your machine updates itself every few weeks. A suite that must keep working on the versions your users run should be tested against those versions on purpose. steero can install specific builds into its cache, without touching the system browser:

    steero install chrome@154            # newest 154.x from Chrome for Testing, plus its chromedriver
steero install firefox@esr           # newest Extended Support Release
steero install firefox@157

    chrome@154: C:\Users\you\AppData\Local\steero\browsers\chrome-154.0.8037.92\chrome-win64\chrome.exe

    Then select one with an environment variable. Nothing in your script changes:

    $env:STEERO_CHROME_VERSION = "154"
python examples/course/01-getting-started/example_first_script.py

    STEERO_CHROME_VERSION=154 python examples/course/01-getting-started/example_first_script.py

    Running chrome 154.0.8037.92
Title: Sign in - steero practice site
Saved signed-in.png

    STEERO_FIREFOX_VERSION does the same for Firefox. If the version is not installed, the launch fails at once with the command that fixes it:

    LaunchError: STEERO_CHROME_VERSION=153 but that version is not installed; run: steero install chrome@153

    STEERO_CHROME_PATH and STEERO_FIREFOX_PATH still win over a pinned version. A useful habit: run the suite against the current stable, the previous major version and, for Firefox, the ESR your users are on. The pinned browsers guide lists the limits (Chrome for Testing starts at about version 113; macOS Firefox is not installable this way).

    Downloads

    steero install chrome@... and firefox@... download a whole browser (well over 100 MB). The examples in this lesson never do; they only report what is already installed.

    Chrome extras¶

    steero.chromium is a handful of async functions that take a Page:

    Function What it gives you
    performance_metrics(page) Chrome's counters: Nodes, JSEventListeners, JSHeapUsedSize, LayoutCount ...
    set_cpu_throttling(page, rate) a CPU rate times slower (1 switches it off), for testing slow devices
    start_js_coverage(page) / stop_js_coverage(page) which JavaScript ran, per script
    heap_usage(page) the JavaScript heap's used and total bytes
    cdp(page, method, params) any CDP command, when you know exactly what you need

    They are async only, so a script that uses them uses the async API (lesson 01). In Firefox each one raises UnsupportedOnBrowser, a SteeroError that says what is missing:

    from steero import UnsupportedOnBrowser, chromium

try:
    heap = await chromium.heap_usage(page)
except UnsupportedOnBrowser as error:
    print(error)   # Chrome DevTools Protocol extras are not available in firefox

    The same error comes from the main API when a browser cannot apply an option, so it is the one exception to handle when a script must run everywhere but use a feature only some browsers have. The Chromium extras guide has the full list, including the listener tools that reach objects a page keeps out of scope.

    Browser support

    The extras work in Chrome and Edge, on both backends. In Firefox they raise UnsupportedOnBrowser before anything is sent to the browser.

    Firefox specifics¶

    Firefox needs no driver at all: it has a BiDi server built in, and steero starts Firefox with a fresh profile and connects to it directly. Three differences are worth knowing.

    Preferences. Firefox is configured through preferences (the settings in about:config). prefs= writes extra ones into the fresh profile before Firefox starts:

    launch("firefox", prefs={"intl.accept_languages": "fr-FR, en"})

    Chrome ignores prefs=; there, use args= for command-line switches.

    Emulation gaps. Firefox cannot yet apply is_mobile, has_touch, java_script_enabled=False, reduced_motion or forced_colors over BiDi. Passing one raises UnsupportedOnBrowser naming the option; steero never falls back to something that only looks right. Lesson 06 and the emulation guide have the table.

    Video. Firefox records video itself (browsingContext.startScreencast) and writes a .webm. Chrome has no BiDi screencast yet, so steero captures frames and encodes them with ffmpeg when it is installed (lesson 10).

    Worked example¶

    The script below opens the products page in whatever browser the course runs. In Chrome or Edge it also starts JavaScript coverage before the page loads, then prints a few metrics; in Firefox the first extra raises UnsupportedOnBrowser, and the script prints that and carries on with the part every browser can do.

    """Lesson 13: the same page in any browser, plus the Chrome-only extras where they exist.

Prints the browser's name and version. In Chrome (or Edge) it also prints a few performance
metrics and how many scripts JS coverage saw; in Firefox it shows the ``UnsupportedOnBrowser``
error those extras raise instead.

    python examples/course/13-browsers-and-backends/example_browser_info.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import asyncio
import os

import steero
from steero import UnsupportedOnBrowser, chromium, expect

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        print(f"Browser: {browser.name} {browser.version}")
        page = await browser.new_page()
        try:
            # Coverage must start before the page's scripts run, so start it before goto.
            await chromium.start_js_coverage(page)
        except UnsupportedOnBrowser as error:
            print("No Chrome extras here:", error)
            await page.goto(BASE_URL + "products.html")
            await expect(page.get_by_role("status")).to_have_text("3 products")
            return

        await page.goto(BASE_URL + "products.html")
        await expect(page.get_by_role("status")).to_have_text("3 products")

        coverage = await chromium.stop_js_coverage(page)
        metrics = await chromium.performance_metrics(page)
        heap = await chromium.heap_usage(page)
        print(f"DOM nodes: {metrics['Nodes']:.0f}, event listeners: {metrics['JSEventListeners']:.0f}")
        print(f"JS heap used: {heap['used'] / 1024:,.0f} KiB")
        print(f"Scripts with coverage: {len(coverage)}")


if __name__ == "__main__":
    asyncio.run(main())

    Two more examples cover the other launch options. example_edge_and_channels.py launches Edge and the chrome-beta channel if they are installed, and says "Skipping" for each one that is not, so it runs anywhere:

    """Lesson 13: launch Microsoft Edge and a Chrome release channel, when they are installed.

Edge is found the way Chrome is; a channel such as ``chrome-beta`` picks that channel's
executable. Anything not installed is reported and skipped, so the script always exits 0
on a machine that has Chrome.

    python examples/course/13-browsers-and-backends/example_edge_and_channels.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

# course: browsers=chrome

import os

from steero import LaunchError
from steero.launch.discover import find_browser, find_channel
from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def sign_in(browser_name: str, **options: str) -> None:
    """Sign in on the practice site and print which browser did it."""
    with launch(browser_name, headless=HEADLESS, **options) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("edge")
        page.get_by_label("Password").fill("secret")
        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Welcome, edge")
        print(f"  signed in with {browser.name} {browser.version}")


def main() -> None:
    try:
        print("Edge at", find_browser("edge"))
    except LaunchError as error:  # not installed: say so and carry on
        print("Skipping Edge:", error)
    else:
        sign_in("edge")

    try:
        family, path = find_channel("chrome-beta")
        print(f"chrome-beta ({family}) at {path}")
    except LaunchError as error:
        print("Skipping chrome-beta:", error)
    else:
        sign_in("chrome", channel="chrome-beta")


if __name__ == "__main__":
    main()

    example_firefox_specifics.py (Firefox only) sets a preference and shows the error an unsupported emulation option raises:

    """Lesson 13: Firefox preferences, and an emulation option Firefox cannot apply.

``prefs=`` writes Firefox preferences into the fresh profile before Firefox starts. Here
``intl.accept_languages`` makes the browser ask for French first. Then a context with
``is_mobile=True`` (Chrome only) shows the ``UnsupportedOnBrowser`` error it raises in Firefox.

    python examples/course/13-browsers-and-backends/example_firefox_specifics.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

# course: browsers=firefox

import os

from steero import UnsupportedOnBrowser
from steero.sync_api import launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "firefox")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    prefs = {"intl.accept_languages": "fr-FR, en"}
    with launch(BROWSER, headless=HEADLESS, prefs=prefs) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        languages = page.evaluate("navigator.languages")
        print("navigator.languages:", languages)
        assert languages[0] == "fr-FR", languages

        try:
            browser.new_context(is_mobile=True)
        except UnsupportedOnBrowser as error:
            print("As expected:", error)
        else:
            print("This Firefox accepted is_mobile: its BiDi support has grown since this lesson")


if __name__ == "__main__":
    main()

    navigator.languages: ['fr-FR', 'en']

    Exercises¶

    Run each solution from the repository root with the practice site running.

    Exercise 1: a slower CPU¶

    In Chrome, time the products page at normal speed and again with set_cpu_throttling(page, 4). Page loads on a local server are so fast that the difference is small, so also time a fixed piece of JavaScript inside the page with performance.now(). Check that the throttled run is clearly slower, and switch throttling off again at the end.

    Hint: page.evaluate() can run a function that returns how long a loop took.

    Solution 
    """Lesson 13, exercise 1: time a page at normal speed and with the CPU four times slower.

Chrome only (``set_cpu_throttling`` is a DevTools Protocol extra). The page load is timed
from Python; a fixed piece of JavaScript work is timed inside the page with
``performance.now()``, which shows the throttling most clearly.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

# course: browsers=chrome,edge

import asyncio
import os
import time

import steero
from steero import chromium, expect

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

WORK = """() => {
    const t = performance.now();
    let x = 0;
    for (let i = 0; i < 3e6; i++) x += i % 7;
    return performance.now() - t;
}"""


async def measure(page: steero.Page) -> tuple[float, float]:
    """Seconds to load the products page, and milliseconds of in-page work."""
    started = time.perf_counter()
    await page.goto(BASE_URL + "products.html")
    await expect(page.get_by_role("status")).to_have_text("3 products")
    load = time.perf_counter() - started
    work = min([await page.evaluate(WORK) for _ in range(3)])  # the best of three is the least noisy
    return load, work


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        page = await browser.new_page()
        await measure(page)  # warm up: the first load also starts the page's processes

        normal_load, normal_work = await measure(page)
        await chromium.set_cpu_throttling(page, 4)
        slow_load, slow_work = await measure(page)
        await chromium.set_cpu_throttling(page, 1)  # 1 switches throttling off again

        print(f"normal:    load {normal_load:.2f} s, work {normal_work:.1f} ms")
        print(f"4x slower: load {slow_load:.2f} s, work {slow_work:.1f} ms")
        print(f"the work took {slow_work / normal_work:.1f} times as long")
        assert slow_work > normal_work * 1.5, "throttling should slow the in-page work down"


if __name__ == "__main__":
    asyncio.run(main())

    normal:    load 0.08 s, work 15.1 ms
4x slower: load 0.19 s, work 33.1 ms
the work took 2.2 times as long

    The first measure() is a warm-up: the first load also starts processes and compiles code, which would make the normal run look slow. Taking the best of three runs of the loop keeps one noisy run from deciding the result. The ratio is rarely exactly 4, because throttling slows the page's main thread, not the whole machine.

    Exercise 2: two backends, one script¶

    Run the lesson 01 sign-in with backend="chromedriver" and again with backend="chromium-bidi", and print how long each launch took. Do not let the script download the mapper: if it is not cached yet, print the steero install command instead.

    Solution 
    """Lesson 13, exercise 2: run the lesson 01 sign-in on both Chrome backends and compare launch times.

``chromium-bidi`` needs the BiDi mapper in steero's cache. This script never downloads it:
when it is missing, the script says how to fetch it (``steero install chromium-bidi``) and
times the default backend only.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

# course: browsers=chrome

import os
import time

from steero.launch.discover import cache_dir
from steero.launch.mapper import DEFAULT_VERSION
from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def mapper_available() -> bool:
    """True when chromium-bidi can start without a download."""
    if os.environ.get("STEERO_CHROMIUM_BIDI_PATH"):
        return True
    version = os.environ.get("STEERO_CHROMIUM_BIDI_VERSION") or DEFAULT_VERSION
    return (cache_dir() / "chromium-bidi" / version / "mapperTab.js").is_file()


def sign_in(backend: str) -> float:
    """Launch with ``backend``, sign in, and return the seconds the launch took."""
    started = time.perf_counter()
    with launch(BROWSER, headless=HEADLESS, backend=backend) as browser:
        launched = time.perf_counter() - started
        page = browser.new_page()
        page.goto(BASE_URL + "login.html")
        page.get_by_label("User name").fill("ada")
        page.get_by_label("Password").fill("lovelace")
        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Welcome, ada")
    return launched


def main() -> None:
    print(f"chromedriver:  launched in {sign_in('chromedriver'):.2f} s")
    if not mapper_available():
        print("chromium-bidi: skipped, the mapper is not cached; run: steero install chromium-bidi")
        return
    print(f"chromium-bidi: launched in {sign_in('chromium-bidi'):.2f} s")


if __name__ == "__main__":
    main()

    chromedriver:  launched in 1.79 s
chromium-bidi: launched in 1.74 s

    On a warm machine the two are close; the difference shows on the very first launch, when chromedriver is downloaded, and on machines where starting an extra executable is slow. The behaviour of the script is identical, which is the point.

    Exercise 3: skip a Chrome-only step, keep the rest¶

    Write a small async helper that awaits a Chrome-only step and, in Firefox, prints which step was skipped and why, then returns None. Use it to read the heap size on the products page, then add a product to the cart, which must work in every browser.

    Solution 
    """Lesson 13, exercise 3: a helper that runs a Chrome-only step, or skips it with a clear message.

The same script runs in every browser. In Chrome and Edge the step runs; in Firefox the
helper prints why it was skipped and the rest of the script carries on.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import asyncio
import os
from collections.abc import Awaitable
from typing import TypeVar

import steero
from steero import UnsupportedOnBrowser, chromium, expect

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"

T = TypeVar("T")


async def chrome_only(step: str, action: Awaitable[T]) -> T | None:
    """Await ``action``; if the browser cannot do it, print a message and return None."""
    try:
        return await action
    except UnsupportedOnBrowser as error:
        print(f"skipped {step!r}: {error}")
        return None


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        page = await browser.new_page()
        await page.goto(BASE_URL + "products.html")
        await expect(page.get_by_role("status")).to_have_text("3 products")

        heap = await chrome_only("heap usage", chromium.heap_usage(page))
        if heap is not None:
            print(f"heap used: {heap['used'] / 1024:,.0f} KiB")

        # The part of the check that every browser can do still runs.
        await page.get_by_role("button", name="Add Blue mug to cart").click()
        await expect(page.get_by_test_id("cart-count")).to_have_text("1")
        print(f"cart updated in {browser.name}")


if __name__ == "__main__":
    asyncio.run(main())

    skipped 'heap usage': Chrome DevTools Protocol extras are not available in firefox
cart updated in firefox

    Catching UnsupportedOnBrowser (and nothing wider) is what makes this safe: a real failure, such as a timeout, still raises.

    Common mistakes¶

    Common mistakes

    • Calling a steero.chromium function from sync code. It returns a coroutine and nothing happens (RuntimeWarning: coroutine ... was never awaited). The extras are async: write that script with steero.launch and await.
    • Expecting prefs= to change Chrome. It is for Firefox preferences only. Chrome takes command-line switches through args=.
    • Catching SteeroError to skip a Chrome-only step. That also hides timeouts and real failures. Catch UnsupportedOnBrowser.
    • Setting STEERO_CHROME_VERSION without installing the build. The launch fails with ... that version is not installed; run: steero install chrome@<version>. Run that command.
    • Leaving STEERO_CHROME_PATH set from an earlier experiment. It outranks a pinned version and the channel lookup, so the run quietly uses another browser. steero doctor shows which executable is picked; remove the variable when you are done.
    • Passing a Chromium channel to Firefox (launch("firefox", channel="msedge")). It raises LaunchError: channel 'msedge' is an edge channel, not a firefox one, before steero even looks for the executable. Launch "chrome" or "edge" with that channel instead.

    Recap¶

    • Everything in the main API is WebDriver BiDi and behaves the same in Chrome, Edge and Firefox; CDP appears only in steero.chromium.
    • Chrome has two backends, chromedriver (default) and chromium-bidi (no driver binary); pick one with backend= or STEERO_CHROME_BACKEND.
    • launch("edge"), channel="chrome-beta" and executable_path= choose the build; steero install chrome@154 with STEERO_CHROME_VERSION=154 pins a version.
    • A feature a browser lacks raises UnsupportedOnBrowser; catch exactly that to skip a step.
    • Firefox needs no driver, takes prefs=, and has a few emulation gaps listed in the guide.
