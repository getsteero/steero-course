    14. AI agents with MCP¶

    In this lesson

    You will learn to:

    • explain what the Model Context Protocol server does, and the risks of letting an agent drive a browser
    • start steero mcp for Chrome or Firefox and connect an MCP client to it
    • name the tools an agent gets (navigate, snapshot, click, type, wait, screenshot, console, tabs)
    • drive the server from a small Python client, as a test of your own setup

    Time: about 25 minutes. Before this: 13. Browsers and backends. Code: examples/course/14-mcp-agents/

    So far you have written every step yourself. An AI agent can also drive a browser: you ask it to "sign in and check the welcome message", and it decides which buttons to press. steero ships a server that gives such an agent a real Chrome or Firefox, with the same auto-waiting your tests get. This lesson shows what the agent sees and lets you speak the protocol yourself, so you can test the setup without any AI service.

    What MCP is¶

    The Model Context Protocol (MCP) is an open standard for connecting an AI application to tools. The application (the client: an IDE, a desktop assistant, an agent framework) starts a server program and asks it which tools it offers; the model then calls those tools by name with JSON arguments, and the server answers with text or images.

    steero mcp is such a server. It speaks MCP over stdio: the client writes one JSON-RPC message per line to the server's standard input and reads one reply per line from its standard output. There is no port and no network listener. The browser starts on the first tool call and closes when the client closes the server's input.

    steero mcp --browser firefox

    Started by hand like this, it just waits for JSON on its input; press Ctrl+C to stop it. It is meant to be started by a client.

    Safety first¶

    An agent that drives a browser acts with your machine's network access: it can open any site your browser can reach, including internal ones, and type whatever it decides into any form. steero adds no sandbox around that. So:

    • connect only agents you trust, from vendors you trust, and point them only at sites you are allowed to automate;
    • do not give it secrets it does not need; the server tells the agent not to enter secrets it was not given, but that is an instruction, not a guarantee;
    • watch it work the first few times (--headed), and review what it did;
    • run it against a practice site or a test environment before anything real.

    steero mcp --help prints the same warning. The browser itself starts from a fresh, empty profile every time, so the agent never sees your own cookies or saved passwords.

    Configure a client¶

    Most MCP clients read a JSON file with an mcpServers section. Where that file lives depends on the client (its documentation says); the entry for steero looks the same everywhere:

    {
  "mcpServers": {
    "steero": { "command": "steero", "args": ["mcp", "--browser", "firefox"] }
  }
}
    Option Meaning
    --browser chrome or --browser firefox which browser to drive (default chrome)
    --headed show the window, so you can watch
    --backend chromium-bidi reach Chrome without chromedriver (lesson 13)

    If the client cannot find steero (for example, it does not run inside your virtual environment), give the full path: "command": "C:\\path\\to\\.venv\\Scripts\\steero.exe", or "command": "/path/to/.venv/bin/python", "args": ["-m", "steero", "mcp", ...].

    Coming from Playwright

    Playwright's MCP server is a separate Node package. steero's is part of the Python package, has no extra dependencies, and drives stock Firefox as well as Chrome. The tool names follow the same browser_* pattern, so prompts written for one mostly work with the other.

    Browser support

    steero mcp --browser takes chrome, edge or firefox, and everything works the same in all three.

    The tools¶

    Tool Does
    browser_navigate open a URL; answers with a snapshot of the page
    browser_snapshot list the page's visible interactive elements, each with a ref (e1, e2 ...)
    browser_click, browser_type, browser_hover, browser_check, browser_select_option act on an element, given its ref (or a CSS selector)
    browser_press_key press a key or a combination such as Control+A
    browser_wait_for wait for text to appear (or, with gone, to disappear), or for some seconds
    browser_evaluate run JavaScript and return the value as JSON
    browser_screenshot a PNG of the viewport (full_page for the whole page), as image content
    browser_console_messages console output and page errors since the last call
    browser_tabs, browser_navigate_back, browser_close tabs, history, and closing the browser

    A snapshot is how the agent "sees" the page: one line per element, its role, its name and a ref.

    Page: Sign in - steero practice site
URL: http://127.0.0.1:8765/login.html
- heading "Sign in" [ref=e4]
- textbox "User name" [ref=e6]
- textbox "Password" [ref=e8]
- button "Sign in" [ref=e11]

    The agent then calls browser_type with {"ref": "e6", "text": "ada"}. Refs are short, cheap for a model to repeat, and valid until the next snapshot (each snapshot numbers the page again). Every action goes through a steero locator, so it auto-waits exactly as click() does in your scripts, and a dialog that opens is dismissed so the agent is never stuck behind it. A tool that fails (an element that never appears, say) answers with isError: true and the error text, which the agent can read and react to.

    Talking to it yourself¶

    You do not need an AI to try the server: any program that writes JSON lines can be the client. Three methods are enough.

    1. initialize: the handshake. The client says which protocol version it speaks; the server answers with its name, version and capabilities. The client then sends the notifications/initialized notification (no id, so no reply).
    2. tools/list: the tools, each with a JSON Schema for its arguments.
    3. tools/call: {"name": "browser_click", "arguments": {"ref": "e11"}}; the reply holds content (a list of text or image parts) and isError.

    On the wire, a request and its reply look like this:

    {"jsonrpc": "2.0", "id": 3, "method": "tools/call", "params": {"name": "browser_navigate", "arguments": {"url": "http://127.0.0.1:8765/login.html"}}}
{"jsonrpc": "2.0", "id": 3, "result": {"content": [{"type": "text", "text": "Page: Sign in - steero practice site\n..."}], "isError": false}}

    The lesson's folder has a small client, mcp_client.py, that starts python -m steero mcp as a subprocess and does exactly this. Each request gets a number, and a reader thread matches each reply to it with a deadline, so a lost reply fails in seconds instead of hanging:

    """Lesson 14: a minimal MCP client that starts ``steero mcp`` and talks JSON-RPC to it over stdio.

Not an example on its own: the lesson's scripts import it. It does what an AI agent's host
program does, without the AI: one JSON message per line on the server's stdin, one reply per
line on its stdout, every request numbered so its reply can be matched.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (edge)
"""

from __future__ import annotations

import json
import queue
import subprocess
import sys
import threading
from types import TracebackType
from typing import Any


class McpError(Exception):
    """The server answered a request with a JSON-RPC error."""


class McpClient:
    """Start ``steero mcp`` as a subprocess and call its tools.

    Args:
        browser: ``chrome``, ``edge`` or ``firefox``.
        headed: Show the browser window.
        command: The whole command line that starts the server, used as given (``browser`` and
            ``headed`` are then ignored). Default: ``python -m steero mcp --browser <browser>``.
    """

    def __init__(self, browser: str = "chrome", *, headed: bool = False, command: list[str] | None = None):
        args = command or [sys.executable, "-m", "steero", "mcp", "--browser", browser,
                           *(["--headed"] if headed else [])]
        # stderr is inherited: the server logs warnings there, never on stdout.
        self.process = subprocess.Popen(args, stdin=subprocess.PIPE, stdout=subprocess.PIPE)
        self._lines: queue.Queue[bytes] = queue.Queue()
        self._next_id = 0
        threading.Thread(target=self._read, daemon=True).start()

    def _read(self) -> None:
        assert self.process.stdout is not None
        for line in self.process.stdout:
            self._lines.put(line)
        self._lines.put(b"")  # end of output: the server has exited

    def _send(self, message: dict[str, Any]) -> None:
        assert self.process.stdin is not None
        self.process.stdin.write((json.dumps(message) + "\n").encode())
        self.process.stdin.flush()

    def request(self, method: str, params: dict[str, Any] | None = None, timeout: float = 60) -> dict[str, Any]:
        """Send a request and return its ``result``; wait at most ``timeout`` seconds."""
        self._next_id += 1
        self._send({"jsonrpc": "2.0", "id": self._next_id, "method": method, "params": params or {}})
        while True:
            try:
                line = self._lines.get(timeout=timeout)
            except queue.Empty:
                raise TimeoutError(f"no reply to {method} within {timeout} s") from None
            if not line:
                raise ConnectionError("the MCP server exited")
            reply: dict[str, Any] = json.loads(line)
            if reply.get("id") != self._next_id:
                continue  # not the answer to this request
            if "error" in reply:
                raise McpError(f"{method}: {reply['error']['message']}")
            result: dict[str, Any] = reply["result"]
            return result

    def initialize(self) -> dict[str, Any]:
        """The MCP handshake: ``initialize``, then the ``notifications/initialized`` notification."""
        result = self.request("initialize", {"protocolVersion": "2025-06-18", "capabilities": {},
                                             "clientInfo": {"name": "course-client", "version": "1"}})
        self._send({"jsonrpc": "2.0", "method": "notifications/initialized"})  # a notification: no id, no reply
        return result

    def call(self, tool: str, **arguments: Any) -> dict[str, Any]:
        """Call a tool and return its result (``content`` and ``isError``)."""
        return self.request("tools/call", {"name": tool, "arguments": arguments})

    def text(self, tool: str, **arguments: Any) -> str:
        """Call a tool that answers with text; raise if the tool reported an error."""
        result = self.call(tool, **arguments)
        text = "\n".join(part["text"] for part in result["content"] if part["type"] == "text")
        if result.get("isError"):
            raise McpError(f"{tool} failed: {text}")
        return text

    def close(self) -> None:
        """Close stdin, which tells the server to close the browser and exit."""
        assert self.process.stdin is not None
        self.process.stdin.close()
        try:
            self.process.wait(timeout=60)
        finally:
            if self.process.poll() is None:
                self.process.kill()

    def __enter__(self) -> McpClient:
        return self

    def __exit__(self, exc_type: type[BaseException] | None, exc: BaseException | None,
                 tb: TracebackType | None) -> None:
        self.close()

    The client closes the server by closing its standard input. The server then closes the browser and exits, so nothing is left running.

    Worked example¶

    The script plays the agent's part with fixed steps: list the tools, open the sign-in page, find the refs in the snapshot, type, click, wait for the welcome message and read it back.

    """Lesson 14: drive ``steero mcp`` the way an AI agent would, from a small Python client.

Starts the server, lists its tools, opens the sign-in page, reads the snapshot to find the
fields' refs, types into them, clicks Sign in and waits for the welcome message.

    python examples/course/14-mcp-agents/example_mcp_sign_in.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (steero mcp drives Edge too)
"""

import os
import re

from mcp_client import McpClient

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def ref(snapshot: str, role: str, name: str) -> str:
    """The ref (``e3``) of the element with this role and name in a snapshot."""
    match = re.search(rf'- {role} "{re.escape(name)}" \[ref=(e\d+)\]', snapshot)
    assert match, f"no {role} {name!r} in the snapshot:\n{snapshot}"
    return match.group(1)


def main() -> None:
    with McpClient(BROWSER, headed=not HEADLESS) as client:
        info = client.initialize()
        print("Server:", info["serverInfo"]["name"], info["serverInfo"]["version"])
        tools = client.request("tools/list")["tools"]
        print("Tools:", ", ".join(tool["name"] for tool in tools))

        snapshot = client.text("browser_navigate", url=BASE_URL + "login.html")
        print(snapshot)

        client.text("browser_type", ref=ref(snapshot, "textbox", "User name"), text="ada")
        client.text("browser_type", ref=ref(snapshot, "textbox", "Password"), text="lovelace")
        client.text("browser_click", ref=ref(snapshot, "button", "Sign in"))
        client.text("browser_wait_for", text="Welcome, ada")

        status = client.text("browser_evaluate", script="document.getElementById('status').textContent")
        print("Status:", status)
        assert "Welcome, ada" in status


if __name__ == "__main__":
    main()

    python examples/course/14-mcp-agents/example_mcp_sign_in.py

URL: http://127.0.0.1:8765/login.html
- link "Practice site" [ref=e1]
- link "Sign in" [ref=e2]
- link "Products" [ref=e3]
- heading "Sign in" [ref=e4]
- label "User name" [ref=e5]
- textbox "User name" [ref=e6]

    Notice that the header link and the submit button are both called "Sign in"; the snapshot tells them apart by role, and so does the ref() helper. browser_wait_for is what makes the last step reliable: the welcome text appears half a second after the click, and the wait returns as soon as it does. browser_evaluate returns JSON, which is why the status is printed in quotes.

    Exercise 1: press Enter, then take a picture¶

    Sign in as grace without clicking the button: let browser_type press Enter after the password. Wait for the welcome message, then call browser_screenshot and save the PNG it returns as mcp-signed-in.png.

    Hint: the screenshot's content part has type: "image" and base64 data.

    Solution 
    """Lesson 14, exercise 1: sign in by pressing Enter, wait for the welcome, and save a screenshot.

``browser_type`` with ``submit=True`` presses Enter after typing, so no click is needed.
``browser_screenshot`` answers with image content: base64 PNG data, decoded and saved here.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (steero mcp drives Edge too)
"""

import base64
import os
import re

from mcp_client import McpClient

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def ref(snapshot: str, role: str, name: str) -> str:
    """The ref (``e3``) of the element with this role and name in a snapshot."""
    match = re.search(rf'- {role} "{re.escape(name)}" \[ref=(e\d+)\]', snapshot)
    assert match, f"no {role} {name!r} in the snapshot:\n{snapshot}"
    return match.group(1)


def main() -> None:
    with McpClient(BROWSER, headed=not HEADLESS) as client:
        client.initialize()
        snapshot = client.text("browser_navigate", url=BASE_URL + "login.html")
        client.text("browser_type", ref=ref(snapshot, "textbox", "User name"), text="grace")
        client.text("browser_type", ref=ref(snapshot, "textbox", "Password"), text="hopper", submit=True)
        client.text("browser_wait_for", text="Welcome, grace")

        result = client.call("browser_screenshot")
        image = result["content"][0]
        assert image["type"] == "image" and image["mimeType"] == "image/png", image.keys()
        png = base64.b64decode(image["data"])
        assert png.startswith(b"\x89PNG"), "not a PNG"
        with open("mcp-signed-in.png", "wb") as file:
            file.write(png)
        print(f"Saved mcp-signed-in.png ({len(png):,} bytes)")


if __name__ == "__main__":
    main()

    Checking the first bytes (\x89PNG) before saving catches the case where a tool answered with an error text instead of an image.

    Exercise 3: your own client, Firefox¶

    Add steero to the configuration of an MCP client you use, with --browser firefox and --headed, restart the client, and ask it to "open http://127.0.0.1:8765/login.html, sign in as ada with any password and tell me what the page says". Watch the window while it works.

    To check a configuration before you hand it to a client, write it to a file and start the command it names yourself. The solution does that for Firefox, and falls back to python -m steero with the full path to Python when steero is not on PATH.

    Solution 
    """Lesson 14, exercise 3: write an MCP client configuration for Firefox, then check it works.

An MCP client (an IDE, a desktop assistant, an agent framework) starts the server from a
``command`` and ``args`` entry. This script writes that entry to ``mcp.json``, then starts
exactly that command and checks the handshake and one tool call, which is what the client
will do. When ``steero`` is not on PATH (a virtual environment that is not activated), it
writes the same server as ``python -m steero`` with the full path to Python.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

# course: browsers=firefox

import json
import os
import shutil
import sys

from mcp_client import McpClient

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "firefox")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def server_entry() -> dict[str, object]:
    """The ``mcpServers`` entry for steero driving Firefox."""
    args = ["mcp", "--browser", "firefox"] + ([] if HEADLESS else ["--headed"])
    steero = shutil.which("steero")
    if steero:
        return {"command": steero, "args": args}
    return {"command": sys.executable, "args": ["-m", "steero", *args]}


def main() -> None:
    config = {"mcpServers": {"steero": server_entry()}}
    with open("mcp.json", "w", encoding="utf-8") as file:
        json.dump(config, file, indent=2)
    print(json.dumps(config, indent=2))

    # Read it back and start the server the way a client would.
    with open("mcp.json", encoding="utf-8") as file:
        entry = json.load(file)["mcpServers"]["steero"]
    with McpClient(command=[entry["command"], *entry["args"]]) as client:
        client.initialize()
        snapshot = client.text("browser_navigate", url=BASE_URL + "login.html")
        assert "Page: Sign in - steero practice site" in snapshot, snapshot
        agent = client.text("browser_evaluate", script="navigator.userAgent")
        assert "Firefox" in agent, agent
        print("The configuration starts a working server in Firefox")


if __name__ == "__main__":
    main()

    If your client reports that the server "closed" or "failed to start", run the configured command by hand in a terminal: an error such as a missing browser is printed there, on standard error, where clients often hide it.

    Common mistakes¶

    Common mistakes

    • Printing to standard output in the server process. stdout carries the protocol, so any stray line breaks the client's parser. steero logs to stderr only; keep it that way in anything you wrap around it.
    • Reusing refs from an old snapshot. Each snapshot numbers the elements again, and after a page changes an old ref may point at nothing (isError: true, a timeout). Take a new snapshot, or use the one an action returns.
    • The client cannot start steero. The client runs outside your virtual environment. Put the full path to steero (or to the environment's Python with -m steero) in the configuration.
    • Waiting forever for a reply. Every request needs an id, and a notification gets no reply at all. Give each read a deadline, as mcp_client.py does.
    • Asking for a browser by a name steero does not know. --browser takes chrome, edge or firefox; anything else is a usage error and the server exits.
    • Pointing an agent at a real site on the first try. Start with the practice site and --headed, and review what it does before you trust it with more.

    Recap¶

    • steero mcp is an MCP server on stdio that gives an AI agent a fresh Chrome or Firefox.
    • The agent acts with your network access: trusted agents only, watch it, review it.
    • A client is configured with "command": "steero", "args": ["mcp", "--browser", "firefox"].
    • Snapshots give refs (e1, e2 ...); actions take a ref, auto-wait like a test, and report failures as isError results.
    • Any program can be the client: initialize, tools/list, tools/call, one JSON line each.
