    03. Actions and auto-waiting¶

    In this lesson

    You will learn to:

    • click, double click, hover, fill, clear, press keys and type key by key
    • check boxes and radios, select options, upload files and drag and drop
    • explain the actionability checks (attached, visible, stable, enabled, editable, receives the click) and read the error that names the failed one
    • set timeouts in seconds per call and per page (set_default_timeout)
    • wait for a condition (wait_for, wait_for_url, wait_for_function) instead of sleeping

    Time: about 45 minutes. Before this: 02. Locators. Code: examples/course/03-actions-and-auto-waiting/

    A locator says which element; an action says what to do with it. This lesson covers every common action and, more importantly, what steero does before each one: it waits until the element is ready. That waiting is why a steero script needs no sleep() calls, and knowing how it works lets you read a timeout error in seconds instead of guessing.

    The practice page for this lesson is /testsite/form.html. Open it in your own browser and reload it a few times: a dark overlay covers the page for 0.7 seconds, and a "Late button" appears after 0.6 seconds. Both are there on purpose, to give auto-waiting something to wait for.

    Your first actions¶

    Most scripts use a handful of actions, and each reads like what a user does:

    page.get_by_label("User name").fill("ada")                          # type into a field
page.get_by_label("Remember me").check()                            # tick a checkbox
page.get_by_label("Pro").check()                                    # choose a radio button
page.get_by_label("Country").select_option(label="United Kingdom")  # pick from a <select>
page.get_by_label("Notes").press("Enter")                           # press one key
page.get_by_role("button", name="Sign in").click()                  # click

    A few details are worth knowing from the start:

    • fill(value) replaces the whole value of an input, textarea or editable element, then fires input and change events, which frameworks such as React listen for. It does not press individual keys. clear() is fill("").
    • check() and uncheck() are better than click() for checkboxes: they do nothing when the box is already in the state you asked for, and they verify the state afterwards. set_checked(True) is the same with a flag.
    • select_option() takes a value (select_option("uk")), a label=, or an index=, or a list of them for a multi-select, and returns the values it selected.
    • click() sends real mouse events (move, press, release) at the centre of the element. It takes button="right", modifiers=["Shift"], click_count=2 and position={"x": 5, "y": 5} (relative to the element's top-left corner) when you need them.

    What auto-waiting checks¶

    Before every action, steero finds the element again and runs the actionability checks in the page. If a check fails, it waits a little and tries again, until the checks pass or the timeout runs out. Which checks run depends on the action:

    Check Means click fill hover check
    attached the element is in the DOM yes yes yes yes
    visible it has a size and is not hidden by CSS yes yes yes yes
    stable it is not moving (same box over two animation frames) yes yes yes
    enabled not disabled, not aria-disabled, not in a disabled fieldset yes yes yes
    editable not read-only yes
    receives the click nothing else covers its centre point yes yes yes

    The last check is the one other tools often miss. On form.html the overlay is a transparent layer over the whole page. A click on the Covered button during the first 0.7 seconds would land on the overlay, not on the button; a script that clicked blindly would "succeed" and the button would never know. steero sees that the point is covered and waits:

    page.get_by_role("button", name="Covered button").click()   # waits for the overlay to go

    If the timeout passes first, the error names the action, the locator, the time it waited, and the check that was still failing:

    click get_by_role('button', name='Covered button'): timed out after 0.2 s: element is covered by <div#overlay>

    The ending tells you where to look:

    Error ends with What to check
    no element matches the locator: wrong name, wrong frame, element not created yet
    element is not visible CSS (display: none, zero size), or the element appears later than the timeout
    element is not stable (still moving) an animation or transition that never settles
    element is disabled the app has not enabled it yet: a form not filled in, a request still running
    element is not editable a read-only field
    element is covered by <...> an overlay, a cookie banner, a toast, a sticky header

    force=True skips the checks (click(force=True)). Use it only when you are sure a check is wrong for your page; usually the check is right and the page is not ready.

    Coming from Selenium

    There is no WebDriverWait, no expected_conditions and no implicit wait to configure. Each action waits for exactly what it needs. There is also no StaleElementReferenceException: a locator finds the element again on every action, so a re-render between two steps does not break the script. And ElementClickInterceptedException becomes a wait plus, if the page never clears, a timeout that names the element in the way.

    Timeouts in seconds¶

    Every action waits up to 10 seconds by default. Timeouts in steero are always in seconds, so timeout=2 means two seconds:

    page.get_by_role("button", name="Save").click(timeout=2)   # this call only
page.set_default_timeout(5)                                # every action and wait on this page
page.set_default_navigation_timeout(60)                    # goto, reload, wait_for_url

    Navigations (goto, reload, wait_for_url) have their own default of 30 seconds, because loading a page usually takes longer than finding a button. Assertions have a third default, 5 seconds, which lesson 04 covers.

    When a wait runs out, steero raises SteeroTimeoutError (from steero import SteeroTimeoutError). It is also a Python TimeoutError, so code that already catches TimeoutError works.

    Pick timeouts for what the app really does. A longer timeout costs nothing when the page is fast, because steero stops waiting the moment the checks pass; it only matters when something is wrong. Shortening a timeout does not make a script faster.

    Coming from Playwright

    Same actions, same checks, but seconds, not milliseconds: click(timeout=2) is two seconds. A Playwright habit of timeout=5000 asks for 83 minutes. The default action timeout is 10 seconds (Playwright's is 30); page.set_default_timeout(30) restores Playwright's.

    Keyboard and mouse¶

    press(key) focuses the element and presses one key or a combination. Key names follow the browser's KeyboardEvent.key values: Enter, Tab, Escape, Backspace, ArrowDown, F2, or a single character. Combinations join keys with +, modifiers first:

    notes = page.get_by_label("Notes")
notes.press("Shift+A")             # a capital A
notes.press("ControlOrMeta+A")     # select all: Meta on macOS, Control elsewhere
notes.press_sequentially("hello")  # five separate key presses

    fill or press_sequentially? Use fill almost always: it is fast and it sets the value in one step. Use press_sequentially(text) when the page reacts to individual keys, such as an autocomplete box that searches as you type, or an input that formats a card number. It takes a delay= in seconds between keys.

    page.keyboard sends keys to whatever has focus, without a locator: page.keyboard.press("Tab") moves focus like a user would, and page.keyboard.type("text") types into the focused field.

    For the mouse, the locator actions are usually enough: hover(), click(), dblclick(), and click(button="right") for a context menu. page.mouse works in viewport pixels for the rare case where you need a point rather than an element (drawing on a canvas, for example): page.mouse.move(x, y), down(), up(), click(x, y) and wheel(0, 300). page.mouse does not auto-wait: it acts at that point, whatever is there now.

    Files and drag and drop¶

    set_input_files() sets the files of an <input type="file">, as if the user had picked them in the file dialog (which never opens):

    upload = page.locator("#file")
upload.set_input_files("report.pdf")                    # one file
upload.set_input_files(["report.pdf", "photo.png"])     # several, if the input allows it
upload.set_input_files({"name": "hello.txt", "mimeType": "text/plain", "buffer": b"hi"})  # in memory
upload.set_input_files([])                              # clear the selection

    Paths are relative to the current directory. The in-memory form is handy in tests: no file to create and clean up.

    drag_to(target) drags one element onto another with real pointer events (press, several moves, release), which works for pages that implement drag with mouse or pointer events and for HTML5 drag and drop:

    page.locator("#box").drag_to(page.locator("#target"))
page.drag_and_drop("#box", "#target")                   # the same, with two selectors

    Browser support

    Firefox starts a native HTML5 drag but does not deliver the final button release to it through WebDriver BiDi, so the page would never see the drop. For elements marked draggable="true" steero replays the HTML5 drag events itself in Firefox. Pages that drag with pointer events, such as /testsite/dnd.html, get real pointer input in both browsers. Your script is the same either way.

    Waiting for things that are not actions¶

    Actions wait for their own element. Sometimes you need to wait for something else: a spinner to go away, a URL to change, a value in the page to be ready. There is a wait for each:

    page.locator("#spinner").wait_for(state="hidden")       # or "visible", "attached", "detached"
page.wait_for_url("**/orders/*")                         # after a click that navigates
page.wait_for_function("() => window.appReady === true") # any JavaScript condition

    wait_for_url takes the same patterns as page.route in lesson 07: a glob string (** any text, * any text without a slash; a URL without wildcards must match exactly), a compiled regex such as re.compile(r"/orders/\d+$"), or a function that takes the URL.

    wait_for_function returns the truthy value the function produced, so it can also fetch the value you were waiting for. Each takes a timeout= in seconds.

    And then there is the wait you should not use. time.sleep(1) (or page.wait_for_timeout(1)) waits a fixed time whatever the page does:

    • when the page is faster than the sleep, the script wastes the rest of the second, on every run;
    • when the page is slower (a busy build machine, a cold cache), the script fails anyway, and you raise the sleep, and every run gets slower.

    A condition-based wait stops the moment the condition is true and fails only when it is really not going to happen. Exercise 4 measures the difference. Before you reach for a wait at all, ask whether the next action or an assertion would wait for you; most of the time it does.

    Worked example¶

    This script fills in every kind of control on /testsite/form.html and submits it. There is no sleep anywhere: the checkbox click waits for the overlay to go, the Late button click waits for the button to appear, and the assertion waits for the status line.

    """Lesson 03: fill in and submit a whole form, with no sleeps anywhere.

The page shows a "Late button" 0.6 seconds after loading and covers everything with an overlay
for 0.7 seconds. Every action below waits for its element to be ready on its own.

    python examples/course/03-actions-and-auto-waiting/example_fill_the_form.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import time

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")
        started = time.monotonic()

        page.get_by_label("User name").fill("ada")                 # text
        page.get_by_label("Password").fill("lovelace")             # password
        page.get_by_label("Remember me").check()                   # checkbox (waits for the overlay)
        page.get_by_label("Pro").check()                           # radio
        page.get_by_label("Country").select_option(label="United Kingdom")
        page.get_by_label("Notes").fill("Two lines\nof notes")     # textarea
        page.locator("#file").set_input_files(
            {"name": "notes.txt", "mimeType": "text/plain", "buffer": b"hello"})

        # Hidden at first, then shown: click() waits until it is visible.
        page.get_by_role("button", name="Late button").click()
        # Under the overlay at first: click() waits until nothing covers it.
        page.get_by_role("button", name="Covered button").click()

        page.get_by_role("button", name="Sign in").click()
        expect(page.get_by_role("status")).to_have_text("Signed in as ada")

        print("Status:  ", page.get_by_role("status").text_content())
        print("Country: ", page.get_by_label("Country").input_value())
        print("File:    ", page.locator("#files").text_content())
        print("Buttons: ", page.locator("#late").text_content(), "/", page.locator("#covered").text_content())
        print(f"Done in {time.monotonic() - started:.1f} s, without a single sleep")


if __name__ == "__main__":
    main()

    Run it from the repository root:

    python examples/course/03-actions-and-auto-waiting/example_fill_the_form.py

    Status:   Signed in as ada
Country:  uk
File:     notes.txt
Buttons:  Clicked late / Clicked through
Done in 1.4 s, without a single sleep

    The time is about the 0.7 seconds the overlay stays, plus the work itself. Run it with STEERO_COURSE_HEADED=1 to watch it: the form fills in while the overlay is still there, because fill does not need to receive a click, and the checkbox waits.

    Async version

    With the async API several pages can work at once. Here two users fill in the form concurrently with asyncio.gather, in one browser; while one waits for its overlay, the other one keeps working, and the printed lines interleave.

    """Lesson 03: with the async API, actions on several pages run at the same time.

One browser, two users: each fills in the form in a context of its own, concurrently, with
asyncio.gather. Each one waits for the late button and the overlay on its own page, and while one
waits, the other keeps working. The contexts keep the users apart (cookies, storage), as two
separate browser profiles would.

    python examples/course/03-actions-and-auto-waiting/example_fill_the_form_async.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (one browser with a context per user, now that background pages no longer stall)
"""

import asyncio
import os

import steero
from steero import expect

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


async def sign_in(browser: steero.Browser, user: str) -> str:
    """Fill in the form as ``user`` in a fresh context and return the status text."""
    context = await browser.new_context()  # a clean, separate session for this user
    try:
        page = await context.new_page()
        await page.goto(BASE_URL + "testsite/form.html")
        print(f"{user}: page loaded")
        await page.get_by_label("User name").fill(user)
        await page.get_by_label("Remember me").check()              # waits for the overlay
        await page.get_by_role("button", name="Late button").click()  # waits until it is shown
        await page.get_by_role("button", name="Sign in").click()
        await expect(page.get_by_role("status")).to_have_text(f"Signed in as {user}")
        print(f"{user}: signed in")
        return str(await page.get_by_role("status").text_content())
    finally:
        await context.close()


async def main() -> None:
    async with steero.launch(BROWSER, headless=HEADLESS) as browser:
        # gather starts both coroutines and waits for both; their steps interleave.
        results = await asyncio.gather(sign_in(browser, "ada"), sign_in(browser, "grace"))
        print(results)


if __name__ == "__main__":
    asyncio.run(main())

    Each user gets a browser context of its own (browser.new_context()): a separate session with its own cookies and storage, so one user's sign-in can never leak into the other's page. Two pages of one context would share them. Only one tab can be in front at a time, so steero brings a page to the front for the moment it clicks, types or takes a screenshot; the other page's waits keep running in the background.

    Two more scripts go with the sections above. example_keyboard_and_mouse.py types, uses key combinations, double-clicks and clicks with page.mouse:

    """Lesson 03: keys, key combinations, typing key by key, double click and hover.

The form page records every key it receives in a paragraph, so you can see the real key events.

    python examples/course/03-actions-and-auto-waiting/example_keyboard_and_mouse.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")
        notes = page.get_by_label("Notes")

        notes.press_sequentially("hello world")      # one real key event per character
        notes.press("ControlOrMeta+A")                # select all (Meta on macOS, Control elsewhere)
        notes.press("Backspace")                      # delete the selection
        expect(notes).to_have_value("")

        page.keyboard.type("typed by page.keyboard")  # keys go to whatever has focus
        expect(notes).to_have_value("typed by page.keyboard")
        print("Keys the page saw:", page.locator("#keys").text_content()[:44], "...")

        # This page has no double-click handler, so add one that writes into the status line.
        heading = page.get_by_role("heading", name="Sign in")
        heading.evaluate("(el) => el.addEventListener('dblclick', "
                         "() => { document.getElementById('status').textContent = 'double-clicked'; })")
        heading.dblclick()                            # two real clicks, close enough to count as one
        expect(page.get_by_role("status")).to_have_text("double-clicked")
        print("The heading received a dblclick event")

        # hover() waits until nothing covers the button (the overlay), then moves the pointer there.
        sign_in = page.get_by_role("button", name="Sign in")
        sign_in.hover()
        # page.mouse never waits: it acts at viewport pixels, whatever is there right now.
        box = sign_in.bounding_box()
        assert box is not None
        page.mouse.click(box["x"] + box["width"] / 2, box["y"] + box["height"] / 2)
        expect(page.get_by_role("status")).to_contain_text("Signed in")
        print("Clicked Sign in with page.mouse")


if __name__ == "__main__":
    main()

    example_waiting.py uses set_default_timeout, wait_for, wait_for_function and wait_for_url:

    """Lesson 03: wait for things that are not actions, and set timeouts in seconds.

    python examples/course/03-actions-and-auto-waiting/example_waiting.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import re
import time

from steero.sync_api import launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.set_default_timeout(5)               # every action and wait on this page: 5 seconds
        page.goto(BASE_URL + "testsite/form.html")
        started = time.monotonic()

        # Wait for an element to reach a state: visible, hidden, attached or detached.
        page.locator("#late").wait_for(state="visible")
        print(f"Late button visible after {time.monotonic() - started:.1f} s")
        page.locator("#overlay").wait_for(state="detached", timeout=2)
        print(f"Overlay removed after {time.monotonic() - started:.1f} s")

        # Wait for any condition you can write in JavaScript; the truthy value is returned.
        count = page.wait_for_function("() => document.querySelectorAll('#items li').length")
        print("List items:", count)

        # Wait for the URL after a click that navigates.
        page.goto(BASE_URL + "testsite/index.html")
        page.get_by_role("link", name="Second page").click()
        page.wait_for_url(re.compile(r"second\.html$"))
        print("Now at:", page.url.rsplit("/", 1)[-1])


if __name__ == "__main__":
    main()

    Late button visible after 0.8 s
Overlay removed after 0.8 s
List items: 3
Now at: second.html

    Exercises¶

    Exercise 1: read a failed check¶

    Click the Covered button on /testsite/form.html with timeout=0.2, so the click fails while the overlay is still there. Catch the SteeroTimeoutError and print it. Which check failed? Then make the Disabled button and the read-only Fixed field fail too, and compare the three messages. Finally, click the Covered button again with the default timeout and check that it worked.

    Solution 
    """Lesson 03, exercise 1: make a click time out on purpose and read which check failed.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero import SteeroTimeoutError
from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")
        covered = page.get_by_role("button", name="Covered button")

        # 0.2 seconds is shorter than the 0.7 seconds the overlay stays, so this must fail.
        try:
            covered.click(timeout=0.2)
        except SteeroTimeoutError as error:
            print("Failed as planned:", error)
            assert "covered by <div#overlay>" in str(error)

        # Two other checks failing, for comparison: enabled, then editable.
        try:
            page.get_by_role("button", name="Disabled").click(timeout=0.2)
        except SteeroTimeoutError as error:
            print("Failed as planned:", error)
        try:
            page.get_by_label("Fixed").fill("x", timeout=0.2)
        except SteeroTimeoutError as error:
            print("Failed as planned:", error)

        # With the default timeout the same click simply waits for the overlay to go.
        covered.click()
        # The click renames the button, so check it by id: the name "Covered button" is gone now.
        expect(page.locator("#covered")).to_have_text("Clicked through")
        print("Clicked once the overlay was gone")


if __name__ == "__main__":
    main()

    Failed as planned: click get_by_role('button', name='Covered button'): timed out after 0.2 s: element is covered by <div#overlay>
Failed as planned: click get_by_role('button', name='Disabled'): timed out after 0.2 s: element is disabled
Failed as planned: fill get_by_label('Fixed'): timed out after 0.2 s: element is not editable
Clicked once the overlay was gone

    Notice the last assertion uses #covered, not the covered locator: clicking renames the button to "Clicked through", so a locator that finds it by the name "Covered button" no longer matches anything.

    Exercise 2: upload two files¶

    Create two small files in the current folder, upload both to the file input on /testsite/form.html (#file) in one call, and check that the page lists both names (it shows them in #files, separated by a comma). Then replace them with a file made in memory.

    Solution 
    """Lesson 03, exercise 2: upload two files and check the names the page shows.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
from pathlib import Path

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    # Two small files in the current folder to upload.
    first, second = Path("report.txt"), Path("data.csv")
    first.write_text("quarterly report\n", encoding="utf-8")
    second.write_text("id,name\n1,ada\n", encoding="utf-8")

    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")
        upload = page.locator("#file")

        upload.set_input_files([first, second])           # paths on this machine
        expect(page.locator("#files")).to_have_text("report.txt,data.csv")
        print("Uploaded:", page.locator("#files").text_content())

        # A file can also be made in memory, without touching the disk.
        upload.set_input_files({"name": "hello.txt", "mimeType": "text/plain", "buffer": b"hi"})
        expect(page.locator("#files")).to_have_text("hello.txt")
        print("Replaced with:", page.locator("#files").text_content())


if __name__ == "__main__":
    main()

    Each call to set_input_files replaces the selection, as picking files in the dialog again would.

    """Lesson 03, exercise 3: drag the box onto its target and check the page noticed.

Author: Pandiyaraj Karuppasamy

"""

        expect(state).to_have_text("dropped")
        print("State after drag_to:", state.text_content())

        # page.drag_and_drop does the same with two selectors.
        page.reload()
        page.drag_and_drop("#box", "#target")
        expect(state).to_have_text("dropped")
        print("State after drag_and_drop:", state.text_content())


if __name__ == "__main__":
    main()

    The page reports "missed" when the box is released outside the target, so "dropped" proves the pointer really ended on it.

    Exercise 4: remove a sleep¶

    Here is a script someone wrote while the Late button was giving them trouble:

    page.goto(BASE_URL + "testsite/form.html")
time.sleep(1)  # wait for the late button
page.locator("#late").click()

    Replace the sleep with the right wait (or with none at all), and measure both versions with time.monotonic().

    Solution 
    """Lesson 03, exercise 4: replace a fixed sleep with the right wait, and measure the difference.

This is the one script in the course that sleeps on purpose, to show what it costs.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import time

from steero.sync_api import Page, expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def with_sleep(page: Page) -> float:
    """The given script: sleep long enough for the late button, then click it."""
    started = time.monotonic()
    page.goto(BASE_URL + "testsite/form.html")
    time.sleep(1)  # "should be enough": too long on a fast day, too short on a slow one
    page.locator("#late").click()
    expect(page.locator("#late")).to_have_text("Clicked late")
    return time.monotonic() - started


def with_auto_wait(page: Page) -> float:
    """The fix: no sleep at all; click() waits until the button is visible."""
    started = time.monotonic()
    page.goto(BASE_URL + "testsite/form.html")
    page.locator("#late").click()
    expect(page.locator("#late")).to_have_text("Clicked late")
    return time.monotonic() - started


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        slow = with_sleep(page)
        fast = with_auto_wait(page)
        print(f"With time.sleep(1): {slow:.2f} s")
        print(f"With auto-waiting:  {fast:.2f} s")
        assert fast < slow, "auto-waiting should not be slower than a fixed sleep"


if __name__ == "__main__":
    main()

    With time.sleep(1): 1.54 s
With auto-waiting:  0.98 s

    Your numbers will differ, but the gap will not: the sleep always costs its full second, while click() waits only the 0.6 seconds the button takes to appear. No separate wait is needed, because the click already waits for the button to be visible. This is the one script in the course that sleeps, and it does so only to be measured.

    Common mistakes¶

    Common mistakes

    • Sleeping before an action. The script gets slower and still fails on a slow day. Delete the sleep: the action waits on its own. If it must wait for something else, use wait_for, wait_for_url or an assertion.
    • timeout=5000. Timeouts are seconds; that is 83 minutes. Write timeout=5.
    • Reaching for force=True when a click times out. The check was usually right: something covers the element, or it is disabled. Read the end of the error message and fix the cause, such as closing the cookie banner first.
    • Using click() on a checkbox. It toggles, so it unticks a box that was already ticked. Use check() and uncheck(), which go to the state you name.
    • Typing with press_sequentially everywhere. It is slower and fires a key event per character. Use fill unless the page reacts to each key.
    • Finding a button by a name the click changes. After get_by_role("button", name="Follow").click() the button may say "Following", and the same locator then finds nothing. Check the result with a locator that does not depend on the old text.
    • Expecting page.mouse to wait. It acts at a point right now. Use locator actions, or wait for the element first.
    • Running concurrent users in one context. Pages of one context share cookies and storage, so the second sign-in replaces the first. Give each concurrent user its own context.

    Recap¶

    • Actions (click, fill, check, select_option, press, set_input_files, drag_to) wait for their element to be attached, visible, stable, enabled, editable and not covered, as each one needs.
    • A timeout error names the action, the locator, the seconds it waited and the check that failed.
    • Timeouts are seconds: per call with timeout=, per page with set_default_timeout; actions default to 10 seconds and navigations to 30.
    • Wait for conditions (wait_for, wait_for_url, wait_for_function, assertions), never for a fixed time.
