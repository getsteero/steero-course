    02. Locators¶

    In this lesson

    You will learn to:

    • find elements the way a user sees them: get_by_role, get_by_label, get_by_text, get_by_placeholder, get_by_alt_text, get_by_title
    • use get_by_test_id, CSS and XPath when nothing user-facing is stable
    • narrow and chain: first, nth, filter(has_text=, has=, has_not=), or_, and_, and locators inside locators
    • reach into iframes with frame_locator, and rely on open shadow roots being searched for you
    • explain strictness and read a StrictModeViolation
    • read state from an element (text_content, input_value, count, all) and know when to assert instead

    Time: about 45 minutes. Before this: 01. Getting started. Code: examples/course/02-locators/

    Every action and every assertion starts with a locator, so the way you find elements decides how readable your scripts are and how often they break. This lesson shows how to describe an element so that the description survives a redesign.

    Keep the practice site running (python examples/course/serve.py) for the whole lesson. Most examples use /testsite/form.html, a form with one of everything; open it in your own browser next to the code.

    Locators are lazy and strict¶

    A locator is a description of how to find elements, not an element you have already found. Building one does not touch the page:

    button = page.get_by_role("button", name="Sign in")   # nothing happens yet
button.click()                                          # now steero looks, waits, then clicks
button.click()                                          # and looks again, from scratch

    Because the search runs again on every use, a locator never goes stale: if the page re-renders the button between two clicks, the second click finds the new one. You can build locators at the top of a script, keep them in variables or page objects, and use them whenever you like.

    A locator is also strict. An action needs exactly one element, and when the description matches several, steero raises StrictModeViolation instead of guessing which one you meant. That sounds fussy, but a guess is how a test clicks "Delete" on the wrong row and still passes. You will trigger one on purpose later in the lesson.

    Reads that work on many elements at once (count(), all(), all_inner_texts()) are not strict, and neither are assertions about lists such as to_have_count.

    Prefer what users see¶

    The get_by_* family finds elements by what a person sees or what assistive technology announces:

    Locator Finds Example on form.html
    get_by_role(role, name=...) elements by ARIA role and accessible name get_by_role("button", name="Sign in")
    get_by_label(text) form controls by their label, aria-label or aria-labelledby get_by_label("User name")
    get_by_placeholder(text) inputs by placeholder get_by_placeholder("you@example.com")
    get_by_text(text) the smallest element containing the text get_by_text("Banana")
    get_by_alt_text(text) images by alt get_by_alt_text("Company logo")
    get_by_title(text) elements by title get_by_title("Logo")

    get_by_role is the one to reach for first. A role is what kind of thing the element is (button, link, textbox, checkbox, radio, combobox, heading, row, cell and so on), and the accessible name is what a screen reader would call it: a button's text, an input's label, an image's alt text. Together they describe an element the way a user would, and they keep working when the markup or the CSS classes change. get_by_role takes a few extra filters, such as level=1 for an <h1>, checked=True for a ticked checkbox and disabled=True for a disabled control:

    page.get_by_role("heading", level=1)
page.get_by_role("radio", checked=True)
page.get_by_role("button", disabled=True)

    How text is matched. A text argument (name=, or the text of get_by_label, get_by_text and the others) matches a case-insensitive substring by default, with whitespace squashed. So get_by_role("button", name="sign") finds "Sign in". Pass exact=True for a whole, case-sensitive match, or a compiled regular expression for anything else:

    page.get_by_text("Banana", exact=True)
page.get_by_text(re.compile(r"^ban", re.IGNORECASE))

    Why not just CSS? #user or .btn-primary describe how the page is built, and they change whenever someone restructures the HTML or renames a class. "The text box labelled User name" changes only when the page changes for its users too, and then you want the test to notice. Role-based locators also double as a small accessibility check: a button that get_by_role cannot find by name is a button a screen reader cannot announce.

    Coming from Selenium

    The find_element(By...) calls map like this:

    Selenium steero
    find_element(By.ID, "user") page.locator("#user"), or better page.get_by_label("User name")
    find_element(By.CSS_SELECTOR, "li.item") page.locator("li.item")
    find_element(By.XPATH, "//li[2]") page.locator("xpath=//li[2]")
    find_element(By.LINK_TEXT, "Docs") page.get_by_role("link", name="Docs")
    find_elements(By.TAG_NAME, "li") page.locator("li").all()
    element.find_element(...) locator.locator(...) or locator.get_by_role(...)

    The big difference is timing: find_element looks once, now, and hands back an element that can go stale. A locator looks every time it is used and waits for the element to be ready.

    Test ids, CSS and XPath¶

    Sometimes nothing user-facing is stable: an icon button with no label, a cell in a grid of identical cells, text that is translated. Then use a test id, an attribute added to the markup only for tests:

    page.get_by_test_id("user-input")            # <input data-testid="user-input">
page.get_by_test_id("cart", attribute="data-qa")   # a different attribute name

    A test id is a promise between the developers and the tests, so it does not change by accident. It says nothing about what the user sees, though, so prefer a role or a label when one exists.

    page.locator(selector) takes CSS, or XPath with an xpath= prefix (a selector starting with // is read as XPath too):

    page.locator("#items li")
page.locator("xpath=//ul[@id='items']/li[last()]")

    CSS selectors in steero also understand three text pseudo-classes that browsers do not: :has-text("x") (contains x, ignoring case), :text("x") (the smallest element containing x) and :text-is("x") (exactly x). They are handy inside a longer selector:

    page.locator("label:has-text('Pro') > input")

    The locators guide lists every option.

    Narrowing and chaining¶

    A locator that matches a list can be narrowed:

    Narrowing Keeps
    .first, .last, .nth(i) one match by position (nth(-1) is the last)
    .filter(has_text="x") matches whose text contains x (has_not_text= drops them)
    .filter(has=locator) matches that contain an element matching locator (has_not= drops them)
    .filter(visible=True) visible matches only
    a.or_(b) elements matching a or b (or both), in document order
    a.and_(b) elements matching both a and b

    And any locator can search inside another, which is called scoping:

    table = page.get_by_role("table", name="Products")
rows = table.get_by_role("row")                    # rows in this table only
teapot = rows.filter(has_text="Green teapot")      # the row that mentions the teapot
teapot.get_by_role("button").click()               # the button in that row

    Read that as a sentence: "in the Products table, the row with Green teapot, its button". Scoping and filtering are how you deal with repeated structure (table rows, cards, list items) without counting positions. nth(2) breaks as soon as the order changes; "the row with Green teapot" does not.

    has= takes a locator built from the page, and steero searches for it inside each candidate:

    sold_out = rows.filter(has=page.get_by_role("button", disabled=True))

    Coming from Playwright

    The locator API is Playwright's, name for name: get_by_role, filter(has=...), or_, and_, nth, first, frame_locator, and the :has-text() pseudo-class all behave the same, and text is matched by the same rules (substring and case-insensitive unless exact=True). One difference to know about: steero computes accessible names with an approximation of the accname algorithm, so in edge cases (nested labels, aria-owns, CSS generated content) a name can differ from the one Playwright computes. If a get_by_role name that works in Playwright finds nothing here, print locator.aria_snapshot() of the surrounding element to see the names steero computed.

    Frames and shadow DOM¶

    Open shadow roots need nothing special. Web components often hide their markup inside a shadow root, where document.querySelector cannot see it. steero's CSS, text, label and role queries search open shadow roots for you, however deeply they nest. On /testsite/shadow.html the Follow button is two shadow roots deep, and this simply works:

    page.get_by_role("button", name="Follow").click()

    (Closed shadow roots are closed to every tool by design; nothing can reach into them.)

    Iframes must be entered. An iframe holds a separate document, so a locator built from the page does not look inside it. frame_locator(selector) names the iframe, and locators built from it search the document inside:

    child = page.frame_locator("#child")
child.get_by_role("button", name="Inner button").click()

    For an iframe inside an iframe, chain one frame_locator per level. Exercise 4 does exactly that.

    Strictness in practice¶

    /testsite/form.html has several text boxes: User name, Password, Notes and the read-only Fixed field (get_by_role("textbox").count() says 4). The file input at the bottom is not one of them: it takes no typed text, and browsers expose it as a button, so steero gives it the button role, as Playwright does. Ask for "the text box" and steero refuses:

    StrictModeViolation: get_by_role('textbox') matched 4 elements; use .first, .nth() or a more specific locator

    The message names the locator and the number of matches. The fix is almost never .first: that makes the script pick whichever text box happens to come first today, which is the guess strict mode exists to prevent. Say which one you mean instead, with a name (get_by_role("textbox", name="Notes")), a filter, or a scope. Use .first only when any of the matches would do, such as "click any product".

    A StrictModeViolation is raised at once, without waiting for the timeout, because waiting would not change the answer.

    Reading state¶

    Sometimes you need a value from the page, to print it or to use it later in the script. These calls read it:

    Call Returns
    count() how many elements match right now
    all() a list of locators, one per current match
    text_content() the element's text, as in the DOM (textContent)
    inner_text() the text as rendered (hidden text left out, CSS applied)
    all_inner_texts() the rendered text of every match, as a list
    input_value() the current value of an input, textarea or select
    get_attribute(name) an attribute, or None
    is_visible(), is_enabled(), is_checked() a yes or no 
    for item in page.locator("#items li").all():
    print(item.text_content())

    There is a catch. count(), all(), all_inner_texts() and is_visible() answer right now, without waiting. On a page that is still loading (the products table arrives a moment after the page does) they can see an empty list. The single-element reads (text_content(), input_value() and so on) wait for the element to exist, but not for its text to change.

    So for anything you check, use an assertion instead of a read plus assert:

    assert page.locator("#items li").count() == 3          # reads once; fails if the list is late
expect(page.locator("#items li")).to_have_count(3)    # waits until it is true, up to 5 seconds

    Reads are for values you need; assertions are for facts you check. Lesson 04 covers assertions in depth.

    Worked example¶

    This script opens /testsite/form.html and finds its controls in every user-facing way, then by test id, CSS and XPath, printing what each locator found:

    """Lesson 02: find every control on a form the way a user would describe it.

Opens the integration-test form, finds its controls by role, label, placeholder, alt text, title
and test id, and prints what each locator found.

    python examples/course/02-locators/example_user_facing.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os
import re

from steero.sync_api import launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")

        heading = page.get_by_role("heading", level=1)
        print("Heading:", heading.text_content())

        # Labels, placeholders and test ids all lead to the same User name field.
        page.get_by_label("User name").fill("ada")
        print("By placeholder:", page.get_by_placeholder("you@example.com").input_value())
        print("By test id:    ", page.get_by_test_id("user-input").input_value())

        # A role plus its accessible name is the most precise user-facing locator.
        page.get_by_role("checkbox", name="Remember me").check()
        page.get_by_role("radio", name="Pro").check()
        print("Checked radio: ", page.get_by_role("radio", checked=True).get_attribute("value"))
        print("Country:       ", page.get_by_role("combobox", name="Country").input_value())

        # Images by alt text or title; text by a regular expression.
        print("Logo found:    ", page.get_by_alt_text("Company logo").count(), "by alt,",
              page.get_by_title("Logo").count(), "by title")
        print("Fruit by regex:", page.get_by_text(re.compile(r"^ban", re.IGNORECASE)).text_content())

        # CSS and XPath still work when nothing user-facing is stable.
        print("By CSS:        ", page.locator("#items li").count(), "list items")
        print("By XPath:      ", page.locator("xpath=//ul[@id='items']/li[last()]").text_content())


if __name__ == "__main__":
    main()

    Run it from the repository root:

    python examples/course/02-locators/example_user_facing.py

    Heading: Sign in
By placeholder: ada
By test id:     ada
Checked radio:  pro
Country:        in
Logo found:     1 by alt, 1 by title
Fruit by regex: Banana
By CSS:         3 list items
By XPath:       Cherry

    The second and third lines prove that three different locators reach the same field: the value filled in through the label is read back through the placeholder and the test id.

    Two more scripts cover the rest of the lesson. example_narrowing.py works on the products page (/products.html) with nth, filter(has_text=), filter(has=), scoping and or_:

    """Lesson 02: narrow a list of matches with nth, filter, has, or_ and scoping.

Works on the products page, whose table is filled from /api/products after the page loads.

    python examples/course/02-locators/example_narrowing.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "products.html")
        # The rows arrive a moment after the page loads; wait for them before counting.
        expect(page.get_by_role("status")).to_have_text("3 products")

        table = page.get_by_role("table", name="Products")
        rows = table.get_by_role("row")                      # scoped: rows inside this table only
        print("Rows, header included:", rows.count())
        print("First data row:", rows.nth(1).inner_text().split("\t")[0])
        print("Last row:      ", rows.last.inner_text().split("\t")[0])

        # filter(has_text=...) keeps rows whose text contains the words.
        teapot = rows.filter(has_text="Green teapot")
        print("Teapot row:    ", teapot.inner_text().replace("\t", " | "))

        # filter(has=...) keeps rows that contain a matching element; has_not drops them.
        sold_out = rows.filter(has=page.get_by_role("button", disabled=True))
        print("Sold out:      ", sold_out.get_by_role("cell").first.text_content())
        buyable = rows.filter(has=page.get_by_role("button", disabled=False))
        print("Can be bought: ", buyable.count(), "rows")

        # A locator inside a locator: the button in the teapot row, found by its role.
        teapot.get_by_role("button").click()
        expect(page.get_by_test_id("cart-count")).to_have_text("1")

        # or_ matches either one, which helps when a page shows one of two states.
        state = page.get_by_text("No products yet").or_(page.get_by_text("3 products"))
        print("Page state:    ", state.text_content())


if __name__ == "__main__":
    main()

    example_shadow_and_frames.py fills an input inside two shadow roots and clicks a button inside an iframe:

    """Lesson 02: reach elements inside open shadow roots and inside iframes.

Shadow roots need nothing special; iframes are entered with frame_locator.

    python examples/course/02-locators/example_shadow_and_frames.py

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()

        # The input and the button live two shadow roots deep; the locators do not care.
        page.goto(BASE_URL + "testsite/shadow.html")
        page.get_by_placeholder("Say hi").fill("hello")
        print("Shadow input:", page.get_by_placeholder("Say hi").input_value())
        page.get_by_role("button", name="Follow").click()
        expect(page.locator("#result")).to_have_text("followed")
        print("Card name:   ", page.locator(".name").text_content())

        # An iframe is a separate document: enter it first, then locate inside it.
        page.goto(BASE_URL + "testsite/frames.html")
        child = page.frame_locator("#child")
        child.get_by_role("button", name="Inner button").click()
        expect(child.locator("#inner-btn")).to_have_text("Inner clicked")
        print("Frame button:", child.locator("#inner-btn").text_content())


if __name__ == "__main__":
    main()

    Exercises¶

    Each exercise has a solution script; run it the same way as the examples.

    Exercise 1: three ways to one button¶

    On /testsite/form.html, find the Sign in button three different ways: by role, by text, and by CSS. Check that all three locate the same element by comparing their bounding_box() (the position and size of the element on the page).

    Hint: page.get_by_text("Sign in") matches two elements, because the heading says "Sign in" too. How can you search only inside the form?

    Solution 
    """Lesson 02, exercise 1: find the Sign in button three ways and prove they find the same element.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")

        by_role = page.get_by_role("button", name="Sign in")
        # The heading also says "Sign in", so text alone matches two elements; scope it to the form.
        by_text = page.locator("#login").get_by_text("Sign in")
        by_css = page.locator("button[type=submit]")

        boxes = [locator.bounding_box() for locator in (by_role, by_text, by_css)]
        for name, box in zip(("role", "text", "CSS"), boxes, strict=True):
            print(f"By {name:<4}: {box}")
        assert boxes[0] == boxes[1] == boxes[2], "the three locators found different elements"
        print("All three locators found the same button")


if __name__ == "__main__":
    main()

    Scoping the text search to #login leaves out the heading, which is outside the form. Equal boxes mean equal elements here, because two elements cannot occupy exactly the same box on this page.

    Exercise 2: the row that has it¶

    On /products.html, add the Green teapot to the cart by clicking the button in its row, and check that the cart count shows 1. Then print the names of the products that are still in stock (their button is enabled).

    Hint: start from page.get_by_role("row"), and use filter(has_text=...) for the first part and filter(has=...) for the second.

    Solution 
    """Lesson 02, exercise 2: add the Green teapot to the cart, then list the products still in stock.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "products.html")
        rows = page.get_by_role("row")

        # Actions wait for the row to appear, so no wait is needed before this click.
        rows.filter(has_text="Green teapot").get_by_role("button", name="Add").click()
        expect(page.get_by_test_id("cart-count")).to_have_text("1")

        # Rows with an enabled button are in stock; the header row has no button at all.
        in_stock = rows.filter(has=page.get_by_role("button", disabled=False))
        expect(in_stock).to_have_count(2)
        # all_inner_texts() reads every match at once; a row's cells are separated by tabs.
        print("In stock:", [text.split("\t")[0] for text in in_stock.all_inner_texts()])


if __name__ == "__main__":
    main()

    In stock: ['Blue mug', 'Green teapot']

    The header row has no button, so has= leaves it out without any extra work. The to_have_count(2) assertion comes before all_inner_texts() because the read does not wait; after the assertion the rows are certainly there.

    Exercise 3: a strict mode violation¶

    On /testsite/form.html, call page.get_by_role("textbox").fill("hello"), catch the StrictModeViolation (import it with from steero import StrictModeViolation) and print it. Then fix the locator two ways: once with a better name, once by scoping to a part of the page.

    Solution 
    """Lesson 02, exercise 3: trigger a StrictModeViolation, read it, then fix the locator two ways.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
Modified: Nov-07-2026 (four text boxes: the file input is a button now)
"""

import os

from steero import StrictModeViolation
from steero.sync_api import launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/form.html")

        try:
            page.get_by_role("textbox").fill("hello")  # four text boxes on this form
        except StrictModeViolation as error:
            print("Refused:", error)

        # Fix 1: give the role an accessible name, so only one text box qualifies.
        notes = page.get_by_role("textbox", name="Notes")
        notes.fill("hello")
        print("Fix 1, a better name:", notes.input_value())

        # Fix 2: scope the search to the part of the page you mean (the label wraps its input).
        password = page.locator("label", has_text="Password").get_by_role("textbox")
        password.fill("secret")
        print("Fix 2, scoping:      ", password.input_value())


if __name__ == "__main__":
    main()

    Refused: get_by_role('textbox') matched 4 elements; use .first, .nth() or a more specific locator
Fix 1, a better name: hello
Fix 2, scoping:       secret

    The second fix works because the Password label wraps its input, so the text box is inside the label. Catching the error is only for this exercise: in a real script, let it fail.

    Exercise 4: two frames down¶

    /testsite/frames.html holds an iframe (#child), which holds another iframe (#grandchild) with a button in it. Print the button's text, click it, and check that its text changed to "Deep clicked".

    Solution 
    """Lesson 02, exercise 4: read and click the button inside an iframe inside an iframe.

Author: Pandiyaraj Karuppasamy
Date: Nov-07-2026
"""

import os

from steero.sync_api import expect, launch

BASE_URL = os.environ.get("STEERO_COURSE_URL", "http://127.0.0.1:8765/")
BROWSER = os.environ.get("STEERO_COURSE_BROWSER", "chrome")
HEADLESS = os.environ.get("STEERO_COURSE_HEADED") != "1"


def main() -> None:
    with launch(BROWSER, headless=HEADLESS) as browser:
        page = browser.new_page()
        page.goto(BASE_URL + "testsite/frames.html")

        # One frame_locator per iframe on the way down: page > #child > #grandchild.
        deep = page.frame_locator("#child").frame_locator("#grandchild").get_by_role("button")
        print("Before:", deep.text_content())
        deep.click()
        expect(deep).to_have_text("Deep clicked")
        print("After: ", deep.text_content())


if __name__ == "__main__":
    main()

    get_by_role("button") is not ambiguous here, because inside the grandchild frame there is only one button. The locator is scoped by the two frames it entered.

    Common mistakes¶

    Common mistakes

    • Adding .first to silence a StrictModeViolation. The script now clicks whichever match comes first, and breaks silently when the order changes. Name the element you mean with a role and name, a filter or a scope.
    • Expecting get_by_text to be exact. It matches a case-insensitive substring, so get_by_text("Sign in") also finds "Sign in to continue". Pass exact=True, or use get_by_role with a name.
    • Using count() or all() before the content has loaded. They answer right now and happily return 0 or []. Wait first with an assertion (to_have_count, or to_have_text on a status line), or assert on the list directly.
    • Looking for an element inside an iframe from the page. The locator times out with "no element matches", although you can see the element. Enter the frame with page.frame_locator("#frame") first.
    • Copying a long CSS path from DevTools (div:nth-child(3) > div > span). It breaks on the next layout change. Find a role, a label or a test id instead.
    • Building a locator from an element's current text when the text changes. A button found by name="Save" is gone once it says "Saved". Use a name that stays the same, a test id, or or_ to accept both.

    Recap¶

    • A locator is a lazy description: it is resolved again on every action, so it never goes stale.
    • Locators are strict: an action on several matches raises StrictModeViolation at once; fix the description rather than adding .first.
    • Prefer get_by_role with a name, then labels and text; use test ids, CSS and XPath when nothing user-facing is stable.
    • Narrow with filter, nth, or_ and and_, and scope one locator inside another.
    • Open shadow roots are searched for you; iframes are entered with frame_locator.
    • Reads such as count() answer right now; use expect for anything you check.
